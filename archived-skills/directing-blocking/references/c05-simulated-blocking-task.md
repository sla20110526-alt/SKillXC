# C05 模拟场戏调度任务

本文件只验证轻量生产回显、调度字段和边界，不建立具体项目数据，也不宣称通过真实导演创作验证。

## 模拟输入

- `DSB-DEMO-SCN012@v001；BDT-DEMO-SCN012@v001`：林舟拒绝主任“坐”的命令，把未拆信封放到桌面，控制权开始争夺。
- `ACT-LINZHOU@v001；ACT-DIRECTOR@v001`：林舟以静止拒绝服从；主任习惯控制办公桌与入口之间的距离。
- `SPB-DEMO-OFFICE@v001`：门、访客椅、办公桌和窗形成可读锚点；访客椅外侧到桌南侧的路径已锁定可通行。现有正式场景图只有正面视角，不能同时支持门、访客椅与桌南侧路径的逐镜观察。
- 生命体、VFX 与顾问约束均不适用。

## 合格轻量回显

当前结果：我已把这一拍落成两条调度单元。主任说“坐”并指向访客椅后，林舟不坐，沿椅外侧到桌南侧，把信封放到桌面中央；这次移动的目的不是让画面更活，而是拒绝服从并把筹码送进双方争夺区。主任的“保持位置”继续维持他对办公桌和入口的控制。两人的关系轴稳定，门仍是林舟可撤离、主任想控制的空间压力点。

必要缺口：空间事实足以完成调度，但现有正式场景图不能支持门、访客椅和桌南侧路径同时可读。我会把它标为“仅专项视图生产缺口”：不阻断下一步场戏表演适配，解决并复核前不进入逐镜设计。

现在请你决定：本拍让观众先跟随林舟、与他同时看见信封，还是先跟随主任、把信封作为一次延迟揭示？

下一步：按你的决定完成 `DBD-DEMO-SCN012@v001` 与 `DBC-DEMO-SCN012@v001`；不会在本阶段预设机位、焦段或运镜。

## 不合格表现

- 展开整张后台任务单、Schema 或任务成果索引让用户逐项确认。
- 默认写“低机位35mm手持推进”，把观众关系直接变成逐镜实现。
- 为了避免固定画面让两个人无触发地走动。
- 因为只有办公室正面参考图，就把所有人物改成正面站定。
- 同时询问是否加载导演 Profile、是否补场景视图、是否改变观众视点，制造多个决定点。
