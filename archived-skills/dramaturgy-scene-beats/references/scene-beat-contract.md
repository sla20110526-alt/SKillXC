## 1. 对象与单向依赖

一次场戏节拍任务产生两个独立成果：

- `BDT-<项目代号>-<场次代号>@v###`：逐节拍权威数据，成果类别为“任务数据集”。
- `DSB-<项目代号>-<场次代号>@v###`：场戏节拍人读卡，成果类别为“创作短卡”。

每行节拍使用稳定 `BT-001`、`BT-002`。重写某一拍时保持原节拍 ID；插入新拍时优先使用下一个未用 ID，不因显示顺序变化重编号既有 ID。`节拍序号` 表示当前播放顺序，允许在新版本中改变，但未获剧本改写授权时不能用它重排锁定事件。

依赖固定为：

```text
剧本事实／表演母档／顾问结论
              ↓
       BDT逐节拍数据
              ↓
       DSB场戏节拍卡
          ↙        ↘
   导演调度切片   表演适配切片
```

BDT 不引用 DSB；DSB 必须精确引用 BDT。不得形成相互依赖，也不得把两者合并成一个含糊的“剧作版本”。

## 2. 节拍判定

### 2.1 什么构成新节拍

至少满足一项：

- 外部事件或对方行动触发人物改变策略；
- 人物获得、失去、误解或确认关键信息；
- 控制权、威胁能力、谈判筹码或关系地位发生变化；
- 人物目标对象或即时目标发生变化；
- 角色进入、退出、被迫停下或选择继续；
- 沉默、拒绝回应或动作中断造成不可逆的关系或信息结果。

单纯换一句台词、重复同一策略、无后果的表情或为方便分镜而切段，不构成新节拍。

### 2.2 节拍长度

不机械限定 2—6 拍。短场可能只有 1—2 拍，复杂场可能更多。数量必须由变化决定，而不是让每拍平均长度相同。一个节拍可以包含多句台词和多个动作，只要人物策略和戏剧状态没有实质改变。

### 2.3 反应节拍

反应只有在以下情况才独立成拍：

- 角色因新信息改变后续选择；
- 沉默使另一方失去控制或暴露意图；
- 拒绝、延迟或错误理解改变权力关系；
- 反应完成不可省略的进入／离开状态转换。

否则把反应写进相邻节拍的“可见行为”或“离开状态”。

## 3. 逐字段填写规则

### 3.1 出处字段

- `剧本内容版本`：逐字继承剧本事实索引中的唯一锁定版本，如 `script-v1` 或项目既有的 `SCRIPT-DEMO@v001`；不得在本 Skill 自造第二套剧本版本名。
- `原文定位`：使用页码、段落、行范围、时间码或可复现的组合，不写“本场中间”。
- `剧本事实ID集合`：列入本拍直接使用的事实 ID；多个以中文分号分隔。
- `原文锁定项`：保存本拍涉及的锁定台词／动作引用。台词可写逐字原文并同时标出处；过长时写事实 ID 与首尾短锚点，但必须能回到权威剧本。

### 3.2 戏剧行动字段

- `触发`：上一结果或新事件，不写抽象的“情绪变化”。
- `行动人物ID`：本拍主动改变局面的人；多人并行时按不同策略拆行或明确主行动者。
- `人物目标`：写“让／阻止／得到／确认某对象的某结果”，不写“愤怒”“悲伤”。
- `障碍`：说明此刻实际阻力，包括对方目标、信息不足、规则、时间、身体条件或自我矛盾。
- `策略`：使用行动动词，如试探、拖延、诱导、压迫、转移、否认、示弱、撤回。
- `可见行为`：只写剧本已有动作或不改变事实的最低限度可观察行动概括；具体表演微动作留给表演 Skill。
- `潜台词`：写人物希望对方理解／误解什么，并说明台词或行为矛盾依据。
- `字段依据与标签`：至少逐项写 `触发=依据/标签；目标=依据/标签；策略=依据/标签；可见行为=依据/标签；潜台词=依据/标签；信息变化=依据/标签；权力变化=依据/标签`。同一拍可以同时包含显式事实与推断，不能用一个总标签覆盖整行。

### 3.3 变化字段

信息和权力都必须写“进入—变化—离开”，不能只写一个结论。

- 信息变化回答“谁现在知道、误以为或确认了什么”。
- 权力变化回答“谁更能决定下一步，凭什么筹码或限制”。
- 节拍进入／离开状态包含人物选择、关系张力和未完成动作，但不塞入机位或表演微动作。
- 若某一维度没有变化，明确写“不变：……”并确保另一维度或总体状态确有变化；所有维度都不变时不应独立成拍。

### 3.4 顺序与因果字段

- `事件顺序锚点`：用“E03之后、E04之前”或事实 ID 序列描述位置。
- `因果依据`：写“由于 X，人物改用 Y，导致 Z”；没有剧本依据时标 `UNKNOWN`，不能补成确定因果。
- 相邻拍必须可连接：上一拍离开状态应成为下一拍进入条件或明确存在场内跳转。

## 4. 原文保护

锁定保护不是“意思差不多”。以下都属于改写：

- 同义替换、语序调整、删减口头词或润色台词；
- 把行动从一人转给另一人；
- 把反应提前到角色获得信息之前；
- 为了更戏剧化而改变出入场、事件顺序或因果；
- 新增解释性台词、回忆、道具功能或隐藏动机并当成事实。

发现节拍无法成立时，先指出剧本缺口或多义性。用户若要求修改，返回 `script-truth-index` 建立新剧本内容版本；旧 BDT／DSB 保持只读，由兼容复核决定待复核、继续使用或建立下一版本。

每拍 `锁定项保护结论` 只允许“保持原文”或“不适用”。卡片全局保护门任何一项不通过，成果不得激活为可交接。

## 5. 事实、推断与创作建议

- `SCRIPT_EXPLICIT`：原文直接写明。
- `SCRIPT_INFERRED`：上下文高置信推断，必须写依据；不能覆盖显式事实。
- `USER_LOCKED`：用户在项目中明确补充并锁定。
- `CREATIVE_PROPOSAL`：不改变锁定事实的分析提案，必须等待采用后才能进入正式切片。
- `UNKNOWN`：多义、缺失或范围外信息。

潜台词通常是推断，不应伪装为显式事实。每个分析字段在 `字段依据与标签` 中单独标记；人物母档只能限制解释不违背稳定行动引擎和弧线阶段，不能替代当前场次的剧本出处。

## 6. Profile 使用边界

先展示候选、代表作品、成熟度和证据边界，再等待用户明确选择。用户未选时不读取 Profile。读取后只提取当前场戏需要的方法，例如“按筹码变化检查转折”或“检查听者反应是否改变信息流”。

以下用法不允许：

- 仿写某位作者的台词；
- 用代表作桥段补当前剧本；
- 把主体姓名、片名或风格标签传给导演、表演或 Prompt；
- 因为 Profile 建议更强而覆盖锁定事件顺序。

DSB 交付即关闭 Profile。项目采用方法写在卡片的采用字段，下游只接收已经转译的戏剧决定。

## 7. 版本与状态

### 7.1 必须升级

- BDT 任一戏剧字段、出处、适用范围或精确上游引用变化；
- DSB 的总体戏剧结构、原文保护结论、Profile采用方法、下游切片或 BDT 引用变化；
- 节拍表增行、删行、合并、拆分、顺序或稳定 ID 变化；
- 文件正文只改错字或排版，仍按任务成果索引内容指纹规则升级。

### 7.2 不升级

- 任务索引状态变化；
- 成果索引从草案到可交接、标记待复核或复核后继续使用；
- 复核日期、状态依据等管理字段变化；
- 上游新版本经责任 Skill 逐项确认内容与精确引用都无需改变。若必须更新精确引用，则仍属于内容变化并升级。

### 7.3 原子顺序

1. 新 BDT 以草案加入任务成果索引。
2. 结构与业务复核通过后激活 BDT。
3. 建立精确引用该 BDT 的新 DSB 草案。
4. DSB 通过原文保护、Profile关闭和交接检查后激活。
5. 同一稳定 ID 的旧当前版在各自事务中改为已替代。

## 8. 下游交接

导演切片只回答：场戏为了什么、何时发生转折、信息和权力怎样变化、什么事件与顺序不能动。导演据此设计观众视点、人物坐标、距离、朝向、遮挡和移动触发。

表演切片只回答：人物要从谁那里得到什么、受什么阻挡、当前采用什么策略、台词之下在做什么、人物此刻知道什么。表演 Skill 据此结合已定调度设计倾听、眼神、呼吸、重心、手上业务与反应延迟。

以下字段不得出现在两个交接切片的决定中：具体景别、构图、机位、摄影机距离、焦段、镜头型号、景深、摄影机运动、稳定器、灯位、曝光、剪辑时长、切点、正式 Prompt 句式。

## 9. 常见失败与返回

| 失败 | 处理 |
|---|---|
| 缺剧本版本或原文定位 | 返回 `script-truth-index`，不产出可交接节拍 |
| 重要角色缺当前有效母档 | 返回 `acting-direction` 模式 A |
| 专业事实会改变因果但结论暂不可裁决 | 返回 `specialist-consultant-router` |
| 目标写成情绪 | 改写为对象明确的行动目标，不改台词 |
| 每句台词切一拍 | 按策略／信息／权力／状态变化合并 |
| 潜台词来自虚构传记 | 降为提案或未知，补写可追溯依据 |
| 需要改变台词、顺序或因果 | 先建立新剧本内容版本，再做兼容复核 |
| 下游要求指定机位或运镜 | 交 `directing-blocking` 或后续镜头责任 Skill |
| 上游替代但差异不清 | 标记待复核，保持“输入不足” |

通用结构能在 C04 验证；节拍密度、潜台词质量和真实场戏推进必须在 V01 用用户剧本验证。
