# Profile 阶段与交接合同 v1.1

本合同回答四个问题：何时询问、完整 Profile 能处理什么、何时关闭、下游能拿走什么。完整 Profile 不是项目常驻上下文；每次调用都必须有同部门责任 Skill、用户本次明确选择、精确 `ProfileID@版本`、作用范围与失效点。

## 阶段矩阵

| 部门 | 允许询问与读取阶段 | 责任 Skill | 本体失效点 | 可跨阶段继承的唯一内容 |
|---|---|---|---|---|
| 导演 | 项目风格意图基线 | `style-lock-director` 模式 A | 项目风格意图基线交付后 | 项目风格意图卡中的观众关系、真实度边界、跨部门不变量、禁区及其适用范围 |
| 导演 | 导演与人物调度 | `directing-blocking` | 当前导演调度卡交付后 | 调度卡中的观众视点、信息顺序、空间行动、轴线、揭示与禁止项 |
| 摄影指导 | 全片摄影基线 | `cinematography-direction` 模式 A | 全片摄影规则卡交付后 | 全片摄影规则卡中的视场/透视、摄影机距离、镜头族、焦点、曝光、支撑和运动边界 |
| 摄影指导 | 用户明确确认的限时场戏摄影例外 | `cinematography-direction` 模式 B | 指定场次或镜头范围结束后 | 例外卡中相对全片基线改变的最小规则、适用范围和恢复点 |
| 美术／Production Design | 美术与 LookDev | `art-lookdev-direction` | 美术/LookDev规则卡交付后 | 美术基线中的世界、空间、材质、工艺、色彩、母题、禁止项和资产短执行决定 |
| 编剧／剧作 | 剧作与场戏节拍 | `dramaturgy-scene-beats` | `DSB`场戏节拍卡交付后 | `DSB@版本 + BDT@版本`中的剧本事实、目标、障碍、策略、潜台词、信息和权力变化；不含Profile身份 |
| 剪辑 | 剪辑与节奏 | `editing-rhythm` | 剪辑节奏卡交付后 | 剪辑卡中的镜头关系、时长、切点、动作/声音接点和生成单元 |

## 统一询问规则

1. 路由先确认通用专业 Skill；到达上表某一阶段后，责任 Skill 才列出同部门可选 Profile、代表作品、成熟度和证据边界。
2. 用户未明确选择具体 Profile 时不读取完整卡。默认最多一个主 Profile；补充 Profile 必须另行确认唯一问题、最小范围和失效点。
3. 同一主体曾在本项目或上一个阶段使用，不构成当前阶段授权。导演在项目风格意图和场戏调度之间必须重新询问；摄影场戏例外也不能继承全片基线阶段的选择授权。
4. `初版／受限可选` 必须同时提示“方法为分析性归纳、未逐条核验”。结构校验通过不等于作品归属、方法归因、创作者意图或模型适配已核验。
5. 完整 Profile 只在本阶段推理中存在。阶段交付时输出采用方法、舍弃方法、可观察目标、禁止项、冲突处理和失效点；随后关闭完整 Profile。
6. 只有表中最后一列的“项目规则切片”能进入下一阶段。下游不得读取完整 Profile、主体姓名、代表作品、未采用方法或资料库目录，也不得把短卡原文塞进图片/视频 Prompt。

## 部门冲突与返回

- 导演项目风格意图只决定观众关系、真实度边界和跨部门目标，不代写美术、摄影或灯光方案；场戏调度只决定叙事视点和人物空间行动，不决定具体焦段。
- 美术 Profile 不发明剧本世界事实；硬历史、科学、法律、职业或物理结论交专业顾问。
- 摄影 Profile 不重新决定镜头叙事功能、信息顺序、人物调度或剪辑关系。场戏规则无法支撑已成立方案时，先返回责任上游，或按用户确认建立最小摄影例外。
- 编剧／剧作 Profile 在剧本已锁定时只分析；改写事件、因果、台词或出入场必须另获用户授权，并先由 `script-truth-index` 建立新剧本内容版本。Profile只影响当前场戏的分析方法，在DSB交付后关闭，导演与表演不得读取其主体姓名、片名或未采用方法。
- 剪辑 Profile 不复制代表作平均镜头长度，不重做机位；需要改变场戏目标、信息顺序或人物调度时返回对应责任 Skill。

## 中央版本与项目采用

中央 Profile 卡使用 `v1.1` 一类版本，项目长期控制卡使用 `v001` 一类独立版本，单次专业成果另有自己的成果版本；三者不得互相推导。

- 中央 Profile 升级，不自动修改项目卡，也不使项目固定引用失效。
- 项目继续使用旧 `ProfileID@版本` 时，读取 `references/history/` 中对应定义；不得用资料库当前版本静默替换。
- 项目决定采用新版方法时，由责任专业 Skill 重新推导项目卡或任务成果；内容或精确引用实质变化后，才由项目版本事务建立下一项目版本。
- 项目采用产生的规则和验证结果不反向升级中央 Profile。中央卡升级到“已核验”仍需逐条具体来源；升级到“项目验证”还需用户确认的适配与失败边界。
