# 灯光指导

## 进入与职责门

先由 `production-router-handoff` 说明本轮唯一工作模式、最小输入和交付物，并取得用户确认。没有具体项目、项目绑定、当前有效上游版本或可定位空间时，只列阻断缺口，不建立虚构灯光方案。

本 Skill 唯一写入项目灯光基线、场景光源地图、人物受光卡、多视图灯光继承卡和镜头灯光短执行卡。它负责来源光的角色、方向、范围、相对关系、控光、可观察受光、阴影、反射、色彩污染和灯光侧曝光实现。

- `location-spatial-production` 唯一写空间锚点、门窗/灯具位置和摄影机投影；本 Skill 引用锚点，不移动或补造空间。
- `cinematography-direction` 决定相机侧曝光保护、动态范围、镜头族、景深和摄影机实现；本 Skill 用来源、光比、填充、反射与负补光实现目标，不修改摄影机方案。
- `vfx-asset-production` 决定 VFX 自发光身份、来源、颜色、强度曲线、阶段与时序；本 Skill只计算其落在人物、物体和场景上的受光、阴影、反射与曝光共存。
- `shot-visual-design` 决定镜头叙事、机位、构图和运镜；本 Skill 只为已确定镜头提供灯光执行。
- `image-prompt-production` / `video-prompt-production` 负责完整 Prompt；本 Skill 不写完整 Prompt、不生成候选、不登记资产。

灯光阶段不读取大师 Profile。项目风格、美术与摄影选择只通过当前已生效规则卡切片传入，不传 Profile 姓名、片名或本体。

## 每次只选一种工作模式

### A｜项目灯光长期基线

用于风格四卡最后一张长期基线，或项目长期灯光原则实质变化后的重建。

1. 只读取当前计划生效或已生效的全片摄影规则直接上游，以及其中传递的项目目标、美术材料和摄影曝光约束；顾问成果另列任务成果引用。
2. 定义全片主方向逻辑、允许的来源类别、实景光/环境填充/反射/负补光关系、人物与材料受光原则、暗部可读性、剪影/死黑/过曝边界、天气时间变化和 VFX 共存边界。
3. 不写具体场景光源坐标、具体人物站位或逐镜灯光变化。
4. 使用 [项目灯光基线卡模板](assets/项目灯光基线卡模板.md) 输出 `待确认 + 当前有效=否` 草案，交 `creative-control-versioning` 管理项目版本和生效事务。

本模式只把全片摄影规则作为直接上游长期基线。中央源升级不自动改变既有项目卡；项目采用内容或精确输入引用实质变化时才建立下一项目版本。

### B｜场景光源地图

用于已定位场景的基准光影状态，或新的时间、天气、灯具开关与 VFX 发光状态。

1. 读取当前有效项目灯光基线、空间圣经、空间锚点、空间依据资产、时间天气、场次功能和必要 VFX 定义。
2. 为每个来源或控光项建立稳定 ID，按“主方向光、实景光、环境填充、反射／回弹、负补光、VFX 自发光”分类；太阳、天空、窗、灯具、火焰、霓虹、车灯等写真实来源或方向场。
3. 写世界位置或方向、锚点、朝向、形状/相对尺寸、色温/颜色、相对强度级、作用区、衰减、遮挡/束光、开关/时序、主阴影贡献、反射与色彩污染。
4. 使用 [场景光源地图说明卡模板](assets/场景光源地图说明卡模板.md)、[场景光源地图模板](assets/场景光源地图模板.csv) 和 `lighting-source-map.schema.json`。

同一空间的基准状态与改变了时间、天气、灯具开关或主光条件的状态使用不同 `光影状态ID`；修正同一状态的定义或精确输入时递增地图成果版本。光源地图是任务数据集，不是图片资产，也不进入正式资产登记。

### C｜人物受光设计

用于人物进入已建立光源地图的空间，或人物站位、朝向、动作路径、服装/肤色/伤妆反射特性变化后的灯光适配。

1. 读取当前光源地图、人物正式资产精确版本、站位/朝向/动作路径、场戏表演与摄影曝光保护最小切片。
2. 依次计算眼睛、面部结构、肤色、头发、服装、手与关键道具的主受光面、填充、负补光、轮廓分离、反射和色彩污染。
3. 对移动人物写起点、转折点和终点的受光连续性；眼神光必须来自地图内可解释来源，不额外发明正面灯。
4. 使用 [人物受光卡模板](assets/人物受光卡模板.md)。人物受光卡是创作短卡，不修改人物资产本体或项目灯光基线。

### D｜多视图灯光继承

用于同一空间换摄影机角度、场景母图派生视图、专项视图或同一光影状态的多视图资产。

1. 读取同一光影状态的当前光源地图、空间圣经、目标视图摄影机卡、锚点投影、人物/对象位置和材料切片。
2. 保持太阳、天空、窗、灯具和控光项的世界位置、方向、开关与时序不变；只重新计算该机位可见的发光源、受光面、屏幕阴影方向、遮挡、镜面高光和反射。
3. 区分“世界阴影方向”与“屏幕上的左/右投影”；摄影机转到反面后屏幕方向可以改变，但世界关系不能改变。
4. 使用 [多视图灯光继承卡模板](assets/多视图灯光继承卡模板.md)。需要改变时间、天气或开关状态时返回模式 B 建立新光影状态，不在继承卡里偷改地图。

### E｜镜头灯光短执行

用于已完成分镜、剪辑写回和逐镜摄影审核的 Seedance 生成单元；也可用于 GPT Image 2 的单张明确视图灯光切片。

1. 读取当前光源地图、适用人物受光/多视图卡、分镜镜头版本、摄影审核、VFX 单镜条款和生成单元时长。
2. 只保留模型必须执行的来源、可观察受光、开始—变化—结束、阴影/反射、曝光护栏和禁止新增项。
3. 不重写镜头叙事、机位、运镜、人物表演或 VFX 时序；发现冲突时返回责任上游。
4. 使用 [镜头灯光短执行卡模板](assets/镜头灯光短执行卡模板.md)，交 Prompt Skill 装配完整正文。

镜头短卡按一个生成单元建立稳定成果 ID/版本。只有下游 Prompt 改版且本卡输入与内容完全不变时才保留当前卡；镜头版本、灯光正文、适用镜头范围或任一精确上游实质变化时建立下一成果版本。

## 灯光决策顺序

具体判断读取 [来源光、受光与曝光决策合同](references/lighting-decision-contract.md)，至少依次完成：

1. 锁定时间、天气、空间与剧情状态，区分空间事实、灯光设计和未知项。
2. 建立来源/控光清单，先判断世界位置和作用范围，再判断画面结果。
3. 选出一个清楚的主方向逻辑，但允许多个有来源实景光、环境填充和局部二次阴影；禁止把“一致”误写为“只能有一个光源”。
4. 计算人物、物体、背景和反射材料的受光层级，明确哪些信息必须可读、哪些允许隐藏。
5. 以摄影约束为边界实现曝光，写相对关系和可观察结果；没有测量依据时不伪造 lux、EV、功率或精确光比。
6. 换角度时保持世界光场，只重新投影；换时间、天气、开关或 VFX 阶段时建立新状态。

## 交付、版本与索引

- 项目灯光长期基线使用稳定控制卡 ID 和项目卡版本，只进入 `creative-control/项目创作基线索引.csv`，不得复制为任务成果。
- 光源地图使用稳定 `LMP-<项目ID>-<场景ID>-<光影状态ID>`，成果类别为“任务数据集”；人物受光、多视图继承和镜头短执行分别使用 `LRC-`、`LVI-`、`LSX-` 稳定成果 ID，成果类别为“创作短卡”。它们都进入 `tasks/任务成果索引.csv`。
- 新任务成果先为 `草案 + 当前有效=否`；完成专业复核和结构检查后才能成为 `可交接 + 是`。结构通过不等于资产批准、Prompt 放行或创作质量通过。
- 相同输入原样再调用不升级。内容、适用范围、工作模式或精确上游引用实质变化时递增成果版本；旧成果文件保持不可变。

## 返工路由

- 门窗、灯具、人物位置或空间锚点错误：`location-spatial-production` / `directing-blocking`。
- 全片摄影曝光保护、动态范围、摄影机、焦点或镜头实现错误：`cinematography-direction`。
- 光源角色、受光、阴影、反射、负补光或多视图继承错误：返回本 Skill 对应模式。
- VFX 来源、颜色、强度曲线、阶段或时序错误：`vfx-asset-production`；环境未正确接受特效光：返回本 Skill。
- 分镜机位、构图、观众视点或运镜动机错误：`shot-visual-design`。
- 灯光设计正确但 Prompt 漏译、冲突或优先级错误：对应 Prompt Skill。

## 停止条件与禁止事项

遇到项目/上游版本不唯一、空间锚点无法定位、时间天气未定、人物站位或目标视图不明、摄影曝光目标冲突、VFX 自发光定义缺失会改变结果时暂停，只询问当前阻断决定。

禁止发明第二个太阳或无来源正面补光；禁止让眼神光、轮廓光或彩色污染没有地图来源；禁止把屏幕左右当世界方向；禁止移动门窗灯具以迁就构图；禁止用灯光修复空间、摄影、表演或 VFX 本体问题；禁止输出器材清单代替画面结果；禁止写完整 Prompt、生成候选或登记资产。

## 输出

- 模式 A：项目灯光长期基线草案和控制版本操作申请。
- 模式 B：场景光源地图说明卡、CSV 数据集和成果索引事务输入。
- 模式 C：人物受光卡及移动连续性。
- 模式 D：多视图灯光继承卡和冲突项。
- 模式 E：镜头灯光短执行卡及唯一返工节点。

默认使用轻量生产回显，只展示当前可见灯光方案、必要缺口和一个决定点；后台任务单、版本、索引与校验保持完整。
