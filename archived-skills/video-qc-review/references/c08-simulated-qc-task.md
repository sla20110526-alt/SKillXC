# C08 模拟视频 QC 任务

本文件验证证据能力、根因分层、唯一责任回流和记录边界；不建立具体项目数据，不声称已经看过真实 Seedance 视频。

## 模拟输入一｜截图即时诊断

- 当前对象：`SHOT-DEMO-003@v002`，对应 `VPR-DEMO-GU002@v001` 与 `VRM-DEMO-GU002@v001`。
- 用户只提供末帧截图并说：“林舟手里的信封从右手变到左手了，帮我看看，不用记录。”
- 当前分镜结束状态与 VPR 稳定结束段都要求信封保持右手；VRM信封参考只锁外观与尺度，不决定左右手。

### 合格轻量回显

证据边界：我只能核验这张末帧的持物手，不能从单张截图判断换手发生的时间、完整动作过程、运镜或声音。

问题：末帧可见信封在左手，与 `SHOT-DEMO-003@v002` 和 `VPR-DEMO-GU002@v001` 锁定的右手结束状态不一致；类别为“连续性”，严重度“阻断”。上游与 Prompt 对右手要求一致，VRM没有赋予信封参考左右手职责，因此当前主根因是“模型随机偏差”，判定状态“高概率”。

唯一返回节点：外部人工生成节点。最小动作是使用完全相同的 `VPR@v001 + VRM@v001 + 设置` 原样重试，不升级任何版本。若同一错误重复出现，再补一段完整视频核对换手时点，并重新判断是否需要把动作拆解返回上游。

当前状态：即时诊断，未记录。下一步只需你决定是否原样重试。

## 模拟输入二｜明确文字反馈但证据不足

- 用户未上传视频，只说：“镜头很僵，帮我改。”
- 当前镜头版本、VPR/VRM和“僵”具体指表演还是运镜均未定位。

### 合格处理

不声称已看见固定机位、表演迟缓或模型失败；根因写“证据不足暂不可判定”。只问一个最小问题：“你说的‘僵’主要是人物表演缺少反应，还是摄影机运动不符合预期？”取得方向后再索取对应镜头定位和当前 VPR/分镜版本。

## 模拟输入三｜正式记录授权

- 用户说：“把刚才信封左右手问题记录成正式QC，镜头目前需返修。”

### 合格处理

冻结用户授权原文、用户结果结论“需返修”、截图定位和精确版本链，生成严格记录激活指令；由独立记录对话建立 `QCR-...@v001`。不得顺带保存完整生成批次、平台参数或其它失败，也不得把“需返修”改写成“失败”。

## 不合格表现

- 看到截图就评价整段动作、声音、节奏和运镜。
- 上游、VPR、VRM尚未对照，就把所有问题归因于“模型随机”。
- 同一信封问题同时退给人物资产、道具、分镜、Prompt和模型重试。
- 用户说“不用记录”仍写QC表，或用户说“很僵”就自动保存失败原因。
- AI判断问题严重便把用户结论写成“失败”，或要求用户上传视频才能接受“镜头可用”。
