# 资产需求计划

## 三种身份必须分开

- `需求槽位ID`：某项生产需求，例如 `REQ-CHR-001`。
- `正式资产ID`：资产拆解阶段预留的项目内稳定身份，例如 `CHR-001`；预留不等于登记。
- `生成批次ID`：一次具体生成尝试，例如 `GEN-CHR-001-003`。
- `正式资产ID@版本`：用户明确登记后才存在的可调用版本，例如 `CHR-001@v001`。

绝不把需求槽位、预留 ID 或生成结果预先写成正式资产版本。

## 执行

1. 读取项目 ID、项目数据绑定卡、剧本事实索引和 `script-asset-breakdown` 带预留正式资产 ID 的候选清单。
2. 复核去重，沿用预留正式资产 ID，并建立基础资产、服装版本、状态变体和组合资产的父子关系。人物按“脸母图槽位 → 五视图基础卡槽位 → 服装/状态/交互槽位”排成精确依赖链；脸母图与五视图卡必须是不同预留正式资产 ID。
   场景按“场景母图槽位 → 场景状态或场景视图槽位 → 光影状态槽位”排成精确依赖链；每张图片交付使用不同预留正式资产 ID。空间圣经、锚点表、视图投影表和光源地图进入任务成果索引，不建立图片资产槽位。
   道具/载具按“基础对象 → 状态/表面应用/装配”排成精确依赖链；图案文字先排独立母版槽位，再作为表面应用的附加依赖。对象定义、部件/交互锚点和文字校对表进入任务成果索引，不建立图片资产槽位。人物/生物交互组合由主体责任 Skill 排产，但必须等对象本体正式登记。
   生物/怪物按“基础形态 → 结构形态链或生理状态 → 持物穿戴组合”排成精确依赖链。结构变体只能等待基础/上一结构形态正式登记，状态变体等待正确生命体父版本，组合同时等待生命体父版本和全部道具/载具附加版本。形态定义、解剖锚点和运动约束进入任务成果索引，不建立图片资产槽位；转化中间过程只在确有可稳定调用的实体阶段时建结构变体槽位。
   VFX按“视觉母版 → 状态/强度变体或接触参考”排成精确依赖链。视觉母版按需等待固定来源/触发实体，状态等待母版/上一状态，接触参考同时等待VFX父版本和全部接触人物、场景、光影、对象或生命体。VFX定义、时序集、接触集和行为分阶段设计板进入任务成果索引，不建立图片资产槽位；一次性单镜效果只进入镜头任务，不建图片资产槽位。
3. 按镜头重要性、出现频率、生成难度和上游依赖确定 P0/P1/P2。
4. 先排风格测试资产，再排基础资产，再排变体；避免在父资产未登记前制作子变体。人物脸母图未明确登记时不得排五视图卡为可生产，五视图卡未明确登记时不得排其服装、状态或交互派生候选。
5. 为每个槽位指定完成定义、必要视图、依赖、相关场次和负责的生产 Skill。
6. 更新计划时保留已登记资产版本，单列受影响项，不静默重写。

声音槽位只对应需要独立参考音频的说话者，一名说话者的基础声音身份默认一个槽位，负责 Skill 为 `sound-voice-direction`。完成定义至少包含：已生效的声音身份卡或简单说话者跳过理由、可独立播放且可唯一定位的音频文件、授权/来源说明、污染与调用范围，以及用户明确登记后的正式版本。环境底声、动作音效、逐场声音表现和临时镜头内声音不得建立需求槽位。

人物脸母图槽位的完成定义至少写“清晰近景、身份锚点和眼神光可判断、用户明确登记”；五视图基础卡槽位至少写“已登记脸母图精确版本、单张固定五视图版式、跨视图身份/身体/妆造一致、用户明确登记”。服装、状态和交互槽位分别写清正确父版本、唯一变化集合及全部附加版本，不能只写“人物变体完成”。

场景母图槽位的完成定义至少写母图构图子模式、空间面/纵深/入口/活动区/锚点读取和用户明确登记；场景视图槽位至少写已登记空间依据、摄影机位置/朝向/高度/视场、全部锁定锚点投影和用户明确登记；场景状态与光影状态分别写清正确父版本、唯一变化集合及空间/光源继承。分镜返回的新专项视图先补槽位和预留 ID，再激活生产对话。

基础道具/载具槽位的完成定义至少写对象交付形态、尺度依据、部件数量、方向、结构/功能锚点、材质和用户明确登记；状态槽位写正确父对象与唯一变化；图案母版槽位写逐字内容、版式和校对通过；表面应用槽位写父对象、全部图案母版、目标锚点和工艺；对象装配槽位写主承载对象、全部附加部件、连接与受力。载具舱内另建场景母图槽位，并把已登记载具列为附加依赖。

生物基础形态槽位的完成定义至少写单张总览卡、形态定义、解剖锚点、尺度/质量、肢体器官数量、承重、表皮、主要运动约束和用户明确登记；结构变体写正确父形态、新增/移除锚点、质量重分配与运动后果；生理状态写正确父生命体、部位/侧别/阶段和功能后果；持物穿戴组合写生命体父版本、全部对象附加版本、双方锚点、接触、受力、遮挡和运动限制。

VFX视觉母版槽位的完成定义至少写单张代表阶段参考、VFX定义、材料层级、尺度、颜色/发光边界、物理规则、时序与用户明确登记；状态/强度槽位写正确VFX父版本和唯一变化；接触参考写VFX父版本、全部接触实体、发生阶段、接触区域、作用、环境受光与残留。单镜执行需求的完成定义写可见阶段、时长、来源、路径、接触、受光、残留和稳定结束状态，不等待图片登记。

分类责任必须写成唯一生产 Skill：人物/服装妆造 → `character-asset-production`；场景/场景视图/光影 → `location-spatial-production`；道具/载具/图案文字 → `prop-vehicle-production`；生物怪物 → `creature-monster-production`；VFX → `vfx-asset-production`；声音 → `sound-voice-direction`。`world-asset-production` 只能作为类别不清或混合需求的临时路由责任；它完成拆分后必须把槽位改交具体生产 Skill。跨类别组合先排各基础资产登记，再排组合候选。

## 资产类型

人物、服装/妆造、场景、光影状态、道具、载具、特殊生物/怪物、VFX、图案/文字、角色声音参考音频。

## 输出

- `资产需求总表.csv`
- `资产依赖关系.csv`
- `生产批次计划.md`

使用 `assets/生产批次计划模板.md`、两张 CSV 模板、`assets/asset-demand.schema.json` 和 `assets/asset-dependency.schema.json`，按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 生成校验报告并写回计划卡。字段见 [资产需求字段](references/asset-demand-fields.md)。

Schema 通过只表示结构可交接，不使需求槽位或预留 ID 成为正式资产；交给 `production-router-handoff` 发任务，不交给正式资产登记。
