# 创作控制版本模型

## 版本域

| 版本域 | 示例 | 谁能升级 | 升级条件 | 项目调用的结果 |
|---|---|---|---|---|
| 中央源定义 | `CCS-CINEMATOGRAPHY@v001` | 中央仓库维护任务 | 专业方法、必填结构或交接规则实质修改 | 项目只固定引用，不修改源版本 |
| Profile卡 | `FP-CIN-ROGER-DEAKINS@v1.1` | `film-profile-library` | 原始方法、证据、适用边界或交接规则修改 | 生成项目短执行决定，不升级原卡 |
| 项目控制卡 | `CC-CIN-001@v002` | 对应专业生产＋专用版本对话 | 项目规则、范围、采用方法、输入引用或禁区实质变化 | 新版待确认，确认后替代旧生效版 |
| 任务短卡 | `SCN-010-BLOCK@v003` | 对应任务 Skill | 该场戏或任务内容变化 | 任务成果索引追踪，不进入长期基线索引 |

三个版本号独立递增，禁止从 `Profile@v1.1` 推导项目卡为 `v011`，也禁止因为项目建立 `v002` 就修改中央源。

## 中央源升级

中央源目录中的每个 ID 只表示一类控制定义。修改目录列出的原始规则或模板时：

1. 判断是否改变专业方法、必填结构、状态门或下游交接。
2. 实质改变则把该源的当前版本递增一位并说明变更摘要；纯错字、排版和链接修复不升级。
3. 不批量改写任何项目数据。既有项目继续固定引用旧源版本。
4. 项目只有在用户选择采用新源并重新生成控制卡时才产生项目新版本。

`available_versions` 是已发布历史，不得删除、重排或把未发布编号补写为历史；`definition_paths` 必须能定位每个已发布版本的只读定义或当前模板，旧项目引用必须继续可验证。

历史项目卡可以继续按其已发布中央源版本只读验证和交接；但新的 P0 评审或批量放行只接受当前四卡“唯一直接上游”链。仍使用旧版多祖先依赖形状的项目，必须先由用户决定采用当前中央源，并重建受影响的四卡项目版本链，不能拿旧组合直接生成新的评审或快照。

Profile 使用自己的 `v1.x` 版本规则，不登记为中央源定义版本；精确历史版本必须存在于 `film-profile-library/references/profile-version-history.json` 并有仓库内定义文件，不得因版本号低于当前版本就推断它曾经发布。Profile 当前版本升级不自动替换项目固定引用；用户决定采用后，由责任专业 Skill 重建项目卡或任务成果，精确引用实质变化才升级项目版本。

## 项目首次建立

无论中央源或 Profile 是哪个版本，每个项目的稳定控制卡 ID 首版都是 `v001`。例如：

```text
源定义：CCS-CINEMATOGRAPHY@v003
Profile：FP-CIN-ROGER-DEAKINS@v1.1
项目控制：CC-CIN-001@v001
```

项目卡只提取当前项目采用的决定，不复制完整 Skill 或 Profile。

## 项目升级判定

升级：

- 项目基线规则或作用范围改变；
- 采用/舍弃的 Profile 方法改变；
- 必须继承、允许变化、禁区或例外改变；
- 精确输入控制卡引用改变；
- 新中央源被项目明确采用，导致源引用或项目执行内容改变。

不升级：

- 再次加载同一文件或恢复对话；
- 把同一项目卡交给新任务；
- 用户只确认状态而正文未变；
- 只改错字、排版、路径或引用格式；
- 中央源/Profile发布新版但项目没有采用；
- 上游变化经复核后，本卡正文和精确输入引用都不需要改变。

状态变化与内容版本分离：`待确认 -> 已生效 -> 已替代` 不另建版本。

## 下游读取

下游必须同时满足：项目 ID 一致、状态为 `已生效`、当前有效为 `是`、作用范围覆盖当前任务、精确源和 Profile 引用可追溯。不得用“最新版”或文件修改时间替代稳定 ID 与版本。

长期基线的正式依赖方向只有 `项目风格锁定 → 美术LookDev → 全片摄影 → 项目灯光`，并且每张下游只精确引用前一张直接上游：风格无上游、美术只引风格、摄影只引美术、灯光只引摄影。祖先规则沿链传递，不在下游重复列全；顾问结论只以当前可交接的 `CCR-...@v###` 写入独立“顾问任务成果引用集合”，CQP问题包和CED证据集不得进入长期卡。首次建立或上游换版时，受影响的新依赖链可以同时保持待确认并互相精确引用；确认时必须在一次原子事务中使整链生效。任何生效下游只能引用当前生效上游，禁止出现“上游已换版、下游仍引用旧版”的半更新状态；停用上游也必须同事务停用全部当前依赖下游。上游卡禁止引用下游卡，防止为“汇总”制造循环升级。P0评审卡和最终风格包分别进入任务成果索引；最终风格包是组合快照，不是第五张长期基线。
