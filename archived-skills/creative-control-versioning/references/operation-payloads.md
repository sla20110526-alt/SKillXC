# 创作控制版本操作载荷

## 草案入表

```json
{
  "项目ID": "PRJ-001",
  "事务ID": "CCV-PRJ-001-001",
  "操作日期": "YYYY-MM-DD",
  "记录": [
    { "完整索引行": "字段必须与对应CSV表头完全一致" }
  ]
}
```

`记录` 可以包含一行或一组可唯一识别的控制卡。每行必须是下一连续版本、`待确认 + 当前有效=否`，卡片文件已经保存为带版本号的独立文件。

## 确认生效

```json
{
  "项目ID": "PRJ-001",
  "事务ID": "CCV-PRJ-001-002",
  "操作日期": "YYYY-MM-DD",
  "目标": [
    {"卡片ID": "CC-STYLE-001", "版本": "v001"},
    {"卡片ID": "CC-CIN-001", "版本": "v001"}
  ],
  "用户操作原文": "确认这组项目基线按当前版本执行"
}
```

目标必须都存在且为待确认；脚本在一个索引事务中使其生效并替代各自旧生效版。长期基线上游变化时，`目标` 必须包含所有受影响的新依赖链版本，不能只确认上游；四卡采用唯一直接上游链，不在载荷中补写祖先引用。表演和声音可以一次确认同一索引内的一组母档/身份卡。

## 明确停用

结构与确认生效相同，`用户操作原文` 必须明确停用。停用长期上游时，`目标` 必须同时列出全部当前直接/间接依赖下游；否则事务拒绝。停用不会自动恢复旧版；需要恢复旧内容时建立新的项目卡版本。
