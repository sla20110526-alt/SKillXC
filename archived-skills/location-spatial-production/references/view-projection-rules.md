# 场景视图投影与Prompt规则

## 先建立摄影机卡

每个候选视图必须先写：

- 预留正式资产 ID、视图用途和所依据的母图/场景状态 `ID@版本`
- 摄影机在空间局部坐标或命名区域中的位置
- 朝向的锚点或轴线、机位高度、俯仰/水平关系
- 视场宽窄、透视强弱和需要覆盖的活动区
- 允许离画、必须看见和禁止新增的锚点

不要只写“反打”“另一侧”“从门口看”“同一房间换角度”。这些可以是用途摘要，不能代替空间位置和锚点投影。

## 锚点投影算法

对空间锚点表中每个 `可见锁定` 或 `关系锁定` 条目逐项判断：

1. 相对摄影机位于前、后、左、右、上或下哪个方向。
2. 是否进入视场；进入时落在画面左/中/右和前/中/后景何处。
3. 摄影机能看到锚点哪一表面；门窗开口朝向是否合理。
4. 是否被墙、柱、家具或其他锚点遮挡；遮挡者写稳定锚点 ID。
5. 若锚点画外，仍保留空间位置，不为填满构图把它搬回画面。

使用投影表一行记录一个“视图—锚点”关系。所有锁定锚点都要有行，包括画外条目；这样才能区分“正确离画”和“生成丢失”。

## 未知区域补全

新机位必须显示未知区域时：

- 只补全构图所需的最小范围，列出新墙面、连接、材质或陈设候选。
- 保持已知墙线、开口、尺度、功能和材质逻辑；不得用新家具掩盖结构矛盾。
- 把每个新条目标为 `推断待确认`，写明来源是设计建议而非母图事实。
- 用户否决时重做；用户明确确认或图片登记后，才更新空间圣经。

## 视图类型

- **预制剧情视图**：支持剧本中已知动作、入口、对话站位或关键道具关系；只做最少必要数量。
- **专项镜头视图**：响应导演/分镜提出的具体观众视点、遮挡、主观视角或运动路径；发现新空间身份时返回资产计划，不在 Prompt 临时造房间。
- **英雄剧照视图**：服务视觉展示或用户指定的漂亮构图；仍服从空间圣经，但不承担母图权威，除非用户明确把剧照式构图指定为母图。

## 光线继承

基础新视图同时读取任务单绑定的当前空间圣经和当前光源地图，并由 `lighting-direction` 建立多视图灯光继承卡；空间圣经不反向引用下游地图：

- 太阳、天空、窗光和主要灯具的世界位置不随摄影机移动。
- 根据新机位重算人物/物体受光面、世界阴影在屏幕上的投影、镜面反射和灯具是否入画；本 Skill 只提供摄影机与锚点投影，不代写灯光结果。
- 允许多个有来源实景光，但必须有一个清楚的主要方向性逻辑；禁止两个冲突太阳或同一物体出现互相否定的主阴影。
- 若时间、天气、灯具开关或主光条件改变，建立独立光影状态，不把变化混进基础视图。

## GPT Image 2 装配顺序

把以下内容交 `image-prompt-production`，由其写完整自然语言 Prompt：

1. 同一场景身份、空间依据和本次唯一视图用途。
2. 摄影机世界位置、朝向、高度、视场和透视。
3. 必须可见锚点的画面位置、景深层级和可见表面。
4. 必须遮挡或离画锚点及遮挡者。
5. 允许补全的未知区和禁止新增项。
6. 结构、尺度、材质、磨损、色彩与光源继承。
7. `PRESERVE EXACTLY / CHANGE / ONLY CHANGE` 与精确依赖版本。

参考图用途按优先级分开：空间依据图负责场景身份和结构；已登记补充视图只补对应锚点；材质/风格参考不改变空间；光影参考只改变已批准的光影字段。参考冲突时暂停，不平均多个空间。

## 生成后检查

逐项检查：

- 空间连接、墙线和门窗是否成立
- 锚点数量、位置、方向和左右关系是否正确
- 尺度、视场和透视是否支持指定用途
- 遮挡与画外是否符合投影表
- 材质、磨损和固定陈设是否继承
- 光源位置、阴影和反射是否连续
- 是否擅自补全未知区、镜像场景或变成另一个地点

任一问题先报告给用户并等待调整方向，不自行登记或记录失败原因。
