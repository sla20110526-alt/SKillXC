# 表演指导

表演不是展示情绪，而是人物在压力下为得到某样东西采取行动。

## 唯一责任

`acting-direction` 唯一负责建立、修改和版本化角色表演母档与场戏表演卡。剧作负责目标、信息、潜台词和戏剧节拍；导演负责观众视点与人物调度；声音负责声音身份与对白声音表现；镜头设计和 Prompt 生产只能读取表演结果，不能在下游另写一套人物性格或表演基线。

每张任务单只选择以下一种模式。

## 首次建档所需资料

系统必须已有：项目数据绑定卡、项目锁定卡中的表演尺度、当前剧本/内容版本与生产范围、角色 ID/名称、该范围的剧本事实和场次出处。没有这些基础信息时不建立可生效母档。

用户可按需要提供：演员或影片表演参考及其具体用途、角色关系与职业身体经验、希望保留的习惯动作/步态/姿态、面具破裂触发、不能出现的表演方式、对剧本未明说部分的角色理解。参考只提取方法和可观察行为，不复制演员身份或把整部作品风格混入母档。

用户不必先写完整人物传记。资料不足时，本 Skill 可以把合理内容标为 `CREATIVE_PROPOSAL` 供用户确认；涉及贯穿目标、弧线阶段、身体限制或禁区且不同答案会实质改变母档时才暂停询问。

## A｜角色表演母档

在角色第一次进入 `dramaturgy-scene-beats` 与 `directing-blocking` 之前建立，以便剧作和调度读取稳定行为边界。先读取项目锁定卡中的表演尺度、剧本事实索引、当前生产范围、角色 ID、用户锁定信息和用户提供的表演参考（如有）。正式人物资产已经存在时只读取可见的年龄感、体态和明确身体限制；不得从脸、服装或外貌推断性格。重要叙事生物/怪物同样可以用其角色 ID 建立项目内表演母档，但只读取当前可调用生命体版本、物种/形态稳定行为边界和运动约束集；本 Skill 不修改解剖、能力或生物力学。

### 谁需要母档

- 必须建立：主角、反派和关键叙事角色；反复出场角色；跨多个生成镜头需要行为连续的角色；承担关键无台词反应或动作的角色。
- 可按任务决定：只出现一次的有台词角色，或只出现一次但表演复杂的角色。
- 默认不建立：模糊背景人群、无身份路人、只承担单一简单动作且无跨镜连续性的角色；在场戏表演卡写群体行为即可。

因此不是每个项目机械建立一套空母档，也不是每场戏重建。每个需要稳定表演的角色在当前项目内建立一份母档；简单项目没有适用角色时，在任务单写明跳过理由。

### 建立方法

1. 为角色建立项目内稳定的 `表演母档ID`，例如 `ACT-CHR-001`；已有预留或正式人物 ID 时记录为 `角色ID`，不要把表演母档当作人物资产版本。
2. 把信息逐项标为 `SCRIPT_EXPLICIT`、`SCRIPT_INFERRED`、`USER_LOCKED`、`CREATIVE_PROPOSAL` 或 `UNKNOWN`。创作解释不得冒充剧本事实。
3. 只写跨场应稳定的行为基线：贯穿目标与行动引擎、社会面具、不同关系对象前的差异、私下基线、地位行为与失控反差、压力升级阶梯、面具破裂条件、倾听和注意力、眼神、呼吸与张力、重心姿态与步态、带触发条件的习惯动作/手上业务、距离与接触边界、动作惯性与恢复。
4. 依据当前生产范围标出角色弧线阶段和不可提前泄露的后期变化；不能读取范围外剧本时明确边界，不猜测后续人格发展。
5. 单列场戏可变项和禁止表演方式。不要把某一场的临时情绪、伤势、道具动作、具体台词策略或走位固化为人格。
6. 用户资料不足时只追问会改变长期行为基线的关键决定；其余保留 `UNKNOWN` 或明确的 `CREATIVE_PROPOSAL`，不编造完整传记。
7. 使用 `assets/角色表演母档模板.md` 和 `assets/角色表演母档表模板.csv` 输出，并用 `assets/acting-master.schema.json` 检查。

### 状态与版本

- 首版为 `v001`，保存为独立的 `表演母档ID@v###.md`，旧文件只读保留。每个项目母档版本的复核与生效操作都在该项目的专用表演控制对话中完成；普通场戏生产对话只读取当前有效母档并提交新版草案，不直接改母档表。
- 新交付先为 `待确认`，不替代当前已生效版本。用户明确指向母档并表示“确认这版表演母档”“按这版母档执行”或等价采用意思后，才改为 `已生效`；用户也可以一次确认一组可唯一识别的母档。这不是资产登记，不需要“登记这张”。
- 新版生效后，上一版改为 `已替代`。用户明确停用时才记 `已失效`。
- `待确认` 与 `已替代/已失效` 版本的 `当前有效` 必须为 `否`；同一项目、同一角色最多一版为 `已生效 + 当前有效=是`。
- 只有稳定行为基线、适用范围、关键事实依据、项目表演尺度或角色身体限制发生实质变化时递增母档版本。新增场戏、改变本场目标或只改 Prompt 表达不升级母档。
- 剧本版本变化时先核对受影响事实；没有影响就保留母档版本并更新审计引用，不为版本号而升级。

数据更新统一调用 `creative-control-versioning` 的表演索引事务：新草案先以 `待确认 + 当前有效=否` 加入临时完整表，校验通过后保留原表副本再替换。用户确认新版生效时，在同一次事务中把新版改为 `已生效 + 是`、旧生效版改为 `已替代 + 否`；失败则恢复原表，不允许同一角色出现两版当前有效。新版生效后把用户确认原文永久保存在 `生效依据原文`；`状态依据原文` 只说明当前状态变化。专用对话使用 `assets/表演控制对话激活指令模板.md` 启动。

中央源定义版本与项目母档版本分离。每个项目母档从 `v001` 开始并记录精确 `CCS-ACTING-MASTER@版本`；只有项目母档内容或源定义引用实质修改时才升级。中央源升级不会自动改既有项目母档。

母档固定写入绑定项目数据根目录下的 `creative-control/acting/masters/`，汇总 CSV 位于 `creative-control/acting/角色表演母档表.csv`；场戏卡写入 `creative-control/acting/scenes/`。这些目录在首次对应任务时按需建立，项目绑定阶段不预建。CSV 保留每个母档版本一行，只有一版可以是当前有效。

## B｜场戏表演适配

在 `dramaturgy-scene-beats` 和 `directing-blocking` 完成后、场戏摄影约束与逐镜设计前执行。

1. 读取本场角色当前有效的母档版本、当前 `可交接 + 当前有效=是` 且彼此匹配的 `BDT-...@v###` 逐节拍数据、`DSB-...@v###` 中的成果身份／原文保护门／“给场戏表演适配的最小切片”，以及精确匹配其剧作来源的 `DBD-...@v###` 调度数据与 `DBC-...@v###` 成果身份／保护门／下游执行切片、进入状态、服装伤势与道具状态。只继承剧作切片中的逐角色目标、障碍、失败代价、策略、可见行为、潜台词、人物已知／未知信息、节拍进出状态和锁定台词引用；从导演成果只继承人物位置、距离、朝向、视线、遮挡、接触、出入场、移动触发、轴线和连续性状态。不读取 DSB 或 DBC 的 Profile 采用审计区；不得读取完整编剧／剧作 Profile，也不得读取完整导演 Profile、主体姓名、片名或未采用方法。任一成果缺失、待复核或精确版本不匹配时返回对应 `dramaturgy-scene-beats` 或 `directing-blocking`；需要母档的角色没有当前有效版本时返回模式 A，经任务单明确为简单角色时可只做本场适配。
   重要叙事生物/怪物另读取当前可调用生命体版本、形态定义和运动约束集最小切片；只设计其本场目标、策略、注意、呼吸/张力与动作选择，不改解剖、运动能力或物种稳定行为边界。
   VFX 构成本场可见刺激或接触时，读取已定触发点、来源方向、可见阶段和接触结果；表演只设计角色何时察觉、注意目标、预备、受力、恢复和继续行动，不得让角色提前知道尚未发生的阶段，也不得改写 VFX 因果。
2. 写清人物此刻想从具体对象那里得到什么、障碍和失败代价。
3. 每个节拍选择可表演的行动策略，如试探、讨好、拖延、压迫、隐藏、撤退；不得改变剧作的信息顺序、原台词或既定调度。
4. 设计倾听：对方台词结束前听者反应已开始；回答前保留判断过程。
5. 设计眼神：注意目标、微扫视、眨眼和眼睛先于头部；眼神光仍服从现场光源。
6. 设计身体生活：呼吸、张力、重心、步态、距离、手上正在做的具体事情和动作停止点。
7. 为习惯动作写触发条件，为社会面具写本场是否接近或发生破裂；用可见行为表达，不堆砌抽象情绪词。
8. 将复杂过渡拆成清楚的可见状态，不要求模型同时执行过多细碎动作。
9. 多人反应按角色认知与关系错开，不默认同时做同一反应；每次移动都必须由接近、逃避、压迫、遮掩或关系变化触发。
10. 对 VFX 反应写清“刺激出现 → 感知延迟 → 眼睛/呼吸先变 → 身体预备或接触受力 → 恢复/残留影响”，并服从角色视线、遮挡、距离和已定时序；未知刺激不能在触发前表演结果。

使用 `assets/场戏表演卡模板.md` 输出一张场戏卡。场戏表演卡拥有稳定 ID 和独立成果版本；表演动作、节拍适配、调度来源或进入/结束状态发生变化时递增。卡片文件的任何修改都会改变指纹，必须写入下一成果版本；只改变索引状态或复核日期不升级。母档或 `DBD/DBC` 版本变化后必须复核受影响的场戏卡，继续兼容时在原成果版本上执行复核状态事务；适配内容或精确引用改变时才建立下一成果版本。它属于单次创作短卡，由任务成果索引追踪，不另建专用 CSV。

如果表演方案必须改变人物走位、距离、接触或出入画，返回 `directing-blocking`；必须改变目标、信息顺序、潜台词或原台词时返回 `dramaturgy-scene-beats`。不得在本 Skill 越权修改。

## 下游交接

- `dramaturgy-scene-beats` 和 `directing-blocking` 在场戏生产开始时读取当前有效母档的最小切片；前者不让角色行动违背稳定引擎和弧线阶段，后者把身体习惯、距离边界与地位行为纳入调度，但都不能修改母档。
- `cinematography-direction` 和 `shot-visual-design` 读取场戏表演卡以及其中列出的母档 ID/版本，只决定表演如何被看见和拍摄，不改写表演目标或节拍。
- `sound-voice-direction` 读取行动意图与停顿节点，但声音年龄感、音高、音色、口音、语速和对白声音表现仍由声音 Skill 单独建立。
- `video-prompt-production` 只提取当前生成单元真正可见的动作短切片，不复制整份母档或整场表演卡，不在 Prompt 中使用“奥斯卡级表演”等抽象标签。

母档和场戏表演卡属于创作控制数据，不进入正式资产登记表或可调用资产表。按[项目数据三层契约](../production-router-handoff/references/project-data-contract.md)检查结构；Schema 通过不替代用户对母档版本的采用确认。

## 质量门

- 每个节拍都有面向具体对象的行动目标、障碍、代价和策略变化。
- 反应从对方话语或动作尚未结束时开始，回答前存在可见判断；停顿中必须发生评估、决定或拒绝。
- 眼神持续有明确注意目标、自然微扫视和符合状态的眨眼；眼睛略先于头部到达目标，受控静止也不能变成冻结凝视。
- 所有习惯动作有触发条件；动作中断可以作为重音，但不能机械重复。
- 状态具有惯性并延续到下一节拍；只写角色当前知道的内容，不提前表演结果。
- 表演指令不含服装、摄影机、焦段、构图、色彩或灯光设计；眼神光只写为服从已定光源的生命感要求。
- 输出以可观察行为为主，不用“愤怒地”“悲伤地”“大师级”“奥斯卡级”代替动作。
