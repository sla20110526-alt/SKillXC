# 特殊生物与怪物资产生产

首次进入时说明当前生命体、工作模式、正式输入和预期交付，询问用户是否确认使用。图片模型固定为 GPT Image 2；不要重新询问图片模型。

## 职责边界

- 负责以非人解剖、轮廓、表皮和运动方式为核心身份的特殊生物、非人生命体、怪物及可复用变体。
- 负责形态定义、解剖锚点、结构/生理状态、运动能力、行为边界和以生命体为主体的持物/穿戴组合。
- 以可识别人类脸、人体和人物表演身份为核心的类人角色交 `character-asset-production`；类别不清时返回 `world-asset-production`，不得两个 Skill 同时改写同一身份。
- 道具、武器、装置和穿戴物本体先由 `prop-vehicle-production` 生产并登记；本 Skill 只负责生命体作为主体的组合成图和接触关系。
- 能量、烟尘、液体、粒子、发光、组织流动和破坏时序交 `vfx-asset-production`；本 Skill 负责转化前后可停留、可跨镜复用的实体形态。
- 只定义生命体和候选验收。把确认的设计交 `image-prompt-production` 装配完整 Prompt；生产对话不写正式登记表。

## 输入门

读取最小数据切片：

- 项目 ID、绑定卡、任务 ID/版本、生命体工作模式、需求槽位、预留正式资产 ID
- 剧本功能、来源规则、现实/超自然边界、栖息环境、智能/行为范围、出现范围和数量
- 尺度/质量依据、运动需求、环境接触、伤害/转化因果和需要保持的固定不对称特征
- 当前有效的生物怪物资产短执行卡；只读取引用的风格、美术、材质和展示灯光最小字段，不读取完整 Profile 或完整摄影规则
- 已登记父生命体和附加对象的精确 `正式资产ID@版本`
- 必须继承、允许变化、禁止变化、用户参考及逐张用途
- 动物行为、比较解剖、生物力学、医学、生态或物理顾问结论；缺少会改变生命体身份、承重、运动、安全或转化因果的事实时返回 `specialist-consultant-router`

使用 [生命体资产生产卡模板](assets/生命体资产生产卡模板.md) 固化决定。身份和运动字段读取 [生命体身份、解剖与运动约束](references/creature-identity-motion.md)。

## 八种工作模式

1. **基础形态**：建立一个可复用生命体的形态身份和单张总览卡，不混入剧情状态或 VFX。
2. **结构变体**：以基础形态或上一结构形态为父资产，建立身体拓扑、肢体/器官数量、体型或固定结构发生身份级变化的新形态。
3. **生理状态变体**：继承正确生命体版本，只改变伤口、感染、湿润、灼伤、衰弱、死亡或其他不重写身体拓扑的状态。
4. **持物穿戴组合**：以一个生命体版本为父资产、已登记道具/载具为附加资产，建立需要跨镜复用的持握、佩戴、骑乘或装置连接。
5. **运动约束定义**：只建立各运动模式的支撑、发力、节律、速度、惯性、环境接触和禁止动作，不产图、不登记。
6. **转化阶段拆分**：判断哪些前后形态需独立资产、哪些只属于单镜过渡，并输出生产顺序与 VFX 交接，不把多个阶段塞进同一正式资产。
7. **版本兼容复核**：比较父形态、附加对象、解剖锚点或运动约束换版影响，只输出 `可继续 / 需重做或新登记 / 资料不足`。
8. **登记回执绑定**：读取专用登记对话回传的正式 `ID@版本`，只更新当前生命体生产卡、解剖锚点表和运动约束表的绑定字段，不产图、不登记、不改登记表。

同一生成尝试只执行一种会产图的工作模式。运动约束和转化阶段表是任务数据，不作为图片资产登记；用户确认任务数据不等于登记图片，也不要求使用“登记这张”。

## 形态身份与解剖锚点

基础形态和每个结构变体分别建立稳定 `形态定义ID@版本`；状态变体与持物穿戴组合继承父资产的形态定义，不另造身体拓扑。使用 `assets/生命体解剖锚点表模板.csv` 和 `creature-anatomy.schema.json` 记录：

- 远景轮廓、头/躯干/承重肢、骨架关节、器官/附肢、感觉/呼吸、攻击/防御、表皮分区、固定不对称和尺度参照
- 每个锚点的身体分区、生命体自身左/右、数量、连接/生长方式、承重或功能、活动范围、静止状态和可见性
- 事实来源与锁定级别；单张参考未显示的内部结构写未知，不把推断伪装成可见事实

数量和连接是身份。眼、口、角、翼、尾、趾、关节和重复附肢不得在面板或镜头间随机增减。眼部高光必须服从已定义光源；发光器官必须有来源规则，不能用展示灯光暗中增加能力。

单体形态卡默认只展示一个个体；场戏中的同种数量不靠在资产卡复制多个个体。固定群体本身具有独立轮廓、构成和跨镜身份时先返回资产计划另建槽位；以群聚粒子、雾团或流动总体为核心时返回 `world-asset-production` 判断生物怪物或 VFX 责任。

## 单张生命体总览卡

每个可调用形态只交付一张总览卡，供 Seedance 2.0 作为单一生命体参考：

- 最大面板使用结构可读的 3/4 全身主视图；必要时加入侧/背轮廓、头面/肢体连接或表皮细节
- 所有面板保持同一形态、同一生理状态、同一固定不对称、同一附加对象和同一尺度逻辑
- 尺度参照不得遮挡生命体，也不能被误识别为附肢；面板不足以判断身份时优化占比，不堆叠大量缩略图
- 画幅服从解剖和轮廓可读性，不继承项目成片画幅；不使用广告海报、运动连拍、攻击特效或多阶段转化构图

基础/结构形态使用中性、稳定、能看清支撑和质量分布的静止姿态。状态卡和组合卡仍只交付一张与当前调用状态匹配的总览卡，不同时给视频模型上传多个互相竞争的形态参考。

## 运动与行为约束

按实际需要读取 [生命体身份、解剖与运动约束](references/creature-identity-motion.md)，为当前形态建立独立、可版本化的 `运动约束集ID@版本`，使用 `assets/生命体运动约束表模板.csv` 和 `creature-motion.schema.json`，同时绑定预留正式资产 ID 及登记后的精确生命体版本。每种站立、行走、奔跑、爬行、飞行、游动、攀附或形态切换模式单独一行，至少定义起始姿态、支撑/接触、质量分布、发力、第一动作、关节范围、节律、速度级别、转向/制动、惯性、环境接触、次级运动和禁止动作。

本 Skill 只定义物种/形态稳定的感觉、警戒、捕食、防御、群体和运动边界。重要叙事生命体的场戏目标、策略、倾听和情绪行动交 `acting-direction`；`directing-blocking` 决定空间路径和关系调度。下游必须继承运动约束，不得用“动物般”“快速扑击”“真实物理”等概括替代可执行动作。

## 结构、状态、组合与转化

结构变体只从基础形态或上一结构变体派生，并建立新的形态定义。身体拓扑、固定肢体/器官数量、承重系统或稳定轮廓变化属于结构变体；表面伤口、感染阶段、湿度、疲态、僵硬、暂时功能损伤或完整尸体状态属于生理状态。若伤害形成永久缺肢或新的稳定身体拓扑，改走结构变体。

每次产图完整输出 `PRESERVE EXACTLY / CHANGE / ONLY CHANGE`。结构变体写清新增/移除锚点、连接、质量重分配、运动后果和不受影响区域；状态变体写清部位、侧别、阶段、组织反应、功能后果和禁止扩散范围。

持物穿戴组合以前一阶段已登记生命体为父资产、道具/载具为附加资产，写清生命体锚点、对象锚点、左右/朝向、接触面、包覆、受力、遮挡、安全间隙和运动限制。对象本体错误返回对象 Skill；不得靠改变生命体肢体数量解决握持或穿戴冲突。

转化规则读取 [转化阶段与对象交互规则](references/transformation-interaction.md)。前后可停留且需跨镜复用的实体阶段各使用独立结构变体 ID；只存在于一个镜头过渡中的拉伸、组织流动、烟尘、能量和碎裂不强建静态资产，交 VFX 与正式镜头 Prompt。

## 正式资产依赖链

| 交付 | 资产类型 / 角色 | 生产依据 |
|---|---|---|
| 基础生命体总览卡 | 生物怪物 / 生物基础形态 | 父与附加依赖均不适用 |
| 结构变体总览卡 | 生物怪物 / 生物结构变体 | 父资产为基础形态或上一结构变体 `ID@版本`；附加依赖不适用 |
| 生理状态总览卡 | 生物怪物 / 生物状态变体 | 父资产为状态发生前的正确生物怪物版本；附加依赖不适用 |
| 持物穿戴组合卡 | 生物怪物 / 生物交互组合 | 父资产为正确生物怪物版本；附加资产为全部道具/载具精确版本 |

各交付使用不同预留正式资产 ID；同一 ID 的新版本只替代同一形态或同一派生交付。形态定义、解剖锚点表和运动约束集由任务索引追踪，不进入正式资产表；只改变运动规则时升级运动约束集，不自动升级图片资产。

登记回执产生正式 `ID@版本` 后，以“登记回执绑定”模式把该精确版本写回解剖锚点表、运动约束表和生产卡的绑定字段，再把它们交给分镜、表演、导演和 Prompt。登记对话只写正式资产表与可调用表，不代写这些任务数据；字段仍为“未登记”时不得进入下游。运动约束集随后升级时不改正式图片版本，但必须把引用旧约束集的任务卡、场戏卡、分镜和正式 Prompt 列入复核。

## Prompt回流、登记与复核

向 `image-prompt-production` 交付生命体生产卡、形态定义/解剖锚点切片、单张总览版式、运动静止姿态、精确父/附加版本、参考用途和三类变化清单。结果从身份、轮廓、尺度、质量分布、肢体/器官数量、连接、关节、承重、表皮、固定不对称、接触和跨面板一致性检查；形态或解剖设计错误由本 Skill 重写完整生命体生产卡，再交后者建立下一 Prompt 版本，漏译、歧义、参考映射或模型随机偏差直接返回后者处理。本 Skill 不自行维护第二份完整 Prompt，也不在旧 Prompt 末尾叠加补丁。

只有“登记这张”“确认登记”等明确指向唯一候选的措辞才输出登记申请。“不错”“继续”“这个方向”“就用这张”不触发登记；失败或待调整图不登记，失败原因只有用户明确要求才转 `generation-version-log`。

父形态或附加对象换版后，比较轮廓、尺度、解剖锚点、接触、承重、运动和状态因果。只有用户对唯一待复核版本明确确认继续使用后，才交 `approval-asset-registry` 更新当前兼容依赖；本 Skill 不写正式状态。

## 输出

- 生命体资产生产卡与当前工作模式
- 形态定义、生命体解剖锚点表和运动约束表
- 单张生命体总览卡交付定义
- 结构/状态变化、持物穿戴接口或转化阶段拆分
- GPT Image 2 Prompt 装配输入和生成后检查清单
- 用户明确登记后的登记申请与登记对话激活指令
