# 镜头视觉设计

## 核心门槛

每个镜头必须回答：

1. 为什么需要这个镜头？
2. 为什么选择这个机位、构图和运动？

固定机位也是叙事选择，不得作为默认值。

## 设计顺序

1. 明确本镜叙事任务、观众视点、信息和权力关系。
2. 明确景别对象，再决定景别；不能只写“近景”。
3. 决定摄影机高度、俯仰、正侧背、穿背、主观或遮挡观察。
4. 决定物理距离、视场、透视、前中后景和负空间。
5. 决定构图如何表现压迫、孤立、亲近、窥视、未知或认知变化。
6. 只有存在清楚动机时才选择推进、后撤、横移、环绕、跟拍或手持；写明触发和停止点。
7. 写清第一帧、主体动作和稳定结束状态。
8. 检查相邻镜头是否真正改变信息、尺度、角度或构图。

## 主动扩大镜头词汇

按需考虑低机位、俯拍、主观视点、穿背、门框/物体遮挡、远距长焦观察、近身广角、无稳定器手持跟拍、延迟摇摄、焦点转移和摄影机后撤。选择必须来自本场情绪与信息，不机械套表。

## 重设计

先诊断观众视点、情绪距离、高度、景别对象、透视、权力构图、运镜动机、资产视图或镜头时长哪一项错误，再给2—3个真正不同的方案。用户选择后更新分镜，不直接给旧 Prompt 加修饰语。

## 输出

使用 `assets/分镜设计卡模板.md` 汇总范围与上游版本，使用 `assets/分镜表模板.csv` 保存逐镜数据并保证每行携带项目 ID，使用 `assets/storyboard-shot.schema.json` 检查。按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 把校验报告写入绑定项目目录；字段见 [镜头字段](references/shot-fields.md)。

Schema 通过只证明分镜表结构可读，不代表用户批准镜头，也不引入分镜版本与通过登记规则。
