# 镜头视觉设计

## 进入前

1. 由 `production-router-handoff` 说明用途并取得用户确认。
2. 读取全片摄影规则卡和当前场戏摄影约束卡，不询问或读取完整摄影 Profile。
3. 全片摄影规则卡缺失时，返回 `cinematography-direction` 的“全片摄影基线”模式；场戏摄影约束卡缺失时，返回其“场戏摄影约束”模式。
4. 若用户要求用另一个摄影 Profile 重释本场，只能先通过 `cinematography-direction` 建立用户确认的场戏例外卡；不得在本 Skill 内临时加载或混合 Profile。
5. 读取当前场戏表演卡及其母档 ID/版本引用。重要角色缺少当前有效母档或场戏适配时返回 `acting-direction`；不得从人物外貌、台词或通用情绪词临时补写角色表演。

## 唯一写入责任

本 Skill 是分镜设计卡与分镜 CSV 的唯一写入者。`cinematography-direction` 只提供摄影规则卡和逐镜摄影审核卡，不直接改写逐镜数据。

镜头视觉设计负责决定并写入镜头存在理由、叙事任务、观众视点、景别对象、机位高低/俯仰/侧别、构图、遮挡、运镜动机、触发点和停止点。它必须在摄影卡允许范围内提出视场/透视目标、物理距离和执行参数草案，摄影指导随后只审核摄影一致性与物理可执行性。

按 [分镜、正式 Prompt 与可用镜头的版本状态规则](../production-router-handoff/references/shot-prompt-version-state.md) 建立稳定的分镜组 ID、镜头 ID、生成单元 ID 和版本。每次写表都形成明确且独立保存的分镜组快照，不覆盖旧快照；只递增实际发生设计变化的镜头版本。

## 核心门槛

每个镜头必须回答：

1. 为什么需要这个镜头？
2. 为什么选择这个机位、构图和运动？

固定机位也是叙事选择，不得作为默认值。

## 设计顺序

1. 明确本镜叙事任务、观众视点、信息和权力关系。
2. 明确景别对象，再决定景别；不能只写“近景”。
3. 决定摄影机高度、俯仰、正侧背、穿背、主观或遮挡观察。
4. 决定物理距离、视场、透视、前中后景和负空间。
5. 决定构图如何表现压迫、孤立、亲近、窥视、未知或认知变化。
6. 只有存在清楚动机时才选择推进、后撤、横移、环绕、跟拍或手持；写明触发和停止点。
7. 写清第一帧、主体动作和稳定结束状态。
8. 检查相邻镜头是否真正改变信息、尺度、角度或构图。

每个镜头另写唯一 `场景空间依据ID与版本`，引用实际用于本镜的可调用场景母图、场景状态、场景视图或光影状态精确版本。现有正式空间依据无法支持已设计机位时，不用无版本名称或 Prompt 临时补景；按 SV3 缺口返回资产计划和 `location-spatial-production`。

所有逐镜选择必须满足全片摄影规则卡与场戏摄影约束卡。规则限制了更好的叙事方案时，不私自越过规则；写明冲突并返回 `cinematography-direction` 评估场戏例外。

## 主动扩大镜头词汇

按需考虑低机位、俯拍、主观视点、穿背、门框/物体遮挡、远距长焦观察、近身广角、无稳定器手持跟拍、延迟摇摄、焦点转移和摄影机后撤。选择必须来自本场情绪与信息，不机械套表。

## 重设计

先诊断观众视点、情绪距离、高度、景别对象、透视、权力构图、运镜动机、资产视图、摄影实现或镜头时长哪一项错误，再给2—3个真正不同的方案。用户选择后更新分镜，不直接给旧 Prompt 加修饰语。

若问题只是镜头族、景深/焦点、曝光、支撑方式或运动路径的物理实现，沿用现有叙事方案并送 `cinematography-direction` 逐镜摄影审核；不要为技术问题重做叙事功能。只有用户明确要求摄影风格重释，或现有摄影规则卡无法支持已成立的叙事方案时，才请求场戏 Profile 例外。

## 剪辑与摄影审核闭环

1. 完成逐镜草案后，先交给 `editing-rhythm` 检查镜头数量、顺序、时长、切点和生成单元。
2. 由本 Skill 把不改变既定场戏目标与调度的剪辑修订写回分镜表；需要改变镜头叙事功能时，返回相应上游重新设计。
3. 将已写回剪辑修订的逐镜草案交给 `cinematography-direction` 的“逐镜摄影审核”模式。
4. 对结论为 `通过` 的镜头保持不变。
5. 对结论为 `摄影技术修正` 的镜头，只在不改变镜头叙事功能的前提下把修正写回分镜表。
6. 如果审核意见会改变镜头存在理由、观众视点、景别对象、机位意义、构图权力关系、运镜动机或人物调度，不把它当技术修正；按审核卡返回指定上游重新设计。
7. 摄影审核退回 `editing-rhythm` 调整时长或生成单元时，由本 Skill 写回剪辑修订并再次提交逐镜摄影审核。
8. 摄影审核写回完成并重新通过 Schema 检查后，才交给声音与 Prompt 生产。

## 输出

使用 `assets/分镜设计卡模板.md` 汇总范围、摄影卡引用和审核写回状态，使用 `assets/分镜表模板.csv` 保存逐镜数据并保证每行携带项目 ID，使用 `assets/storyboard-shot.schema.json` 检查。按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 把校验报告写入绑定项目目录；字段见 [镜头字段](references/shot-fields.md)。

Schema 通过只证明分镜表结构和版本字段可读，不代表用户批准镜头。系统不要求用户单独登记“分镜批准”；正式 Prompt 被放行生成时，只确认该 Prompt 引用的分镜组与镜头版本为本次生产依据。
