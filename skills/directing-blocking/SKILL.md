# 导演与人物调度

导演调度先决定观众与人物、信息和空间的关系，再让逐镜设计选择具体机位、构图与运动。人物移动必须改变行动条件、信息可见性或关系压力，不能为“画面更活”而走动。

## 唯一职责与工作模式

`directing-blocking` 是场戏调度数据集和场戏调度卡的唯一写入者，不建立表演母档，不改变剧作节拍，也不写分镜表。每张任务单只选择一种模式：

- `A｜场戏调度建立或重设计`：从当前有效输入建立新的 `DBD` 逐调度单元数据和 `DBC` 场戏调度卡；用户认为关系、走位或空间使用错误时也从此模式重做，不给旧卡叠加补丁。
- `B｜上游或空间换版兼容复核`：比较新旧剧作、表演母档、空间圣经、场景状态、生命体/VFX 或顾问结论，只返回 `继续兼容 / 需要下一版本 / 输入不足`；影响分析本身不改成果状态。

## 进入门

1. 先由 `production-router-handoff` 说明通用 Skill 的用途、输入和产物并取得用户确认。
2. 本阶段单独列出导演 Profile 候选、代表作品、成熟度和证据边界，询问是否调取。项目风格意图阶段曾选同一 Profile 不构成本次授权；未明确选择时只用通用方法。
3. 默认最多一个主 Profile。补充 Profile 必须另行确认唯一问题、作用范围和失效点。完整 Profile 只用于建立调度方法，`DBC` 交付后关闭；下游不得收到主体姓名、片名或未采用方法。
4. 以下任一必要输入缺失、待复核或版本不匹配时不开始模式 A：
   - 当前 `可交接 + 当前有效=是` 且相互匹配的 `BDT-...@v###` 与 `DSB-...@v###`；
   - 重要角色当前有效的表演母档，或任务单中明确的简单角色跳过理由；
   - 当前场景状态适用的空间圣经、局部坐标约定和锚点表；
   - 会改变调度的当前生命体运动约束、VFX 时序/接触约束或 `CCR@版本 + 主张ID／采用字段 + 结论状态`。

## 最小输入切片

- 从 `BDT/DSB` 只读取成果身份、原文保护门和导演调度切片：场戏问题、逐拍触发、信息/权力变化、进出状态、不可缺失事件、锁定顺序与因果。不得读取完整编剧／剧作 Profile、剧作 Profile 审计区或提前改变目标、潜台词、台词和事件。
- 从表演母档只读取身体习惯、重心/步态、距离与接触边界、地位行为、身体限制和当前弧线阶段；不得从人物脸、服装或外貌推断性格。
- 从空间圣经只采用当前锁定坐标、分区、入口/出口、通道、障碍、活动区和锚点关系。`推断待确认` 不能写成既有空间事实，`未知禁止补写` 必须形成缺口。
- 生命体切片只约束尺度、支撑、转向、惯性、介质、接触和禁止动作；VFX 切片只约束触发、来源、影响区、可见阶段、接触结果和残留。调度不能改写其身份或物理因果。
- 顾问结论为“暂不可裁决”时返回 `specialist-consultant-router`；现实危险内容不补成可执行伤害步骤。

## A｜场戏调度建立或重设计

### 1. 建立观众关系

按节拍先写观众跟随谁、观众相对各角色知道得更多/相同/更少、此刻必须看见什么、暂时不能看见什么。这里写叙事视点与信息权限，不写低机位、长焦、手持、推进等逐镜实现。

### 2. 把戏剧关系落到空间

1. 在空间圣经的同一局部坐标系内写人物起始/结束坐标或命名分区；没有可靠尺度时使用锚点和拓扑关系，不伪造小数精度。
2. 对每个 `节拍ID × 行动人物ID × 空间行动` 建立一个稳定 `BLK-###` 调度单元，记录相对对象的距离、朝向、视线目标、遮挡/揭示、接触和出入场。
3. 把权力写成可观察的空间变化：谁控制入口、关键锚点、距离、视线或退路；允许“权力不变”，但必须说明空间如何保持它。
4. 人物保持不动也是决定，写清其行动目的；发生移动时必须写触发、目的、路径和结束状态。没有触发的移动不得交接。
5. 画外人物仍须写在做什么、能听见什么、何时进入或离开；未知刺激不能在发生前被角色感知。

### 3. 轴线与银幕方向

为主要关系或行动建立稳定轴线 ID，说明轴线两端、默认侧、人物进入/离开方向和连续性要求。故意越轴必须同时写叙事理由与重新建立空间的方法，例如清楚的中性过渡、可读的角色/锚点重定位或连续动作建立新轴；“为了有冲击力”不是理由。

导演调度只建立空间和连续性约束。具体镜头高度、俯仰、侧别、景别、构图、摄影机距离、焦段、支撑和运镜仍由 `shot-visual-design` 在摄影规则内决定。

### 4. 不让现有参考图限制调度

先设计成立的调度，再检查现有场景资产是否能支持。缺少必要空间依据时在 `DBC` 提出 `SV3` 专项场景视图缺口，至少写：

- 缺口 ID、对应 `BLK` 单元和调度用途；
- 视图相对空间锚点的观察关系；
- 必须可见、必须遮挡和必须离画的锚点；
- 需要核实的通道、尺度或遮挡关系。

缺口返回 `asset-demand-plan` 补需求槽位与预留正式资产 ID，再由 `location-spatial-production` 生产。导演对话不直接造图，不因为手头只有正面图就把人物改为正面站定；专项视图也不预设焦段或替分镜决定镜头。

## 两项交付与依赖方向

先用 `assets/场戏调度表模板.csv` 和 `assets/directing-blocking.schema.json` 建立 `DBD-<项目代号>-<场次代号>@v###`，再用 `assets/场戏调度卡模板.md` 建立精确引用该数据集的 `DBC-<项目代号>-<场次代号>@v###`。字段语义、版本和返工规则见 `references/directing-blocking-contract.md`。

- `DBD` 是逐节拍、逐人物、逐空间行动的任务数据集；只引用剧作、表演母档、空间、顾问、生命体和 VFX 上游，不得反向引用 `DBC`。
- `DBC` 是创作短卡；保存场戏级观众关系、轴线/银幕方向、出入场/画外规则、Profile 采用审计、专项视图缺口和下游切片，并且只把当前 `DBD@版本` 作为直接成果上游。
- 两项分别以“任务数据集”和“创作短卡”进入绑定项目的 `tasks/任务成果索引.csv`。只有二者均为 `可交接 + 当前有效=是`、Profile 已关闭且无调度事实阻断时才能下传；仅缺正式 SV3 视图但空间事实已经成立时可以先交场戏表演适配，必须等专项视图登记并完成兼容复核后才能交逐镜设计。
- 项目文件建议保存到 `creative-control/directing/scenes/`；中央仓库只保存模板和规则，不建立虚构项目数据。

## Profile 关闭与下游切片

`DBC` 的 Profile 审计区记录精确 `ProfileID@版本`、用户确认依据、采用方法 ID、适用范围、转译规则、舍弃方法和关闭结论。下游只读取 `DBD` 具体调度行及 `DBC` 的成果身份、保护门和“下游执行切片”，不得读取 Profile 审计区。

交接顺序固定为：

1. `acting-direction` 模式 B 读取 `DBD@版本 + DBC@版本` 和当前表演母档，完成场戏表演适配；如果表演必须改变既定位置、距离、接触、出入场或移动触发，返回本 Skill。
2. `cinematography-direction` 场戏摄影约束核对调度卡与表演卡的 `DBD/DBC/DSB/BDT` 来源一致性，只解决摄影实现边界，不重新决定叙事视点或人物调度。
3. `shot-visual-design` 读取当前调度、表演和摄影约束，把观众关系与空间行动翻译成具体镜头；它是分镜表唯一写入者。

## 版本、复核与返工

- 首版均为 `v001`，稳定 ID 不随内容修订改变，旧成果文件只读保留。
- 人物位置/分区、距离、朝向、视线、遮挡、出入场、移动触发/路径/结束、权力空间变化、轴线/银幕方向、连续性状态、专项场景视图缺口、约束引用或适用范围变化时，先建立下一 `DBD` 版本，再建立引用它的下一 `DBC` 版本。
- 只有场戏级观众关系、Profile 审计、保护门或下游切片变化且不改变任何调度行时，只升级 `DBC`。专项视图缺口绑定 `BLK` 行，变化时仍先升级 `DBD`。任何已入索引成果文件的正文修改都必须建立下一成果版本。
- 只改变任务成果索引状态、复核日期或兼容结论，不升级成果内容版本。上游换版先用模式 B 比较；内容仍完全兼容时可在原版本上完成复核状态事务，精确引用或调度内容变化时必须建立下一版本。
- 目标/信息顺序/台词或因果要改，返回 `dramaturgy-scene-beats`；稳定身体边界要改，返回 `acting-direction` 模式 A；空间关系未知，返回 `location-spatial-production`；生命体/VFX/专业约束缺失，返回其唯一责任 Skill。

## 质量门与禁止事项

- 每个节拍都有观众信息关系；每个行动人物都有可定位起始和结束状态。
- 每次移动都有触发、行动目的、可行路径和结束状态；保持位置也有行动目的。
- 距离、朝向、视线、遮挡、出入场和权力变化能够互相解释，不是相互独立的标签堆积。
- 轴线、银幕方向、故意越轴理由和重建空间方法可执行；专项视图缺口不冒充已登记资产。
- 不建立表演母档，不改剧作，不设计具体焦段，不写分镜表，不决定剪辑切点，不写正式 Prompt，不直接登记或生成图片。
- Schema 通过只证明字段、ID 和业务门可检查，不代表导演调度的创作质量已通过；真实质量留待 V01 用用户场景验证。
