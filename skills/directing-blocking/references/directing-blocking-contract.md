## 1. 成果身份与依赖方向

- `DBD-<项目代号>-<场次代号>@v###` 是多行权威调度数据集；每行使用场内稳定 `BLK-###` 调度单元 ID。
- `DBC-<项目代号>-<场次代号>@v###` 是场戏调度卡；它精确引用一个当前 `DBD@版本`，保存场戏级控制和下游切片。
- `DBD` 的上游只能是当前剧作成果、表演母档、空间圣经/锚点、顾问结论、生命体运动和 VFX 时序/接触约束。`DBD` 不引用 `DBC`；`DBC` 以 `DBD` 为唯一直接成果上游，形成单向链。
- 二者分别进入任务成果索引。任务版本、`DBD` 版本和 `DBC` 版本互不代替。

## 2. 调度单元边界

一个调度单元对应“一个节拍中，一个行动人物的一次空间行动或有目的的保持”。以下任一发生时另建后续单元：

- 人物开始或结束一段有新触发的移动；
- 目标对象、路径、接触结果、出入场或画外状态改变；
- 主要轴线或银幕方向要求改变；
- 遮挡/揭示导致观众知情关系改变。

同一段连续移动不因经过每个锚点拆成多个单元；锚点按路径顺序写在同一行。多人同时行动时每个行动人物各有一行，靠同一节拍 ID、相邻序号与接触结果互相对齐。

同一空间行动在后续 DBD 版本中保持原 `BLK` ID；新增行动取得未使用的新 ID，删除的 ID 只在历史版本保留且不得回收给另一行动。`调度序号` 表示当前版本顺序，可以变化，但不能拿顺序号代替稳定身份。

## 3. 观众视点与逐镜实现边界

导演调度记录：观众跟随谁、比谁知道得多/少、必须看见和暂不可见的信息、遮挡何时解除、人物在空间中的权力关系。它可以要求“观众暂被排除在门外的知识位置”或“先让威胁来源保持画外”，但不写实现这些要求的低/高机位、主观镜头、穿背、焦段、手持或推进。

`shot-visual-design` 才把这些要求转成具体机位、景别对象、构图、遮挡观察与运镜。摄影规则限制实现时，由摄影 Skill 提出技术边界；不能反向删除已经成立的观众信息关系。

## 4. 坐标、距离、朝向和视线

- 坐标继承空间圣经固定原点和方向，不随参考图左右翻转。可靠尺度不足时写“门内活动区”“桌北侧一臂内”等拓扑关系。
- 距离必须写相对对象或锚点；“近”“远”不能脱离对象。
- 朝向写身体/肩胯主要方向，视线另写注意目标；人物可以背对对方但看向反射或出口，两者不能合并成一个模糊“面向”。
- 遮挡写遮挡物、被遮对象、观众暂时不知道什么、解除触发和解除后的信息后果。

## 5. 移动、静止与权力变化

每次移动都要形成：`触发 → 行动目的 → 可行路径 → 结束状态`。合法触发来自争取、逃避、威胁、试探、遮挡、揭示、接触、程序要求或关系改变；“避免固定机位”“让画面丰富”不是人物移动触发。

保持位置时，`移动触发` 写“不适用：保持位置”，`空间行动与路径` 写“保持位置”，`行动目的` 仍须说明人物如何以不动来拒绝、等待、控制入口、维持距离或迫使他人行动。

权力空间变化可以为“不变”，但要说明谁仍控制关键锚点、距离、退路或视线；不能只写抽象的“更强势”。

## 6. 轴线、银幕方向与越轴

轴线 ID 固定到关系或行动，例如两人视线轴、走廊运动轴、桌面接触轴。每条轴线写两端和默认侧，并说明人物进出方向、运动方向和相邻连续性。

故意越轴必须同时满足：

1. 有明确叙事理由，例如关系倒置、认知断裂或空间失序；
2. 观众能在越轴前后重新确认角色或锚点；
3. 写明重建方法，例如中性过渡、连续动作经过轴线、可读锚点重定位或明确的新轴建立。

没有上述三项时保持原轴，不用“更有冲击力”掩盖连续性错误。

## 7. 专项场景视图缺口

`SV3` 是需求缺口，不是图片资产，也不是已经成立的机位。它必须绑定调度单元、调度用途、相对锚点观察关系、必须可见/遮挡/离画锚点和待核实空间关系。缺口先交资产计划建立需求槽位与预留 ID，再由场景 Skill 生产并经明确登记后成为正式空间依据。

已有场景图不能支持调度时，优先补视图而不是无理由改变人物位置；若空间圣经本身没有足够事实，先补空间事实，不从新图 Prompt 偷写未知门窗或通道。

空间事实、通道或尺度尚未成立时属于“调度事实阻断”，DBD/DBC 不得下传。空间事实已经成立、只缺供后续镜头调用的正式专项视图时标为“仅专项视图生产缺口”：可以先交场戏表演适配，但不能交逐镜设计。专项视图登记后先做兼容复核；缺口字段或精确空间依据改变时建立下一 DBD/DBC 版本。

## 8. Profile与下游隔离

导演 Profile 在本阶段重新取得用户确认。完整卡只用于选择调度方法；`DBC` 的审计区保存确认和方法映射，交付时关闭。下游只拿转译后的观众关系、空间行动、轴线、揭示和禁区，不拿 Profile 身份、作品名或未采用方法。

Profile 改变了实际调度行时升级 `DBD` 和 `DBC`；只补充审计而不改变任何项目决定时只升级 `DBC`。中央 Profile 版本变化不自动改项目成果。

## 9. 版本与兼容复核

- `DBD` 内容字段（包括专项场景视图缺口）、适用范围或任何精确上游引用改变，建立下一数据集版本。
- `DBC` 的数据集引用、场戏级观众关系、轴线总则、专项视图缺口、Profile审计、保护门或下游切片改变，建立下一卡片版本。
- `DBD` 升级后，引用它的 `DBC` 必须建立下一版本；`DBC` 可以在 `DBD` 不变时独立升级。
- 只改任务成果索引状态、当前有效、复核日期或状态依据，不升级成果文件版本。
- 模式 B 的结果只有：内容与精确引用均仍兼容时“继续兼容”；需要改变内容或引用时“需要下一版本”；差异无法判断时“输入不足”。

## 10. 返工路由

| 冲突 | 返回节点 |
|---|---|
| 台词、目标、信息顺序、因果或节拍边界需改 | `dramaturgy-scene-beats` |
| 角色稳定身体习惯、距离/接触边界或弧线阶段需改 | `acting-direction` 模式 A |
| 本场表演动作必须改变既定调度 | `directing-blocking` 模式 A 建下一版本 |
| 空间事实、锚点、通道或专项视图不足 | `asset-demand-plan` → `location-spatial-production` |
| 生命体动作超出运动约束 | `creature-monster-production` |
| VFX触发、来源、影响区或接触结果缺失 | `vfx-asset-production` |
| 专业结论暂不可裁决 | `specialist-consultant-router` |
| 具体机位、景别、构图或运镜不成立 | `shot-visual-design` |
| 焦段、摄影机距离、支撑或运动物理实现冲突 | `cinematography-direction` |

本合同可检查结构与责任边界，不能自动判断某种调度是否最有戏剧力量。
