# 资产审批与登记

## 唯一触发条件

只有用户对可唯一识别的结果发出明确登记命令才执行，例如：

- “登记这张”
- “确认登记这张为角色A基础卡”
- “把第三张登记为 SCN-002 母图”

“不错”“就这个方向”“这张先留着”“可以继续”“就用这张”均不得自动触发；如语义不确定，保持候选状态并询问，不推定授权。

## 禁止登记

- 用户判定失败的图片或声音
- 尚待修改的候选
- 无法唯一定位的结果
- 缺少父资产、用途或版本关系的结果
- 与已登记资产冲突但未说明替换/并存关系的结果

## 执行

1. 复述待登记文件、需求槽位、资产类型、用途和父版本。
2. 核对文件存在、身份唯一、必填字段齐全。
3. 分配或递增正式版本，例如 `CHR-001@v002`；稳定槽位 ID 不变。
4. 写入正式资产登记表。
5. 同一操作中写入可调用资产表；记录平台引用名和可调用范围。
6. 若替代旧版本，把旧版本标为停用/历史，不删除历史记录。
7. 输出登记回执和受影响范围。

## 数据契约

使用 `assets/正式资产登记表模板.csv`、`assets/可调用资产表模板.csv`，并通过 `assets/formal-asset.schema.json` 检查结构。

失败原因只在用户明确要求调用 `generation-version-log` 时记录。本 Skill 不维护失败档案。
