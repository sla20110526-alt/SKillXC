# 资产审批与登记

## 项目绑定门

每次登记前必须读取当前项目的 `项目数据绑定卡.md`，核对：

- 项目 ID 唯一，并与项目名称一致对应；
- 项目数据根目录已经由用户确认；
- 正式资产登记表、可调用资产表和资产文件根目录都位于该项目数据根目录内；
- 当前任务单、登记申请和两张表的项目 ID 完全一致。

项目内资产身份的唯一键是 `项目ID + 正式资产ID`；不同项目可以各自使用 `CHR-001`，但记录绝不能跨项目引用或迁移。

不得从当前工作目录猜测项目，不得把项目数据根目录指向 SKillXC 中央仓库、Skill 安装/持久化目录或它们的子目录，也不得读取另一个项目的登记表补全当前项目。路径校验细则见 [项目数据绑定规则](references/project-data-binding.md)。

若没有绑定卡，提醒用户指定或确认项目数据根目录，使用 `assets/项目数据绑定卡模板.md` 生成待确认卡。获得确认后才能初始化该项目的两张登记表。若用户尚未指定具体项目，只说明所需信息，不创建虚构项目目录或数据。

绑定确认后，同时初始化或更新 `项目数据绑定索引.csv`，每个绑定卡版本一行；使用 `assets/project-data-binding.schema.json` 检查。若上游已有用户确认的项目锁定卡，原样保存到绑定目录并建立 `项目锁定索引.csv`，不得改写锁定内容；若没有则只初始化绑定数据，不虚构锁定卡。项目锁定、事实索引、计划、任务、登记、就绪、分镜和按需记录各自保存在绑定项目目录，不写入中央 Skill 仓库。

若已有绑定卡和登记表，先校验并继续使用，禁止用空模板覆盖。用户明确说“确认绑定这个项目目录”等措辞只授权建立目录关联和空表，不构成任何资产登记授权。

## 对话职责

- 生产对话：即使收到明确登记命令，也只使用 `assets/登记申请模板.md` 输出登记申请，并附上 `assets/登记对话激活指令模板.md`；不写正式资产登记表和可调用资产表，输出后即可继续生产。
- 专用登记对话：只处理项目绑定、登记申请核验、正式写表和登记回执；不生产资产、不修改 Prompt、不评价候选质量。
- 新对话必须从绑定卡取得项目目录，不沿用上一次对话的项目路径记忆。

## 正式资产登记的唯一触发条件

只有用户对可唯一识别的结果发出明确登记命令才执行，例如：

- “登记这张”（此前已经明确过正式资产名称）
- “确认登记这张为角色A基础卡”
- “把第三张登记为‘旧宅客厅’母图，沿用 SCN-002”
- “登记这段声音”（此前已明确唯一音频、正式名称和预留声音资产 ID）
- “确认登记这段参考音为‘角色A基础声音’”

“不错”“就这个方向”“这张先留着”“可以继续”“就用这张”均不得自动触发；如语义不确定，保持候选状态并询问，不推定授权。

## 禁止登记

- 用户判定失败的图片或声音
- 尚未形成独立、可唯一定位音频文件的 Seedance 镜头内声音
- 尚待修改的候选
- 无法唯一定位的结果
- 缺少父资产、用途或版本关系的结果
- 与已登记资产冲突但未说明替换/并存关系的结果
- 缺少项目数据绑定卡，或登记申请与绑定卡项目 ID 不一致的结果
- 缺少资产拆解阶段预留的正式资产 ID，或登记申请挪用了其他项目预留记录的结果
- 用户尚未明确给出正式资产名称的结果

## 执行

1. 复述项目 ID、待登记文件、需求槽位、预留正式资产 ID、用户给出的正式资产名称、资产类型、用途和父版本。
2. 核对绑定卡、文件、身份、预留 ID、正式名称和必填字段；正式名称以用户当前或此前明确指定的名称为准，不自行命名。对声音资产另核对：`声音类别=角色声音参考音频`、关联说话者、声音身份卡版本或简单说话者跳过理由、来源/授权、污染与可调用限制，以及当前平台真实调用方式。身份卡生效、镜头可用或“这个声音可以”均不能替代音频登记指令。
3. 沿用资产拆解阶段预留的正式资产 ID，不在登记阶段重新编号；为它分配或递增版本，例如 `CHR-001@v002`。
4. 在临时副本中分别加入正式登记行和可调用映射行；每行都写项目 ID、绑定卡版本和必要版本关系。
5. 使用 `formal-asset.schema.json` 与 `callable-asset.schema.json` 检查两份临时完整表；任一未通过都不改正式文件。
6. 两份临时表都通过后，先保留两张原表的可恢复副本，再替换绑定卡指定的两张表；任一步写入异常时回滚两张原表并报告失败，不留下单表已更新状态。
7. 若替代旧版本，把同项目、同正式资产 ID 的旧版本标为停用或历史，不删除历史记录，不影响其他项目。
8. 对写入后的两张表再次检查，并使用 `assets/登记回执模板.md` 输出登记回执、绑定卡版本、两张表与校验报告路径和受影响范围；任一表未通过就不得回执“已登记并可调用”。

生产对话只能输出登记申请，不直接维护两张正式表。登记申请必须携带项目 ID、绑定卡路径和版本、唯一候选、预留正式资产 ID、用户登记指令原文和用户指定名称；登记对话重新核对后执行。

## 数据契约

使用 `assets/项目数据绑定卡模板.md`、`assets/项目数据绑定索引模板.csv`、`assets/登记申请模板.md`、`assets/登记对话激活指令模板.md`、`assets/正式资产登记表模板.csv`、`assets/可调用资产表模板.csv` 和 `assets/登记回执模板.md`。分别通过 `project-data-binding.schema.json`、`formal-asset.schema.json` 与 `callable-asset.schema.json` 检查；通用规则见 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md)。

失败原因只在用户明确要求调用 `generation-version-log` 时记录。本 Skill 不维护失败档案。
