# 资产审批与登记

遵守 [轻量生产与严格记录合同](../production-router-handoff/references/interaction-modes.md)。生产对话只显示候选结论和是否明确登记的决定点；正式绑定、登记、状态传播和待复核解除均属于严格记录，由专用登记对话执行。

## 项目绑定门

每次登记前必须读取当前项目的 `项目数据绑定卡.md`，核对：

- 项目 ID 唯一，并与项目名称一致对应；
- 项目数据根目录已经由用户确认；
- 正式资产登记表、可调用资产表、资产状态传播表和资产文件根目录都位于该项目数据根目录内；
- 当前任务单、登记申请和三张表的项目 ID 完全一致。

项目内资产身份的唯一键是 `项目ID + 正式资产ID`；不同项目可以各自使用 `CHR-001`，但记录绝不能跨项目引用或迁移。

不得从当前工作目录猜测项目，不得把项目数据根目录指向 SKillXC 中央仓库、Skill 安装/持久化目录或它们的子目录，也不得读取另一个项目的登记表补全当前项目。路径校验细则见 [项目数据绑定规则](references/project-data-binding.md)。

若没有绑定卡，提醒用户指定或确认项目数据根目录，使用 `assets/项目数据绑定卡模板.md` 生成待确认卡；生产对话再附 `assets/项目绑定对话激活指令模板.md`，由严格记录对话完成绑定。获得确认后才能初始化该项目的任务索引、任务成果索引、正式资产登记表、可调用资产表和资产状态传播表。若用户尚未指定具体项目，只说明所需信息，不创建虚构项目目录或数据。

绑定确认后，同时初始化或更新 `项目数据绑定索引.csv`，每个绑定卡版本一行；使用 `assets/project-data-binding.schema.json` 检查。任务调度与任务产物必须分别初始化为 `tasks/任务索引.csv` 和 `tasks/任务成果索引.csv`，使用 `production-router-handoff` 的模板和 Schema，不得继续写入 `control/任务索引.csv`。若上游已有用户确认的项目锁定卡，原样保存到绑定目录并建立 `项目锁定索引.csv`，不得改写锁定内容；若没有则只初始化绑定数据，不虚构锁定卡。项目锁定、事实索引、计划、任务、登记、就绪、分镜和按需记录各自保存在绑定项目目录，不写入中央 Skill 仓库。

若已有绑定卡和登记表，先校验并继续使用，禁止用空模板覆盖。用户明确说“确认绑定这个项目目录”等措辞只授权建立目录关联和空表，不构成任何资产登记授权。

## 对话职责

- 生产对话：即使收到明确登记命令，也只使用 `assets/登记申请模板.md` 输出登记申请，并附上 `assets/登记对话激活指令模板.md`；不写正式登记、可调用或传播表，输出后即可继续生产。
- 专用登记对话：只处理项目绑定、登记申请核验、正式写表、状态传播、用户明确的待复核解除和登记回执；不生产资产、不修改 Prompt、不替用户判断派生资产兼容。
- 新对话必须从绑定卡取得项目目录，不沿用上一次对话的项目路径记忆。

## 正式资产登记的唯一触发条件

只有用户对可唯一识别的结果发出明确登记命令才执行，例如：

- “登记这张”（此前已经明确过正式资产名称）
- “确认登记这张为角色A基础卡”
- “把第三张登记为‘旧宅客厅’母图，沿用 SCN-002”
- “登记这段声音”（此前已明确唯一音频、正式名称和预留声音资产 ID）
- “确认登记这段参考音为‘角色A基础声音’”

“不错”“就这个方向”“这张先留着”“可以继续”“就用这张”均不得自动触发；如语义不确定，保持候选状态并询问，不推定授权。

## 禁止登记

- 用户判定失败的图片或声音
- 尚未形成独立、可唯一定位音频文件的 Seedance 镜头内声音
- 尚待修改的候选
- 无法唯一定位的结果
- 缺少父资产、用途或版本关系的结果
- 与已登记资产冲突但未说明替换/并存关系的结果
- 派生资产只写父正式资产 ID、未精确到生产依据版本的结果
- 缺少项目数据绑定卡，或登记申请与绑定卡项目 ID 不一致的结果
- 缺少资产拆解阶段预留的正式资产 ID，或登记申请挪用了其他项目预留记录的结果
- 用户尚未明确给出正式资产名称的结果

## 执行

1. 复述项目 ID、待登记文件、需求槽位、预留正式资产 ID、用户给出的正式资产名称、资产类型、用途和父版本。
2. 核对绑定卡、文件、身份、预留 ID、正式名称、资产角色、生产图片 Prompt、生产依据父版本/附加版本和必填字段；正式名称以用户当前或此前明确指定的名称为准，不自行命名。经 `image-prompt-production` 生成的图片必须填写精确 `图片PromptID@版本`；用户提供或外部既有且未经过本系统图片 Prompt 的资产写明“不适用（来源）”。该字段只追溯候选，不进入依赖传播。普通基础/独立资产及人物脸母图的依赖字段写“不适用”；人物五视图基础卡必须使用不同正式资产 ID，并把唯一脸母图 `ID@版本` 写入父资产字段。场景母图不带父资产；场景状态变体必须依赖一个已登记场景母图或上一场景状态，场景视图必须依赖一个已登记场景母图或场景状态版本，光影状态必须依赖一个已登记场景母图、场景视图或场景状态版本。基础道具/载具与图案文字母版不带依赖；对象状态、表面应用和装配必须分别携带正确的同类型父对象、图案母版附加版本或装配件附加版本。图案文字母版及含可见文字的表面应用还必须有生产 Skill 输出的逐字/图形校对通过结论；没有通过结论时不登记。生物基础形态不带依赖；生物结构、生理状态和交互组合必须分别携带正确的生命体父版本，交互组合还必须携带全部已登记道具/载具附加版本。VFX视觉母版不带父资产，固定来源可列附加版本；VFX状态和接触参考必须分别携带正确VFX父版本，接触参考还必须携带画面实际使用的全部已登记来源/触发和接触实体附加版本。其他派生资产也必须使用精确 `正式资产ID@版本`，多个附加依赖以中文分号分隔。对声音资产另核对：`声音类别=角色声音参考音频`、关联说话者、声音身份卡版本或简单说话者跳过理由、来源/授权、污染与可调用限制，以及当前平台真实调用方式。身份卡生效、镜头可用或“这个声音可以”均不能替代音频登记指令。
3. 沿用资产拆解阶段预留的正式资产 ID，不在登记阶段重新编号；为它分配或递增版本，例如 `CHR-001@v002`。
4. 在临时副本中加入正式登记行和可调用映射行；生产依据字段永久保留原始生成依赖，当前兼容依赖初始等于本次生产依据。每行都写项目 ID、绑定卡版本、状态依据和状态更新时间。
5. 若同项目、同正式资产 ID 已有当前可调用版本，执行 [资产状态传播规则](references/asset-state-propagation.md)：旧版本转历史；按“当前兼容依赖”遍历直接及传递派生资产，把受影响版本在正式表与可调用表都标为 `待复核`；为新版本、旧版本和每个受影响派生版本写传播事件行。没有依赖者也必须写新旧版本事件，证明已完成传播扫描。
6. 使用 `formal-asset.schema.json`、`callable-asset.schema.json` 与 `asset-state-propagation.schema.json` 检查三份临时完整表；再执行跨表检查，确认同一 `项目ID + 正式资产ID + 版本` 在正式表与可调用表的状态、依赖和状态依据一致，传播表覆盖全部状态变化。任一未通过都不改正式文件。实际检查、登记和兼容确认必须调用 `scripts/update_asset_registry.py`，不得靠手工分别改三张表。
7. 三份临时表都通过后，先保留三张原表的可恢复副本，再替换绑定卡指定的三张表；任一步异常时回滚全部正式文件，不留下部分更新。第一次为旧项目增加传播表时，也先完成模板升级和完整检查，禁止在旧表头上直接追加新格式行。
8. 写入后再次检查三表和跨表关系，使用 `assets/登记回执模板.md` 输出被替代版本、自动待复核派生资产和返回节点；只有本次新登记版本可回执“已登记并可调用”，不得把待复核派生资产同时写成可调用。

生产对话只能输出登记申请，不直接维护正式数据表。登记申请必须携带项目 ID、绑定卡路径和版本、唯一候选、预留正式资产 ID、资产角色、生产图片 Prompt ID/版本或明确不适用来源、精确生产依据、用户登记指令原文和用户指定名称；登记对话重新核对后执行。

## 待复核解除

资产被自动标为 `待复核` 后，不自动要求重做，也不自动恢复：

1. 先由责任生产 Skill 或 `continuity-readiness-audit` 比较新父版本与该派生资产的必须继承项，给出 `可继续／需重做或新登记／资料不足`，但这不是状态授权。
2. 只有用户对唯一待复核版本明确说“确认这个版本继续可用”“确认不重做，沿用这版”等等，专用登记对话才能处理；普通“可以”“继续”不得解除。
3. 确认继续时，不修改生产依据字段；把当前兼容依赖中的旧父版本替换为用户确认的新版本。传递链末端若直接依赖版本没有换号，只复核这条相同版本依赖，不把根触发资产硬写进兼容字段。全部依赖均可调用时，正式表与可调用表同时恢复 `可调用`；否则继续保持 `待复核`。两种结果都写 `确认继续可用` 传播事件、关闭所处理的旧待复核事件并保存用户原文。
4. 用户决定重做时保持旧版本 `待复核` 或改为历史；新候选仍需新的明确登记指令，不能用“重做”授权登记。
5. 任何仍依赖其他待复核版本的资产不得解除；只有完整依赖链已可调用才能恢复。

## 数据事务脚本

先从绑定卡取得项目数据根目录和三张表的相对路径，再使用操作模板生成一次性 JSON。执行：

```text
python scripts/update_asset_registry.py check --project-root <项目数据根目录> --project-id <项目ID>
python scripts/update_asset_registry.py register --project-root <项目数据根目录> --payload <正式资产登记操作.json>
python scripts/update_asset_registry.py confirm-compatible --project-root <项目数据根目录> --payload <待复核兼容确认操作.json>
```

非默认表路径必须同时传入 `--formal-table`、`--callable-table` 和 `--propagation-table`；相对路径均相对于已绑定项目数据根目录。操作模板只在专用登记对话中使用，生产对话不得运行脚本。

## 数据契约

使用 `assets/项目数据绑定卡模板.md`、`assets/项目数据绑定索引模板.csv`、`assets/项目绑定对话激活指令模板.md`、`assets/登记申请模板.md`、`assets/登记对话激活指令模板.md`、`assets/正式资产登记表模板.csv`、`assets/可调用资产表模板.csv`、`assets/资产状态传播表模板.csv`、`assets/正式资产登记操作模板.json`、`assets/待复核兼容确认操作模板.json` 和 `assets/登记回执模板.md`。项目任务两表另使用 `production-router-handoff/assets/任务索引模板.csv`、`任务成果索引模板.csv`、对应两个 Schema 和任务成果事务脚本。绑定、资产和任务数据分别通过各自 Schema 与业务事务检查；通用规则见 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md)。

失败原因只在用户明确要求调用 `generation-version-log` 时记录。本 Skill 不维护失败档案。
