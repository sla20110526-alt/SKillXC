# 项目数据绑定规则

## 最小目录

```text
<用户确认的项目数据根目录>/
├─ 项目数据绑定卡.md
├─ 项目锁定卡.md
├─ control/
│  ├─ 项目数据绑定索引.csv
│  └─ 项目锁定索引.csv
├─ tasks/
│  ├─ 任务索引.csv                 # 任务调度源
│  ├─ 任务成果索引.csv             # 任务产物源；任务与成果一对多
│  └─ backups/                     # 任务成果索引事务按需建立
├─ registry/
│  ├─ 正式资产登记表.csv
│  ├─ 可调用资产表.csv
│  └─ 资产状态传播表.csv
├─ validation/
│  └─ 数据校验报告.md
├─ creative-control/                # 对应创作控制 Skill 首次执行时按需建立
│  ├─ 项目创作基线索引.csv          # 首次风格/美术/摄影/灯光长期基线任务时建立
│  ├─ baselines/
│  │  └─ <控制卡ID>@<版本>.md
│  ├─ acting/
│     ├─ 角色表演母档表.csv
│     ├─ masters/
│     │  └─ <表演母档ID>@<版本>.md
│  │  └─ scenes/
│  │     └─ <场戏表演卡ID>@<版本>.md
│  └─ sound/                        # 首次声音身份任务时建立
│     ├─ 角色声音身份表.csv
│     └─ identities/
│        └─ <声音身份卡ID>@<版本>.md
├─ records/                         # 首次获得对应记录授权时按需建立
│  ├─ 镜头生产进度表.csv
│  └─ 生成版本记录.csv              # 仅用户要求详细记录时建立
└─ assets/
```

其他事实索引、创作控制卡、计划、交接包和生成记录由对应 Skill 在真实项目中按需增加；项目创作基线、表演和声音索引分别只在首次对应任务且用户已确认使用时创建，`records/` 及其中表格只在用户首次明确授权相应记录时建立，项目绑定阶段不预建虚构数据。

## 绑定检查

1. 要求用户提供或确认项目 ID、项目名称和项目数据根目录。
2. 把根目录解析为绝对路径；不得依赖对话启动目录或相对当前目录猜测。
3. 拒绝将根目录设为 SKillXC 中央仓库、用户级 Skill/插件持久化目录或它们的子目录。
4. 解析绑定卡中的所有相对路径，确认结果仍在项目数据根目录内，禁止 `..` 逃逸。
5. 若同一项目 ID 已有绑定卡，核对路径和版本；变更时建立下一版本并保留旧卡，不静默改写。
6. 若目标表已经存在，先使用对应 Schema 校验表头和项目 ID，不用模板覆盖。
7. 只有用户明确确认绑定后，才将绑定状态写为 `已绑定`，在项目数据绑定索引中追加当前版本，并初始化任务索引、任务成果索引、正式资产登记表、可调用资产表和资产状态传播表五张空表。顺序固定为：先从 `production-router-handoff/assets/任务索引模板.csv` 建立空任务索引，再执行其 `update_task_artifact_index.py init` 建立空成果索引；目标已存在时只检查，不覆盖。
8. 所有项目 CSV 都按三层数据契约检查，报告写入本项目 `validation/`；中央仓库不保存项目检查报告。

## 跨对话交接

每份任务单或登记申请只传递项目 ID、绑定卡绝对路径与绑定卡版本。接收对话必须重新读取绑定卡；项目不一致时暂停，不尝试自动修复或合并。
