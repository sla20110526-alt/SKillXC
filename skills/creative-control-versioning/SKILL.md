# 创作控制版本管理

## 三类版本不得混用

1. `中央源定义版本`：SKillXC 中专业方法、必填结构或交接规则的版本。只有维护中央原始文件时升级；具体项目不得修改或升级。
2. `Profile卡片版本`：由 `film-profile-library` 管理。项目只引用 `ProfileID@版本`，调用、选择或生成项目短卡不升级原 Profile。
3. `项目控制卡版本`：绑定项目内的可执行决定。每个稳定控制卡 ID 从 `v001` 开始；只在项目决定实质变化时升级。

完整边界和例子见 [版本模型](references/version-model.md)。中央源当前版本只从 [源定义目录](references/control-source-catalog.json) 读取，不凭记忆推断。

## 纳入范围

项目级长期基线统一写入 `creative-control/项目创作基线索引.csv`：

- 项目风格锁定基线
- 美术LookDev基线
- 全片摄影规则
- 项目灯光基线

探索期可以往返试验，正式依赖固定为：项目风格锁定基线 → 美术LookDev基线 → 全片摄影规则 → 项目灯光基线。每张下游只引用前一张直接上游，祖先约束沿链传递；顾问任务成果使用独立字段，不能冒充长期基线。首次建立或上游升级时，可以先把同一新依赖链全部作为待确认草案入表，再一次确认整链生效；任何生效卡都必须精确引用对应的当前生效上游版本。上游不得反向引用下游，系统也不得只切换或停用上游而留下引用旧版/失效版的下游生效卡。最终风格锁定包作为任务成果组合当前四张有效卡，不另造一张循环依赖的“总卡”。

旧中央源版本及其当时依赖形状保持可验证，不原地改写历史项目卡；但建立新的 P0 评审或批量组合快照前，四卡必须先迁移为当前中央源支持的唯一直接上游链。

角色表演母档继续写 `creative-control/acting/角色表演母档表.csv`，声音身份卡继续写 `creative-control/sound/角色声音身份表.csv`；它们使用同一版本与生效规则，但详细表分别是权威源。

场戏节拍、导演调度、场戏表演、场戏摄影约束、逐镜摄影审核、剪辑节奏和场戏声音属于任务短卡，由任务成果索引追踪稳定 ID 与独立版本，不进入长期基线索引。项目锁定、资产、分镜和生成结果使用各自专用版本系统；图片/视频 Prompt 作为任务成果进入任务成果索引。

## 职责分离

- 专业 Skill 负责控制卡内容，只交付 `待确认 + 当前有效=否` 的新版本草案。
- 本 Skill 负责项目创作基线索引的版本分配、状态事务和检查，不替专业 Skill 改写创作决定。
- `acting-direction` 与 `sound-voice-direction` 仍是各自详细内容的唯一生产者；其专用控制对话调用本 Skill 的事务脚本维护版本状态。
- 普通生产对话不写任何长期控制索引，只输出版本操作申请和专用控制对话激活指令。

## 项目版本何时升级

以下任一项目级决定实质变化时建立下一版本：适用范围、稳定创作规则、Profile采用方法、必须继承、允许变化、禁止项、关键输入控制卡引用或与下游有关的例外。

以下情况不升级：首次从中央源创建项目实例以外的重复加载；重新打开对话；复制同一内容；只改错字、排版、路径或引用格式；中央源或 Profile 升级但项目尚未选择采用；上游版本变化但复核后项目内容与精确输入引用都不变。

若上游控制卡版本变化，即使正文结论相同，只要本卡的精确输入引用必须改为新版本，就视为可追溯内容变化并升级。中央源升级后，用户明确选择重新采用且项目决定或源定义引用发生变化，也建立项目新版本；既有项目版本不原地改引用。

## 状态门

- 新草案：`待确认 + 当前有效=否`，不影响当前生效版。
- 用户明确确认唯一版本或可唯一识别的一组版本后：新版 `已生效 + 是`，同 ID 旧生效版 `已替代 + 否`。涉及长期基线上游变化时，必须一次确认完整受影响新依赖链，禁止留下引用非当前上游的生效卡。
- 用户明确停用：`已失效 + 否`；不自动回退旧版。需要恢复旧内容时，以当前源引用建立新项目版本。
- 同一项目、同一稳定控制卡 ID 最多一版 `已生效 + 当前有效=是`。
- 用户确认项目卡生效不是资产登记，不要求“登记这张”；普通“继续”“可以”不能在对象不唯一时推定确认。

生效或替代只改变索引状态，不覆盖带版本号的卡片文件。旧文件永久保留并只读引用。

## 执行

1. 读取项目数据绑定卡，确认所有路径位于绑定项目根目录。
2. 读取中央源目录，核对 `源定义ID@版本`；使用 Profile 时再核对 `ProfileID@卡片版本`。
3. 由责任专业 Skill 生成带稳定 ID、下一项目版本和完整来源引用的独立卡片草案。
   事务脚本从卡片的语义内容计算 SHA-256 指纹；版本、状态、日期和路径等管理字段不进入指纹。与该稳定 ID 最新版本语义指纹相同的草案不得建立新版本。
4. 普通生产对话使用 `assets/创作控制版本操作申请模板.md` 输出申请，转专用控制对话。
5. 对应索引尚不存在时，在用户已确认当前专业/控制任务后使用 `init` 只初始化这一张空索引；不在项目绑定阶段预建所有控制目录。随后使用 `draft` 把草案加入临时完整索引，结构和跨行检查通过后原子替换。
6. 用户明确确认后使用 `activate`；明确停用时使用 `invalidate`。事务先备份、写临时表、复检，失败恢复原表。
7. 用 `check` 检查项目创作基线、表演母档和声音身份三张索引；下游只读取当前已生效版本。

## 数据事务

项目创作基线：

```text
python scripts/update_control_index.py init --kind baseline --project-root <项目根目录> --project-id <项目ID>
python scripts/update_control_index.py check --kind baseline --project-root <项目根目录> --project-id <项目ID>
python scripts/update_control_index.py draft --kind baseline --project-root <项目根目录> --payload <操作JSON>
python scripts/update_control_index.py activate --kind baseline --project-root <项目根目录> --payload <操作JSON>
python scripts/update_control_index.py invalidate --kind baseline --project-root <项目根目录> --payload <操作JSON>
```

表演母档或声音身份分别把 `--kind` 改为 `acting` 或 `voice`；非默认索引路径使用 `--index`。载荷字段见 [操作载荷](references/operation-payloads.md)。

## 数据契约

使用 `assets/项目创作基线索引模板.csv`、`assets/creative-control-baseline.schema.json`、`assets/创作控制版本操作卡模板.md`、`assets/创作控制版本操作申请模板.md` 和 `assets/创作控制对话激活指令模板.md`。项目详细卡由责任专业 Skill 的模板产生。按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 检查；Schema 通过不等于用户已经确认生效。
