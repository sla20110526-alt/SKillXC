# 道具与载具资产生产

首次进入时说明当前对象、工作模式、交付形态、正式输入和预期交付，询问用户是否确认使用。图片模型固定为 GPT Image 2；不要重新询问图片模型。

## 职责边界

- 负责非生命对象的结构身份：道具、武器、器具、机械装置、载具外观及对象上的图案文字。
- 负责对象部件、尺度、功能、状态、表面应用、对象—对象装配和供下游使用的交互接口。
- 人物持握、穿戴、骑乘或操作成图由 `character-asset-production` 锁定人物身份；生物/怪物组合由 `creature-monster-production` 负责。本 Skill 只交付已登记对象版本和接口锚点。
- 可供人物走位和换机位的大型载具舱内由 `location-spatial-production` 建立场景空间；本 Skill 负责外壳、门窗、座椅/控制台接口和精确载具版本。
- 本 Skill 生产可独立调用的图案文字母版，并负责把它应用到本 Skill 管辖的道具/载具。服装上的应用成图交 `character-asset-production`，场景固定表面上的应用成图交 `location-spatial-production`；两者都继承图案文字母版精确版本，不在本 Skill 越权改造载体。
- 爆炸、烟尘、能量、流体和碎屑时序交 `vfx-asset-production`；爆炸后的对象结构状态仍由本 Skill 负责。
- 只定义对象和候选验收。把确认的设计交 `image-prompt-production` 装配完整 Prompt；生产对话不写正式登记表。

## 输入门

读取最小数据切片：

- 项目 ID、绑定卡、任务 ID/版本、对象工作模式、需求槽位、预留正式资产 ID 和资产类型
- 剧本功能、时代地域、来源/制造条件、使用者、出现范围、数量和尺度依据
- 当前有效的场景/道具资产短执行卡中的对象切片；只读取引用的风格、美术、材质和展示灯光最小字段，不读取完整 Profile 或完整摄影规则
- 已登记父对象和附加对象的精确 `正式资产ID@版本`
- 必须继承、允许变化、禁止变化、用户参考及逐张用途
- 武器、机械、车辆、历史工艺或文字语言所需的顾问结论；缺少会改变身份、功能、安全或时代归属的事实时返回 `specialist-consultant-router`

使用 [对象资产生产卡模板](assets/对象资产生产卡模板.md) 固化决定。所需字段见 [对象交付、视图与缺口](references/object-deliverables.md)。

## 八种工作模式

1. **基础对象**：建立可复用道具/载具的结构身份和对象总览卡。
2. **对象状态变体**：继承正确对象版本，只改变破损、沾污、开合、空满载、烧灼、缺件或其他可复用剧情状态。
3. **图案文字母版**：先生产清洁、正视、可逐字核对的图案/文字母版，不同时贴到对象。
4. **对象表面应用**：以一个对象版本为父资产、一个或多个图案文字母版为附加资产，只改变指定表面区域。
5. **对象装配**：以一个主承载对象为父资产、一个或多个已登记对象为附加资产，建立需要跨镜复用的固定组合。
6. **交互接口定义**：只建立握点、接触、操作、受力、乘坐和进出锚点；不生成或登记人物/生物组合图。
7. **载具舱内接口交接**：把已登记载具外观、开口、尺度和控制/座椅接口交给场景空间 Skill；不把外观图伪装成完整舱内。
8. **版本兼容复核**：比较父对象、图案、装配件或接口换版影响，只输出 `可继续 / 需重做或新登记 / 资料不足`。

同一生成尝试只执行一种会产图的工作模式。交互接口和舱内接口是任务数据，不作为图片资产登记。

## 对象身份与交付形态

基础对象先建立稳定 `对象定义ID@版本`，使用 `assets/对象部件与交互锚点表模板.csv` 和 `object-anchor.schema.json` 记录轮廓、部件、连接、方向、尺度、握持、支撑、操作、乘坐、进出和图案区域锚点。没有可靠尺寸时写关系尺度和来源，不制造小数精度。

按用途选择一个交付形态：

- **单主视图卡**：简单道具使用清晰 3/4 主视图、尺度参照和必要细节，主体占比足够，不为排版制造多余小图。
- **单张对象总览卡**：复杂机械、武器或载具使用一张图中的 3/4 主视图、必要侧/后视图和功能细节；所有面板必须是同一对象、同一状态、同一图案和同一尺度逻辑。
- **图案文字母版**：正视、无透视、无材质变形的清洁母版；表面工艺留到对象表面应用模式。

对象卡画幅服从结构可读性，不继承项目成片画幅。展示灯光只能帮助判断材质和体积，不能改变对象固有色、增加无来源发光或隐藏功能结构。供 Seedance 2.0 调用时优先使用与当前状态匹配的一张对象卡，不同时上传一组重复小图。

## 结构、材质与功能

- 写清真实尺度或可信比例、正前/后/左/右、轮廓识别点、重心、支撑和安全间隙。
- 每个连接、铰链、开合、承重、握持、乘坐和操作部件必须解释功能；视觉造型不得使动作路径互相穿透。
- 材质区分基材、制造工艺、涂层、粗糙度、反射、边缘磨损、受力与污染来源；磨损要落在可解释部位。
- 载具另锁定轴距/轮距或等效结构、离地高度、门窗开合、灯具、动力/转向方向、驾驶/乘坐位置和外壳—舱内接口。
- 数量是身份的一部分。弹匣、容器、座位、车门、轮组和重复部件不能在不同面板中增减。

## 状态、图案与装配

状态变体以一个正确对象版本为父资产，完整输出 `PRESERVE EXACTLY / CHANGE / ONLY CHANGE`。结构性破损须写缺失部件、断口、形变、内部暴露和功能后果；爆炸、火焰或飞散过程不固化进静态状态卡。

图案文字任务读取 [图案文字与表面应用规则](references/graphic-text-application.md)，使用 `assets/图案文字校对表模板.csv` 与 `graphic-text-proof.schema.json`。逐字锁定内容、语言、大小写/全半角、行序、书写方向、版式和工艺；生成后逐字符比对。文字有误、缺字、多字、镜像或行序错乱时不得登记。

对象表面应用必须写父对象和图案母版精确版本、目标区域锚点、朝向、尺寸、边距、曲面变形、遮挡、工艺和磨损。不得借贴图任务改变对象结构或让图案漂到未批准表面。

对象装配只用于需要跨镜保持的固定组合。主承载对象写父资产，其余对象写附加依赖；写清装配锚点、连接方式、相对方向、间隙、受力和拆卸状态。短暂接触或人物临时拿取不建立对象装配。

## 正式资产依赖链

| 交付 | 资产类型 / 角色 | 生产依据 |
|---|---|---|
| 基础道具/载具卡 | 道具或载具 / 独立对象 | 父与附加依赖均不适用 |
| 对象状态卡 | 与父对象同类型 / 状态变体 | 父资产为基础、上一状态、表面应用或装配 `ID@版本` |
| 图案文字母版 | 图案文字 / 图案文字母版 | 父与附加依赖均不适用 |
| 对象表面应用卡 | 道具或载具 / 对象表面应用 | 父资产为被应用对象；附加资产为图案文字母版精确版本 |
| 对象装配卡 | 道具或载具 / 对象装配 | 父资产为主承载对象；附加资产为其余道具/载具精确版本 |

各交付使用不同预留正式资产 ID；同一 ID 的新版本只替代同一对象身份或同一派生交付。对象定义、锚点表和文字校对表由任务索引追踪，不进入正式资产表。

## 下游组合与载具空间交接

- 人物/生物交互：下传当前可调用对象 `ID@版本`、交互锚点、尺度、左右方向、握点/接触面、重量与运动限制。组合图由主体责任 Skill 建立，人物/生物为父资产，对象为附加资产。
- 载具舱内：下传载具 `ID@版本`、对象定义版本、外壳尺度、门窗/舱口锚点、座椅与控制台接口、可见外观材料和未知项。舱内场景母图把载具列为附加依赖；载具换版后触发舱内及其视图复核。
- 跨载体图案：下传图案文字母版 `ID@版本`、逐字内容、版式、方向、颜色和校对结论。服装或场景的责任 Skill 负责应用成图并把母版列为附加依赖；独立招牌、铭牌等对象仍由本 Skill 处理。
- 镜头临时物：无跨镜识别、无近景、无动作因果且不承担文字信息的普通物件可留在镜头 Prompt，不强建资产。

## Prompt回流、登记与复核

向 `image-prompt-production` 交付对象生产卡、对象定义/锚点切片、交付形态、精确父/附加版本、图案逐字校对切片、参考用途和三类变化清单。结果从身份、轮廓、尺度、结构、部件数量、材质、功能、文字、状态和跨视图一致性检查；对象设计错误由本 Skill 重写完整对象生产卡，再交后者建立下一 Prompt 版本，漏译、歧义、参考映射或模型随机偏差直接返回后者处理。本 Skill 不自行维护第二份完整 Prompt，也不在旧 Prompt 末尾叠加补丁。

只有“登记这张”“确认登记”等明确指向唯一候选的措辞才输出登记申请。“不错”“继续”“这个方向”“就用这张”不触发登记；失败或待调整图不登记，失败原因只有用户明确要求才转 `generation-version-log`。

父对象、图案母版或附加对象换版后，比较结构、尺度、锚点、应用区域、装配关系和功能。只有用户对唯一待复核版本明确确认继续使用后，才交 `approval-asset-registry` 更新当前兼容依赖；本 Skill 不写正式状态。

## 输出

- 对象资产生产卡、对象定义和工作模式
- 对象部件/交互锚点表或图案文字校对表
- 单主视图卡、单张对象总览卡或图案文字母版的交付定义
- GPT Image 2 Prompt 装配输入和生成后检查清单
- 候选检查、下游接口或兼容复核结论
- 用户明确登记后的登记申请与登记对话激活指令
