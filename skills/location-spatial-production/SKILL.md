# 场景空间资产生产

首次进入时说明当前场景、工作模式、母图构图模式、正式输入与预期交付，询问用户是否确认使用。图片模型固定为 GPT Image 2；不要重新询问图片模型。

## 职责边界

- 负责可供人物进入和调度的室内、室外及大型载具舱体的空间身份、母图、视图、场景状态和光影状态候选。
- 负责从已确认图像提取空间关系和锚点，不把单张图未显示的区域伪装成已知事实。
- 固定家具、门窗、灯具、柱体和自然地貌可作为场景锚点；需要独立复用或交互的道具/载具先交对应生产 Skill 登记。
- 不决定镜头叙事功能或人物调度。`directing-blocking` 和 `shot-visual-design` 提出所需空间关系或专项视图，本 Skill 负责资产落地。
- 只定义场景和候选验收。把确认的设计交 `image-prompt-production` 装配完整 Prompt；空间圣经、锚点表、视图投影表和光源地图是任务数据，不作为图片资产登记。

## 输入门

读取最小数据切片：

- 项目 ID、绑定卡、任务 ID/版本、场景工作模式、需求槽位和预留正式资产 ID
- 剧本明确的地点功能、时代地域、时间天气、场次动作和用户锁定参考
- 当前有效的场景/道具资产短执行卡中的场景切片；需要拆分复核时只读取其中引用的风格、美术、材质和展示灯光最小字段，不读取完整 Profile 或完整摄影规则
- 已登记空间依据资产、补充视图及独立附加资产的精确 `正式资产ID@版本`；载具舱内另读取已登记载具外观版本与对象接口切片
- 场景固定表面含可见图案文字时，读取已登记图案文字母版精确 `ID@版本`、逐字/图形校对通过结论和目标空间锚点；不得自行改字、镜像或让图案漂移到其他表面
- 必须继承、允许变化、禁止变化和需要支持的调度/镜头用途

缺少会改变建筑类型、空间功能、门窗连通、尺度、关键陈设、时间天气或主光方向的信息时暂停并列出最小问题。使用 [场景空间生产卡模板](assets/场景空间生产卡模板.md) 固化本轮决定。

## 七种工作模式

1. **场景母图**：生产场景的空间权威图。母图构图子模式只能是 `默认3/4空间母图` 或 `用户明确要求的剧照式母图`。
2. **空间圣经建档/更新**：基于已登记母图及已登记补充视图建立空间坐标、锚点、未知区和光源地图；不生成或登记新图片。
3. **预制剧情视图**：在分镜前按剧本动作和预期调度生产最少必要视图。
4. **专项/英雄视图**：为导演、分镜或用户指定机位补做专项视图；漂亮剧照构图若不替代母图，作为英雄视图处理。
5. **场景状态变体**：结构、陈设或环境状态发生可复用剧情变化时，继承母图/上一状态，只改变已批准状态。
6. **光影状态**：保持精确空间或视图不变，只改变时间、天气、灯具开关、曝光结果或其他已批准光影条件。
7. **版本兼容复核**：比较母图、场景状态、视图或附加资产换版后的兼容性，只输出 `可继续 / 需重做或新登记 / 资料不足`。

同一生成尝试只执行一种工作模式。母图构图子模式不是两个正式资产角色，也不能在生成失败后自行切换。

## 母图规则

默认使用 3/4 斜角空间视图，而不是把“3/4”理解为缩放比例：

- 同时显示至少两个相互垂直或明显转折的空间面、纵深轴、主要入口/出口、人物活动区和关键锚点。
- 使用能读清结构关系的中等广度透视和足够景深；避免正面平拍把场景压成宽幅壁纸。
- 画面首先服务空间读取和后续换角度，不为封面美感牺牲门窗连通、尺度或纵深。
- 对称大厅、窄长走廊、桥梁、洞穴或开阔自然地貌可按真实空间功能例外，但必须说明为何正面/轴线视图仍能提供足够深度。

只有用户明确要求更换母图规则时，才使用漂亮剧照式构图作为母图。此时仍提取可证实锚点，把无法从该图判断的背面、转角和连接关系标成 `未知禁止补写`；不得把电影感构图自动解释成完整空间。若用户只需要漂亮构图而不要求替代母图，将其作为英雄视图，不覆盖空间母图。

## 空间圣经与锚点

母图明确登记后读取 [空间圣经与锚点规则](references/spatial-bible.md)，建立稳定 `空间圣经ID@版本`、局部坐标约定、锚点表、简化平面关系、未知区和光源地图。使用 `assets/场景空间锚点表模板.csv` 与 `location-anchor.schema.json`。

每条关系区分 `可见锁定 / 关系锁定 / 推断待确认 / 未知禁止补写`。门、窗、柱、楼梯、沙发、床、灯具、树、山、道路等都使用稳定锚点 ID；Prompt 不写“人物在房间里”，而写可执行关系，例如“人物位于灯具 A 前方、面向门 D”。

新登记视图揭示此前未知区域时，更新空间圣经版本和锚点来源，但不反向声称旧母图已经显示该区域。只有已登记图像或用户明确确认的信息可以升级为锁定事实。

## 新视图与投影

每个视图先读取 [场景视图投影规则](references/view-projection-rules.md)，再使用 `assets/场景视图投影表模板.csv` 与 `location-view-projection.schema.json`：

1. 指定视图用途、空间依据资产、摄影机局部位置、朝向、机位高度、视场与透视；“反向视图”“另一边”“换个角度”不构成完整指令。
2. 对当前空间全部锁定锚点逐项写画面左/中/右、前/中/后景、完整/部分/遮挡/画外状态和可见表面。
3. 摄影机移动后重新计算投影和遮挡，不镜像母图，不把门窗、床、沙发、树山随构图需要重新排列。
4. 只补全目标视图必须显示的未知区域；先把补全项标为候选，不扩写其他不可见区域。
5. 保持尺度、结构连接、材质、磨损、色彩和固定物数量。基础视图继承同一光源地图；不发明第二个太阳或冲突主光。
6. 每张图片候选独立等待明确登记，并使用拆解/计划阶段预留的正式资产 ID。分镜后来发现的新专项视图先返回拆解/计划补充槽位和预留 ID。

## 场景状态与光影状态

场景结构、门窗开闭、家具移动、破坏、积水、积雪或持续环境改变若需跨镜复用，建立场景状态变体；一次性轻微烟尘、飞溅或短暂光效留在镜头 Prompt。状态变体保持未授权锚点不变，并在空间圣经中记录哪些锚点改变、移除或新增。

墙面、地面或其他场景固定表面的标志、壁画、编号和文字由本 Skill 负责应用成图，把图案文字母版列为附加依赖，并在生成后复核字符、方向、锚点、尺寸和透视；独立招牌、铭牌或可移动标识仍交 `prop-vehicle-production`。本 Skill 不改写图案文字母版内容。

光影状态必须继承精确母图、场景状态或场景视图，只改变光影条件。遵循一个清晰的主要方向性光源逻辑，允许位置明确的实景灯、天空填充和反射；禁止两个互相冲突的太阳、无来源阴影和新视图擅自改变灯具位置。详细继承见 [场景视图投影规则](references/view-projection-rules.md)。

## 正式资产依赖链

| 交付 | 资产类型 / 角色 | 生产依据 |
|---|---|---|
| 场景母图 | 场景 / 场景母图 | 父资产不适用；已登记独立固定对象可列为附加依赖 |
| 场景状态变体 | 场景 / 状态变体 | 父资产为母图或上一场景状态 `ID@版本` |
| 预制、专项或英雄视图 | 场景视图 / 场景视图 | 父资产为对应母图或场景状态 `ID@版本`；实际用于生成的其他正式视图列为附加依赖 |
| 光影状态图 | 光影 / 光影状态 | 父资产为被改光的母图、场景状态或场景视图 `ID@版本` |

不同交付使用不同预留正式资产 ID；同一 ID 的新版本只表示同一母图、同一视图或同一状态的替代版本。空间圣经、锚点表、投影表和光源地图分别以任务成果行由任务成果索引追踪，不进入正式资产表。

载具舱内场景母图的父资产仍写不适用，把已登记载具外观 `ID@版本` 列为附加依赖，并将舱口、门窗、座椅、控制台和外壳尺度映射为场景锚点。载具换版时该舱内母图及其派生视图进入兼容复核。

## Prompt 回流、登记与复核

向 `image-prompt-production` 交付场景生产卡、目标视图摄影机卡、锚点投影切片、空间依据与附加资产精确版本、光源继承和 `PRESERVE EXACTLY / CHANGE / ONLY CHANGE`。用户回传结果后从空间结构、锚点、尺度、遮挡、材质、光源和构图用途七层检查；空间设计或投影错误由本 Skill 重写完整场景生产卡，再交后者建立下一 Prompt 版本，漏译、歧义、参考映射或模型随机偏差直接返回后者处理。本 Skill 不自行维护第二份完整 Prompt，也不在旧 Prompt 尾部叠加补丁。

只有“登记这张”“确认登记”等明确指向唯一候选的措辞才输出登记申请及登记对话激活指令。“不错”“继续”“这个方向”“就用这张”不触发登记；失败或待调整图片不登记，失败原因只有用户明确要求才转 `generation-version-log`。

父版本变化时比较空间构造、锁定锚点、尺度、材质、场景状态、光源和投影。只有用户对唯一待复核版本明确确认继续使用后，才交 `approval-asset-registry` 更新当前兼容依赖；本 Skill 不写正式状态。

- 场景空间生产卡与工作模式
- 空间圣经、锚点表、光源地图与视图投影表

- 用户明确登记后的登记申请与登记对话激活指令
