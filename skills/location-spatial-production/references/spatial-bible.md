# 场景空间圣经与锚点规则

## 权威范围

空间圣经描述当前场景空间的可证实关系，不是从单张图片自动恢复出的精确三维模型。为每个场景建立稳定 `空间圣经ID`，内容或精确空间依据实质变化时递增版本；仅修正错字不改变空间事实时可按项目记录规则处理。

空间圣经至少引用：项目 ID、需求槽位、空间依据正式资产 `ID@版本`、适用场景状态、任务 ID/版本、锚点表路径、视图投影表路径和光源地图。它由任务索引追踪，不进入正式资产登记。

## 局部坐标约定

选择一个在各视图中稳定可解释的原点，例如主入口门槛中心、房间几何中心或建筑基准角；写清：

- `+X` 指向哪个命名锚点或现实方向
- `+Y` 指向哪个命名锚点或现实方向
- `+Z` 向上
- 尺度依据来自已知尺寸、用户锁定、人物尺度估计或仅为关系示意

坐标可以是近似值；没有尺度依据时优先写分区和拓扑关系，不制造小数精度。坐标系一旦锁定，不随新视图画面左右改变。

## 四级事实状态

| 状态 | 含义 | 下游使用 |
|---|---|---|
| 可见锁定 | 已登记图像直接显示 | 可作为 Prompt 硬继承 |
| 关系锁定 | 多个可见线索、剧本事实或用户确认足以确定关系 | 可作为空间关系使用，注明尺度置信度 |
| 推断待确认 | 为生成新视图提出的最小补全 | 只能作为候选，不得冒充既有事实 |
| 未知禁止补写 | 当前资料无法判断 | 新视图需要显示时先提出补全项 |

用户明确确认补全，或补全结果被正式登记后，才把对应条目升级为锁定。不得用“通常房间会有”改变事实状态。

## 锚点设计

使用稳定锚点 ID，例如 `ANC-SCN001-DOOR-A`、`ANC-SCN001-SOFA-A`。每个锚点记录：

- 名称与类别：结构、开口、通道、家具、灯具、固定道具、自然地貌、水体、道路、活动区或其他
- 局部位置/分区、尺度和离地高度
- 附着面、朝向、开合/可移动性
- 与其他锚点的连接、前后左右、距离级别和通行关系
- 在母图中的完整、部分、不可见或待确认状态
- 事实来源、锁定级别、允许变化和备注

“门在左边”只描述母图屏幕位置，不足以成为空间事实。应写成“门 D 位于北墙东段，向室内开启；在母图中位于画面左后方”。新视图只改变后半句的屏幕投影。

## 平面关系与活动区

用简化平面文字或示意图记录墙体、开口、通道、楼梯、主要家具、室外地标和人物活动区。不要求完整施工图，但必须回答：

- 哪些区域互相连通，门/通道连接到哪里
- 人物从入口到目标锚点的可行路径
- 哪些锚点阻挡视线、移动或摄影机
- 哪些位置能支持剧本明确动作
- 哪些区域当前未知

大型载具内舱作为空间处理时，外壳/门窗/座椅接口与正式载具版本对齐；不把外观资产自动当成完整内舱。

## 光源地图

记录太阳/天空方向、窗、灯具、火焰、霓虹等来源位置和作用范围，并区分主要方向性光源、实景辅助光、反射/环境填充和负补光区域。每个固定灯具使用锚点 ID。

基础空间只记录当前基准光影；时间、天气或灯具开关改变时另建光影状态。新视图重新计算受光、阴影和反射的可见结果，但不移动光源或引入冲突主光。

## 更新门

新登记母图版本、场景状态或补充视图后：

1. 保留原始事实来源和旧版本引用。
2. 只更新被新证据证明或否定的锚点与未知区。
3. 标出空间圣经新版本对既有视图、调度和镜头的复核范围。
4. 正式资产的可调用/待复核状态仍由 `approval-asset-registry` 管理；空间圣经不能替代状态传播。
