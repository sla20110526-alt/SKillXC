# Profile Schema v1.0

Profile 是专业决策方法资料，不是风格名称、Prompt 装饰词或对创作者全部作品的固定定义。每张 Profile 以 Markdown 卡为单一内容真源；[`profile-card-schema.json`](profile-card-schema.json) 定义机器可读字段、枚举和章节顺序，[`../scripts/validate_profiles.py`](../scripts/validate_profiles.py) 检查卡片、目录与来源索引的一致性。

## 1. 固定元数据

每张卡必须以 `## Profile 记录` 开始，并按 Schema 顺序包含：

- `ProfileID`：稳定 ID；更新内容不换 ID。
- `卡片版本`：原始 Profile 内容或规则发生修改才升级；项目只调用而未修改原始卡，不升级。所有真实存在过的版本同时登记在 [`profile-version-history.json`](profile-version-history.json)，禁止把“低于当前版本”推断成“历史版本一定存在”。
- `当前状态`：`待补资料`、`受限可选`、`可选择`、`暂停使用`、`已替代`。
- `资料成熟度`：`提纲`、`初版`、`已核验`、`项目验证`。
- `专业部门`、`主体名称`、`主体类型`、`代表作品`。
- `适用阶段`：允许读取完整 Profile 的专业阶段。
- `Profile默认作用域`：未另行声明时，本次选择覆盖的最小范围。
- `Profile本体失效点`：完整 Profile 在何时停止参与推理；下游只继承短执行卡。
- `方法证据状态`：该卡当前最高证据边界。
- `来源ID`：必须能在 [`sources.md`](sources.md) 找到。

## 2. 成熟度与调用门槛

| 成熟度 | 最低要求 | 正常状态 | 调用规则 |
|---|---|---|---|
| 提纲 | 有候选主体、部门和待研究作品 | 待补资料 | 不列为生产候选，只能补资料 |
| 初版 | 字段齐全；至少三条可执行方法；有适用条件、误用风险、交接和短卡 | 受限可选 | 列出时必须同时说明“分析性归纳、未逐条核验”；用户明确选择后仅在声明范围使用 |
| 已核验 | 关键方法逐条有可靠来源或可定位的作品观察；事实、观察和推断分开；来源可追溯 | 可选择 | 对应阶段由用户选择后使用 |
| 项目验证 | 已达到“已核验”；另有至少一个项目的用户确认结果、失败边界和适配记录 | 可选择 | 选择后仍只对当前声明范围生效 |

`暂停使用` 和 `已替代` 可覆盖任何成熟度，但不得出现在可选候选中。成熟度升级必须先补证据和验证记录，不能只改标签。

## 3. 方法证据标记

每条方法单独编号，并且只使用以下标记：

- `用户提供`：用户明确给出的主体、作品、参考或规则；不自动证明创作者意图。
- `直接观察`：能定位到具体作品、场景或时间点的画面／声音／剧作观察。
- `来源支持`：有可追溯的本人、核心合作者或可靠专业来源支持。
- `分析性归纳`：从作品或行业经验转译出的分析；不得写成创作者本人的原话或恒定风格。

同一条方法有多种证据时，以最强证据标记，并在“依据与边界”中保留其他来源。当前 27 张初版卡均只达到“分析性归纳”，未逐条完成来源核验。

## 4. 固定章节

除标题与 Profile 记录外，章节顺序固定：

1. `核心工作问题`
2. `可观察方法与证据`
3. `决策顺序`
4. `适用与误用风险`
5. `部门交接`
6. `当前项目短执行卡`
7. `来源与升级缺口`

每个 Profile 至少三条方法。禁止使用“高级、电影感、大师感”等不可检查的空词；器材、片名和创作者姓名必须转译成可观察结果和决策规则。

## 5. 当前项目短执行卡

Profile 本体只在对应专业阶段读取。完成本阶段后，下游只接收以下字段：

```markdown
Profile引用：<ProfileID>@<卡片版本>
生效阶段：<当前专业阶段>
生效范围：<全片／场戏／资产包；必须具体>
采用方法：<方法ID，最多保留当前任务真正需要的条目>
可执行规则：<逐条写动作、构图、光线、空间、节拍等决定>
可观察目标：<如何判断已经执行>
禁止项：<本项目中明确不采用的表面模仿或误用>
冲突处理：<与剧本事实、已批准控制卡冲突时保留什么>
失效点：<何时不再继承>
用户选择依据：<用户明确选择原文或当前对话位置>
```

短卡不得自动带入创作者姓名、片名或“某某风格”作为生成 Prompt；只能带入用户选定的方法结果。

## 6. 版本与项目验证

- 修改原始 Profile 的方法、证据、适用边界或交接规则时，升级卡片版本并记录更新依据。
- 升级原始 Profile 时，同步追加历史版本目录；当前卡片版本必须等于历史目录中最后一个版本，已经登记的历史版本不得删除或重排。
- 项目调用产生的是项目短执行卡，不复制或改写资料库原卡。
- `项目验证` 必须指向项目侧记录；资料库只保存验证范围、结论和记录定位，不吸收项目隐私或完整生产日志。
- 新来源与旧结论冲突时，先降级或暂停相关条目，再复核；不得静默覆盖。
