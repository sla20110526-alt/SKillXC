# 影视大师 Profile 资料库

这是独立方法数据库，不随任一项目自动生效。

## 强制调用规则

1. 先读 [Profile Schema](references/profile-schema.md) 与 [资料库目录](references/catalog.md)，只列出当前状态为 `受限可选` 或 `可选择` 的同部门候选。
2. 候选必须同时展示主体、代表作品、资料成熟度和证据边界；`受限可选` 必须明确说明“分析性归纳、未逐条核验”。
3. 只有到导演、美术、剧作、剪辑各自的方法建立阶段，才询问用户是否选择；摄影 Profile 只在建立或重建全片摄影基线时常规询问。
4. 用户明确选择后，才读取对应完整 Profile；未选择时先询问是否确认使用该部门通用 Skill，不自动启用。
5. 默认最多一个主 Profile。需要补充 Profile 时，必须让用户确认，并限定到具体局部问题、作用范围和失效点。
6. 不因过去项目选过某 Profile 就在新项目自动沿用。

## 摄影 Profile 生命周期

- 常规询问点只有 `cinematography-direction` 的“全片摄影基线”模式。选择后把方法压缩进全片摄影规则卡，随即关闭完整 Profile。
- “场戏摄影约束”、`shot-visual-design`、“逐镜摄影审核”和 `video-prompt-production` 只继承全片/场戏摄影卡，不重新列候选、不重复询问、不读取完整 Profile。
- 只有用户明确要求摄影重释，或现有规则无法完成已经成立的场戏风格断裂，才可提出场戏例外。必须先说明冲突规则、例外内容、精确场次/镜头范围和失效点，得到用户明确确认后才读取指定 Profile。
- 场戏例外不得静默覆盖全片摄影规则卡；范围结束后自动回到全片基线。

## 使用方法

1. 记录本次 `Profile引用（ProfileID@卡片版本）／生效阶段／生效范围／用户选择依据`；范围含糊时不得激活。
2. 只选择能解决当前专业问题的方法 ID，结合剧本事实和已批准控制卡重新推导；不复制代表作的具体构图、场面或对白，不堆叠创作者姓名。
3. 输出采用方法、舍弃方法、可观察目标、禁止项、冲突处理和失效点；使用 [Profile Schema](references/profile-schema.md) 的短执行卡字段。
4. 当前阶段结束即关闭完整 Profile。下游 Prompt 只继承短卡的可执行结果，不携带主体姓名、片名或“某某风格”。
5. 引用具体作品时说明提取的是该作品方法，不把它冒充创作者在所有作品中的固定风格。

## 状态与证据门槛

- `提纲／待补资料` 不得进入生产候选。
- `初版／受限可选` 可以在用户知情并明确选择后试用，但所有方法仍视为分析性归纳。
- `已核验／可选择` 必须逐条有可追溯来源或可定位作品观察。
- `项目验证／可选择` 还必须有用户确认的项目适配、失败边界与记录定位。
- `暂停使用`、`已替代` 不得列出或激活。

运行 [`scripts/validate_profiles.py`](scripts/validate_profiles.py) 只能证明卡片结构、目录、来源 ID 和状态门槛一致；不能证明方法归因真实或创作质量成立。

## 累积新 Profile

用户提供新参考时：

1. 确认创作者、作品、部门和具体参考片段。
2. 区分可观察事实、可靠访谈/资料和分析推断。
3. 按 [Profile Schema](references/profile-schema.md) 建卡，逐条标记证据；成熟度只能按门槛升级。
4. 修改原始方法、证据、适用边界或交接规则时升级卡片版本并注明依据；项目只调用原卡不升级。
5. 新资料不得静默改写旧结论；来源冲突时先降级或暂停相应条目，再复核。

## 边界

Profile 是专业决策辅助，不是要求模型“照某位在世创作者的风格生成”的标签。优先使用可执行的视点、空间、光线、调度、节奏和材料语言。用户尚未选择、作用域已结束或短卡失效时，Profile 不再参与当前任务。
