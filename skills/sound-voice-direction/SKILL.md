# 声音与声音资产

## 对象和责任必须分开

- `角色声音身份卡`：跨场稳定的创作控制数据，描述声音边界；不是音频文件，不进入正式资产登记表。
- `角色声音参考音频`：可播放、可唯一定位的独立音频文件；只有用户明确登记后才成为正式声音资产并进入可调用表。
- `场戏声音卡`：逐场对白表现、环境底声、动作音效、空间声、静默和声音桥；属于单次创作短卡，不登记为资产。
- `Seedance临时镜头内声音`：用户明确选择后由当前镜头临时生成；不是正式声音资产，也不保证跨镜声音一致。

环境底声、动作音效、逐场声音表现和镜头内临时声音默认不拆成独立资产、不预留正式资产 ID、不进入登记。系统只处理生成可用镜头所需的同步声音，不延伸到最终配乐、混音或成片母版。

每张任务单只选择以下一种模式。

## 首次所需资料

系统必须已有：项目数据绑定卡、项目锁定卡及声音生成策略、当前剧本/内容版本、说话者 ID/名称、台词/独白/画外发声的原文和出处。模式 C 还必须读取当前分镜版本、场戏表演卡和镜头中的说话关系。

用户可提供：合法可用的参考音频、语言和口音偏好、年龄感与音色倾向、不能出现的声音特征、声音模型/服务偏好。没有参考音频时允许本 Skill 提出声音身份草案；需要外部生成独立候选时，必须先询问用户采用哪个声音模型或服务，再按该工具优化任务说明。

## A｜角色声音身份建档

### 谁需要建档

- 必须建立：有台词、独白或持续画外发声，且跨多个生成镜头需要声音连续的主角、反派、关键叙事角色和反复出场角色。
- 可按任务决定：只发声一次但声音具有叙事辨识度的角色或旁白。
- 默认不建立：无台词角色、模糊背景人群、只发出非语言反应且无需跨镜连续的角色。简单说话者可由用户明确选择“不建身份卡，使用镜头临时声音”，并在任务单写明理由。

### 建立方法

1. 建立项目内稳定的 `声音身份卡ID`，例如 `VOICE-CHR-001`；关联角色/说话者 ID。真人说话者填写人物正式资产精确版本，非人生命体填写生物怪物正式资产精确版本，两者不得同时填写；无对应图片资产时两项都写“无”。不要把身份卡当作人物、生物怪物或声音资产版本。
2. 区分 `SCRIPT_EXPLICIT`、`USER_LOCKED`、`REFERENCE_OBSERVED`、`CREATIVE_PROPOSAL` 与 `UNKNOWN`，不把推测伪装成剧本事实。
3. 只写跨场稳定项：语言、方言/口音边界、年龄感、基础音高范围、音色质地、共鸣与气息、基础语速节奏、咬字与句尾、动态范围、压力下允许变化和禁止变化。
4. 口型同步只记录语言、台词准确性和同步要求；表演目标、倾听和身体动作仍由 `acting-direction` 负责。
5. 使用 `assets/角色声音身份卡模板.md` 和 `assets/角色声音身份表模板.csv`，并用 `assets/voice-identity.schema.json` 检查。

### 状态与版本

- 首版为 `v001`；新草案为 `待确认 + 当前有效=否`。用户明确说“确认这版声音身份卡”“按这版声音身份执行”或等价采用意思后，才设为 `已生效 + 当前有效=是`。这不是声音资产登记，不使用“登记这段声音”触发。
- 新版生效时，上一生效版改为 `已替代 + 否`；同一项目、同一说话者最多一版当前有效。稳定声音边界实质变化才升级，逐场音量、停顿、呼吸或情绪强度变化不升级身份卡。
- 身份卡只保留预留正式声音资产 ID，不反向写“当前音频版本”。正式音频在登记表中单向引用它所依据的身份卡版本；登记或替换音频不会升级身份卡。身份卡稳定边界改变时，输出关联正式声音资产与场戏卡复核清单，由登记/就绪责任 Skill 处理，不自动判旧音频继续有效。
- 身份卡固定写入绑定项目的 `creative-control/sound/identities/`；汇总表为 `creative-control/sound/角色声音身份表.csv`。专用声音控制对话调用 `creative-control-versioning` 的声音索引事务，保留旧版和用户生效原文。
- 中央源定义版本与项目身份卡版本分离。每个项目身份卡从 `v001` 开始并记录精确 `CCS-VOICE-IDENTITY@版本`；中央源升级不自动改既有项目，只有稳定声音边界或源定义引用实质变化时才建立下一项目版本。

## B｜独立声音候选生产

只为有台词、独白或持续画外发声的说话者生产可独立播放的参考音频候选。沿用资产拆解时为该说话者预留的正式声音资产 ID，例如 `VOI-001`；预留不等于登记。若原计划只使用临时声音、后来才决定把它变成跨镜参考音频，先返回 `script-asset-breakdown` 增补候选并预留 ID，再由 `asset-demand-plan` 建立需求槽位；本 Skill 和登记 Skill 都不得临时补号。

1. 读取当前有效声音身份卡；重要或反复发声角色没有有效身份卡时先返回模式 A。简单说话者经用户确认可只用本任务声音说明。
2. 让用户选择唯一来源路线：上传已有合法参考音频；使用用户指定的外部声音模型/服务生成候选；从已生成可用镜头中提取干净参考音频。没有选择时暂停，不自行指定服务。
3. 外部生成候选时给出短试听文本、原台词样本、稳定身份约束和禁止项；试听应覆盖中性陈述、轻微压力和自然停顿，不用一段极端情绪替代基础身份。
4. 检查候选是否可唯一定位、可播放、说话者单一、台词清楚，并标明音乐、环境声、混响或压缩污染及其可调用限制。候选仍然只是候选。
5. 用户明确说“登记这段声音”“确认登记这段参考音为【名称】”等，且已形成独立音频文件后，生产对话只输出登记申请并转 `approval-asset-registry`。只说“这个声音可以”“先用这个”不触发登记。
6. Seedance 镜头内声音只有在用户把它单独形成可唯一定位的音频文件并明确要求登记后，才可作为该预留 ID 的正式版本候选；视频可用不自动登记其中声音。

登记或替换正式音频后不改声音身份卡版本；下游通过正式资产登记表的 `关联声音身份卡ID与版本` 查明该音频依据，并复核受影响的场戏声音卡和正式 Prompt。

使用 `assets/独立声音候选卡模板.md` 输出。失败候选不登记；失败原因只在用户明确要求时交 `generation-version-log` 记录。

## C｜场戏声音适配

在当前分镜组完成逐镜摄影审核后、生成单元就绪审计和正式 Prompt 之前执行。

1. 锁定说话者、原台词、语言、口型同步范围和说话镜头；明确非说话角色不得动嘴，不自动增加对白、旁白、字幕或音乐。
2. 对每个有台词/独白的说话者读取当前有效声音身份卡。只从场戏表演卡读取行动意图、停顿节点和呼吸动作，不修改表演卡。
3. 为每个说话者写明声音来源：`正式声音资产ID@版本 + 调用方式`，或 `用户已确认的Seedance临时镜头内声音`。正式资产只从当前项目可调用表读取。
4. 若没有正式声音资产，必须在写正式 Prompt 前询问用户选择：返回模式 B 生产/上传独立候选，或本生成单元使用 Seedance 临时镜头内声音。用户未选择时暂停；不得自行把缺口改成临时声音。
5. 临时声音按当前有效身份卡或用户确认的本场声音说明约束，但明确标记“不登记、跨镜一致性待复核”。后续若要转正，必须回模式 B 形成独立音频文件并走明确登记。
6. 逐场只变化音量、速度、停顿、吞咽、呼吸、压抑/外放程度、句尾和空间距离；不得无意改变年龄感、基础音高、音色、语言或口音身份。
7. 建立环境底声、前景动作声、远景声、空间混响、静默和声音桥；写清声源与画面动作接点，但不把这些镜头指令登记为独立资产。

使用 `assets/场戏声音卡模板.md` 输出。场戏卡拥有稳定 ID 和独立版本，由任务索引追踪，不另建重复 CSV。

## 下游交接与就绪门

- `continuity-readiness-audit` 对每个发声角色检查声音身份卡版本、正式声音资产版本或用户明确的临时声音决定。无台词、独白或持续画外发声时写“本场无需独立声音资产”；只含喘息、笑声、哭声等非语言发声且无跨镜声音连续需求时，也写明“无需独立声音资产，由场戏声音卡约束”。不能把空白当作通过。
- 正式声音资产可否直接上传给当前 Seedance 工作配置必须在使用时核对。可调用表中的 `调用方式` 必须如实写为直接音频参考、声音描述参考、外部配音参考或使用时核对；不得把未上传的音频写成已上传。
- `video-prompt-production` 只提取当前生成单元的说话者、原句、声音来源、逐场表现、环境声和禁用项，不复制整张身份卡，也不在 Prompt 阶段另造声音身份。

按[项目数据三层契约](../production-router-handoff/references/project-data-contract.md)检查结构。Schema 通过不代表身份卡已生效、候选音频已登记或用户已同意临时声音。
