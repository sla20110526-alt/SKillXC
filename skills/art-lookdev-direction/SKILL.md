# 美术与 LookDev 指导

## 进入与职责门

先由 `production-router-handoff` 说明本轮工作模式、最小输入和交付物，取得用户确认。没有具体项目、绑定卡、项目锁定卡、剧本事实版本或当前风格意图基线时只列缺口，不建立虚构项目规则。

本 Skill 唯一负责项目世界的可见物质逻辑：建筑与室内、陈设密度、服装妆造、道具形制、材料与制造工艺、维护与老化、物体固有色、阶层差异、视觉母题及其跨资产一致性。

不得决定摄影机位置、景别、焦段、透视、运镜、曝光或光源布局；分别交 `cinematography-direction`、`shot-visual-design` 和 `lighting-direction`。不得把历史、科学、职业或物理推测写成项目事实；交 `specialist-consultant-router`。不得直接生产资产图片、Prompt 或登记申请；分别交分类资产 Skill、`image-prompt-production` 和登记流程。

## 每次只选一种工作模式

### A｜项目 LookDev 长期基线

用于风格四卡专业基线链，或项目永久美术规则实质变化后的重建。

1. 读取当前项目风格意图基线、项目锁定卡、剧本事实最小切片、用户参考用途和已经形成的顾问结论。
2. 只在本模式列出美术／Production Design Profile、代表作品、成熟度和证据边界，询问用户是否调取。未明确选择时只使用通用方法；默认最多一个主 Profile，局部补充必须另获确认并限定唯一问题、最小范围和失效点。
3. 使用 [世界设计推导与四层边界](references/art-lookdev-decision-contract.md) 完成事实推导、部门设计和边界判定。
4. 使用 [美术 LookDev 基线卡模板](assets/美术LookDev基线卡模板.md) 输出 `待确认 + 当前有效=否` 的项目长期基线草案。
5. 关闭完整 Profile，只把已采用方法转译为可观察规则；将草案交 `creative-control-versioning` 做项目卡版本与生效事务。

长期基线只把当前项目风格意图基线作为唯一直接上游；顾问成果使用独立字段。不得引用摄影、灯光、P0评审或最终风格包。美术卡生效后交全片摄影建立下一张基线，不反向读取摄影或灯光方案。

### B｜资产类别执行交接

用于把当前已生效的美术基线翻译给一个明确资产类别，供 P0 测试准备或风格总控组装最终资产短执行切片。此模式不重新读取 Profile。

1. 每次只处理人物、场景、道具／载具／图案文字、生物／怪物或 VFX 世界材料接口中的一类，并写唯一责任资产 Skill。
2. 只读取当前有效美术基线、需求槽位、预留正式资产 ID、相关剧本事实和已有顾问成果；不能用本包绕过风格评审或风格包放行门。
3. 使用 [美术执行交接包模板](assets/美术执行交接包模板.md)，从永久世界规则中提取本类别真正需要的建筑／服装／对象、材料工艺、老化污迹、固有色、母题和禁项。
4. 形成 GPT Image 2 美术短执行切片，但不写完整 Prompt，不指定摄影机或光源。分类资产 Skill 先把短切片结合本体结构和状态形成资产生产卡，之后才交 `image-prompt-production`。

交接包使用稳定 `ALD-<项目ID>-<范围>` 和独立成果版本，作为“创作短卡”进入任务成果索引。它只是美术规则的派生投影：P0 使用时必须被当前评审卡绑定到测试 ID 与预留 ID；批量生产必须使用最终风格包中的短切片，不能直接拿本包放行。

### C｜场次美术状态适配

用于同一世界在特定场次出现可复用的季节、占用、整洁、破损、施工、庆典、灾后或其他美术状态；不重新读取 Profile。

1. 读取当前有效美术基线、场次事实、连续性起止状态、当前正式资产版本和本场功能。
2. 只定义跨镜或可复用的美术状态：哪些陈设、服装、道具、表面、污迹或固有色发生变化，变化原因、范围和延续时段。
3. 需要形成新正式资产时返回 `asset-demand-plan` 和唯一分类资产 Skill，预留独立资产 ID 后再生产；不得把场次状态偷偷写回永久基线。
4. 只在本镜发生、不需要跨镜复现的烟尘、反光、镜头污点、光斑或短暂天气可见效应，标为“镜头临时效果”并路由 VFX、灯光或镜头 Prompt；本 Skill 不设计其时序或摄影实现。

场次适配也使用 [美术执行交接包模板](assets/美术执行交接包模板.md)，成果 ID 建议为 `ALD-<项目ID>-SCN-<场次ID>`，进入任务成果索引，不进入项目长期基线索引。

### D｜美术规则兼容复核

用于项目风格基线、美术基线、顾问结论或正式资产父版本变化后的影响比较。逐项核对事实依据、材料工艺、阶层、固有色、母题、场次状态和下游精确引用，只输出 `可继续 / 需建立新版 / 资料不足`。本 Skill 不直接改控制索引、成果状态、资产状态、分镜或 Prompt。

## 事实到设计的决策顺序

任何模式都不得从“高级、电影感、复古、压抑、贫穷”等抽象词直接跳到画面。至少依次判断：

1. **事实底座**：年代、地域、季节、经济与供应条件、社会阶层、职业、空间所有权、建造／制造来源、功能、使用者、维护能力和剧情时间跨度。
2. **真实度路线**：真实复原、可信重构或有限风格化；写明允许偏离的范围和不能偏离的事实。
3. **空间与社会秩序**：尺度、动线、私密／公共边界、陈设密度、物件获得难度和阶层差异如何可见。
4. **材料生态**：基材、制造工艺、表面处理、维修替换、污染来源、磨损部位、老化速度和维护差异必须互相解释。
5. **部门展开**：分别建立建筑／陈设、服装／妆造、道具、材质工艺、老化污迹、固有色和母题规则，不用一段氛围词代替。
6. **颜色与母题**：颜色写固有色的叙事职责和跨资产分布；母题写可重复载体、出现条件、变化方式和禁用俗套。现场受光颜色仍归灯光。
7. **四层归类**：每条决定只归入永久世界规则、资产类别规则、场次美术状态、镜头临时效果之一；不能用镜头偶发现象升级永久规则。
8. **顾问缺口**：把需要准确、允许艺术化、纯虚构规则分开；没有可靠结论时保留缺口、截止点和安全回退，不自行裁决。

每项设计决定至少能回答：依据哪条事实、转成什么物质规则、画面中如何观察、适用到哪里、由谁实现、如何检查。抽象形容词只能作为意图标签，后面必须跟可观察结果。

## 四层边界

- **永久世界规则**：在本项目适用范围内长期稳定的建造、制造、阶层、材料、固有色、维护和母题语法；进入 LookDev 基线，不跨项目继承。
- **资产类别规则**：某类人物、空间、对象、生物或 VFX 接口如何继承永久规则；进入美术执行交接包，不替代分类资产设计。
- **场次美术状态**：在明确因果与时间范围内，已存在世界或资产出现的可复用变化；进入场次适配成果，需要跨镜复现时建立资产状态版本。
- **镜头临时效果**：只服务一个镜头、没有跨镜身份、不会改变资产固有状态的短暂可见效果；路由到 VFX、灯光、镜头设计或 Prompt，不进入美术基线。

## 交付与版本

- 项目 LookDev 长期基线使用稳定控制卡 ID、项目卡版本和当前中央源定义，唯一写入 `creative-control/项目创作基线索引.csv`；不要再复制到任务成果索引。
- 资产类别执行包和场次美术状态包使用稳定成果 ID 与独立 `v001` 起版本，进入 `tasks/任务成果索引.csv`。新成果先为 `草案 + 当前有效=否`，本 Skill 完成业务复核和结构检查后才可激活为 `可交接 + 是`。
- 永久规则、适用范围、采用方法、直接上游、顾问结论或 Profile 精确引用实质变化时建立下一项目基线版本；中央源/Profile发布新版、本次继续调用同一决定、场次状态或镜头临时效果本身不升级项目基线。
- 交接包正文、范围、工作模式或上游精确引用变化时建立下一成果版本；原样交接不升级。已入表旧成果文件保持不可变。

## 返工路由

- 剧本事实、年代或状态出处错误：`script-truth-index`。
- 历史、职业、科学、法律、危险物理或工艺事实缺口：`specialist-consultant-router`。
- 永久世界、材料、阶层、固有色或母题规则错误：返回本 Skill 模式 A。
- 单类人物、空间、对象、生物或 VFX 本体翻译错误：返回唯一分类资产 Skill；若短切片本身错误，返回本 Skill 模式 B。
- 摄影机、透视、构图或镜头运动错误：`cinematography-direction` / `shot-visual-design`。
- 来源光、受光、阴影、反射或曝光错误：`lighting-direction`。
- 已确认资产设计在图片 Prompt 中漏译或参考映射错误：`image-prompt-production`。

## 停止条件与禁止事项

遇到项目／剧本／上游版本不唯一、参考用途不明、硬事实缺口会改变设计、四层边界混淆、Profile 未获确认、资产类别或责任 Skill 不唯一时暂停，只询问当前阻断决定。

禁止只输出“高级、电影感、质感、复古、做旧、低饱和”等口号；禁止把灯光造成的颜色当固有色；禁止把摄影透视当空间设计；禁止用美术 Profile 发明剧本事实；禁止传递 Profile 姓名、片名或未采用方法；禁止让执行交接包越过 P0／风格包门直接放行批量生产。

## 输出

- 模式 A：美术 LookDev 长期基线草案、Profile 采用／舍弃、顾问缺口和控制版本操作申请。
- 模式 B：单一资产类别美术执行交接包、GPT Image 2 美术短执行切片和成果索引事务输入。
- 模式 C：场次美术状态包、连续性范围、需新建的资产状态槽位和镜头临时效果路由。
- 模式 D：兼容复核结论、受影响精确版本和唯一返工节点。

默认使用轻量生产回显，只向用户展示本轮可见设计结论、必要缺口和一个决定点；后台版本与索引仍完整维护。
