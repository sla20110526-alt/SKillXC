# 摄影指导

## 权责边界

`cinematography-direction` 负责摄影语言的一致性和物理实现：视场与透视体系、摄影机物理距离、镜头族、景深与焦点、曝光保护、支撑方式、手持尺度以及运动路径的可执行性。

`shot-visual-design` 负责逐镜叙事方案并且是分镜表的唯一写入者：镜头存在理由、叙事任务、观众视点、景别对象、机位侧别与高低、俯仰、构图、遮挡、运镜动机、触发点和停止点。

摄影指导不得重新决定镜头叙事功能、镜头数量与顺序、信息揭示、观众视点或人物调度，也不得直接改写分镜表。摄影审核提出的技术修正由 `shot-visual-design` 判断并写回；需要改变叙事方案时退回真正负责的上游 Skill。

## 先判断工作模式

每张任务单必须只选择以下一种模式：

### A｜全片摄影基线

在 `style-lock-director` 的风格锁定阶段执行；项目摄影基线发生实质变化时也从此模式重建。

1. 由 `production-router-handoff` 说明通用摄影 Skill 的用途并取得用户确认。
2. 仅在此模式列出 `film-profile-library` 中现有摄影 Profile 与代表作品，询问用户是否调取以及选择谁。
3. 用户未选择时只使用通用摄影方法；不得默认沿用旧项目或过去对话中的选择。
4. 默认最多一个主 Profile。补充 Profile 必须由用户确认，并限定到一个明确局部问题和作用范围。
5. 把采用与舍弃的方法转译为可执行摄影规则；模式结束后关闭完整 Profile，只向下游传递规则卡。
6. 使用 `assets/全片摄影规则卡模板.md` 输出全片基线。

### B｜场戏摄影约束

在场戏节拍、导演调度和表演方向明确后、逐镜设计前执行。

1. 读取全片摄影规则卡、当前场戏节拍、导演调度、场戏表演卡及其母档 ID/版本引用、空间与灯光最小切片。重要角色缺少当前有效母档或场戏适配时返回 `acting-direction`，不在摄影卡中补写表演。
2. 继承全片规则，不询问或读取完整摄影 Profile。
3. 把上游已经决定的观众视点、情绪距离、人物关系和空间行动翻译为本场允许的视场/透视范围、景深与焦点原则、曝光保护、支撑方式、手持尺度、运动物理边界和禁区。
4. 不替 `shot-visual-design` 决定逐镜机位、构图、镜头数量、运动动机或信息顺序。
5. 使用 `assets/场戏摄影约束卡模板.md` 输出约束卡。

只有以下任一条件成立时才提出摄影 Profile 例外：用户明确要求按指定摄影方法重新解释本场；或现有全片摄影规则确实无法完成一个已经成立的场戏风格断裂。先说明冲突、需要改变的规则和最小作用范围，得到用户明确确认后才调取 Profile。例外到指定场次或镜头范围结束即失效，不覆盖全片基线。

### C｜逐镜摄影审核

在 `shot-visual-design` 已把剪辑节奏修订写回逐镜草案后、进入声音与 Prompt 生产前执行。这样审核读取的是镜头数量、顺序、时长和运动可用时间已经稳定的当前草案。

1. 读取全片摄影规则卡、场戏摄影约束卡、剪辑节奏卡和已写回的逐镜草案，不询问或读取完整摄影 Profile。
2. 保留每镜叙事任务、观众视点、景别对象、机位含义、构图关系与运镜动机。
3. 检查可见视场与透视目标能否成立，摄影机物理距离与空间是否可行，镜头族是否一致，景深/焦点/曝光是否承担了正确的信息，支撑方式和运动路径/速度/加减速是否可执行。
4. 每镜只给出一种结论：`通过`、`摄影技术修正`、`退回上游重设计`。
5. 使用 `assets/逐镜摄影审核卡模板.md` 输出审核卡，不直接修改分镜 CSV。

`摄影技术修正` 只能在不改变叙事功能的前提下提出物理距离、视场/透视实现、镜头族、景深/焦点、曝光、支撑方式或运动物理参数的修正。若必须改变观众视点、镜头存在理由、景别对象、机位意义、构图权力关系、运镜动机或人物调度，选择 `退回上游重设计` 并指明责任 Skill。若运动无法在既定时长或生成单元内完成且不能用摄影技术修正解决，退回 `editing-rhythm`；剪辑修订写回后必须重新执行逐镜摄影审核。

## 输出语言

优先描述可观察结果：摄影机与人物的物理距离、视场宽窄、前后景比例、背景压缩、步伐反馈、景深结构、暗部可读性和运动稳定程度。毫米焦段、器材和支撑系统只作辅助，不得只写器材名或“电影感”。

本 Skill 的三种输出都是单次创作短卡，由任务索引追踪；它们不是用户批准记录，也不替代后续分镜确认。
