# 分镜、正式 Prompt 与可用镜头的版本状态规则

## 五类稳定身份

- `分镜组ID`：一次交给用户检查和生产的一组镜头，建立后不因返修改变。
- `镜头ID`：单个镜头的稳定身份，不用当前顺序代替；重新排序不改 ID。
- `生成单元ID`：一次外部生成承载的镜头成员与内部顺序；成员或内部顺序变化、拆分或合并时建立新身份。
- `视频参考映射数据集ID`：一个生成单元的媒体参考映射身份，建议为 `VRM-<项目代号>-<生成单元代号>`；同一单元的映射修订只升级版本。
- `正式PromptID`：一个生成单元的稳定 Prompt 身份；同一生成单元的版本变化不改 ID。生成单元拆分或合并时，新单元必须建立新的生成单元 ID 和正式 Prompt ID。

生成单元身份由成员集合与内部顺序共同界定。成员或内部顺序改变、一个拆多个、多个合一个时，新单元建立新 ID，旧 ID 标为被替代；仅把成员与内部顺序都未改变的完整单元挪到另一位置时保留 ID。`editing-rhythm` 只在 `ERT/ERC` 提出成员和替代映射，`shot-visual-design` 写回正式身份；不得让剪辑卡直接改分镜或预造正式 Prompt ID。

ID 的具体前缀可按项目规则生成，但同一项目内必须唯一、稳定且可读。镜头顺序另用 `镜头序号` 表达。

## 四种版本何时递增

### 分镜组版本

从 `v001` 开始。组内镜头成员、顺序、生成单元成员/边界、剪辑或摄影审核精确引用/写回状态，或任一镜头内容变化时，分镜组形成新的快照版本。未改变的镜头保留原镜头版本。只写入 `ERT/ERC` 来源、审核处置或改变生成单元分组而没有改变镜头创作内容时，也建立新分镜组快照，但不因此递增单镜头版本。每个快照使用 `分镜组ID@版本.csv` 或项目约定的等价独立路径保存，旧快照只读保留；不得只改表内版本号后覆盖旧文件。

### 镜头版本

从 `v001` 开始。只有本镜叙事任务、观众视点、景别/机位/构图/运镜、人物动作与表演、调用资产、时长、第一帧或结束状态发生变化时递增。单纯写入剪辑/摄影审核来源与处置、改变生成单元分组而不改变本镜内容，或改写 Prompt 表达，不递增镜头版本。

### 视频参考映射版本

从 `v001` 开始。媒体来源、参考顺序、平台引用名、唯一用途、允许/禁止继承、平台处理方式、适用镜头或当前服装/状态变化时递增。只改 Prompt 措辞且参考映射完全不变时不递增。生成单元身份改变时不沿用旧映射 ID，而是建立新 VRM 身份。

### Prompt 版本

从 `v001` 开始。每次交付一份替代上一版的完整正式 Prompt 时递增。不得使用 `最终版`、`终版2`、`final-final` 等名称代替版本号。每版必须引用准确的分镜组版本、镜头版本集合和VRM版本。VRM变化、平台设置变化或上游精确引用变化都必须形成新的完整Prompt版本。

状态变化本身不升级分镜组、镜头或 Prompt 版本。使用完全相同的 Prompt 重新生成也不升级 Prompt 版本；只有 Prompt 正文被重新交付为替代版本时才递增。不同抽卡结果的详细批次差异只在用户要求时写入详细生成版本记录。

## 两个状态面不得混用

### Prompt 状态

- `待人工检查`：已交付，等待用户检查。
- `已放行生成`：用户确认可以复制到外部模型生成。
- `需修订`：用户要求重写当前 Prompt。
- `已替代`：已有更新 Prompt 版本取代本版。

### 生成结果状态

- `未生成或未回报`
- `生成中`
- `需返修`
- `部分可用`
- `可用`
- `已替代`

Prompt 已放行不代表生成结果可用；结果可用也不得倒推其他 Prompt 或其他镜头通过。

Prompt 版本被替代，不自动把旧版本生成结果改成“已替代”。旧结果是否仍被当前剪辑采用，必须由用户明确决定；版本记录分别保存“Prompt当前有效”和“结果当前采用”。

不建立额外的“分镜批准”负担。正式 Prompt 被用户放行生成时，仅把该 Prompt 明确引用的分镜组版本和镜头版本集合作为本次生成依据；后续分镜发生变化时必须产生新分镜版本和新 Prompt 版本。

## 用户短指令的解释

- “这组 Prompt 通过，我去生成”“Prompt 没问题”：只把指定 Prompt 标为 `已放行生成`。
- “镜头可用”“成片可用”：只把可唯一定位的生成单元标为 `可用`；对当前 Prompt 版本的结果默认同时记 `结果当前采用=是`，除非用户明确说只是备选、暂留或不采用。
- “上一组通过，继续下一组”：仅当上一组已进入外部生成且范围唯一时，解释为上一组生成结果 `可用`；否则先问清是 Prompt 通过还是成片可用。
- “上一版通过”：按紧邻上下文判断；无法唯一判断时不得猜测。
- “继续”“可以”“不错”：不单独改变任何正式状态。

用户明确确认镜头可用即为状态依据，不要求上传视频。没有视频文件或路径时，`可用结果定位` 留空，并保留用户结论原文。

## 生产对话与记录对话

- 生产对话只维护当前对话内的轻量检查点、输出 Prompt 和继续返修；不写项目进度表。
- 用户说“导出本对话进度包”时，只输出同步包，不构成正式写表授权。
- 用户说“同步本对话进度”或“登记本组进度”时，生产对话仍只输出携带指令原文的同步包和专用记录对话激活指令。
- 专用记录对话加载 `generation-version-log`，核对项目绑定和同步包后更新镜头生产进度表；不改分镜、不改 Prompt、不评价视频。
- 项目结束时，可在各生产对话分别导出同步包，再交给一个专用记录对话统一汇总。不可访问的旧对话标缺失，不虚构。

轻量进度只保存明确状态和版本链；完整 Prompt、参考、参数、失败原因或 QC 证据仍只在用户明确要求详细记录时保存。

同一 Prompt 版本多次抽卡时，轻量进度表只反映当前明确采用或最近明确回报的结果状态，不逐个列出候选。只有用户要求保存多个候选、生成批次或失败原因时，才进入详细生成版本记录；不得为了补全轻量进度而追问用户未要求保存的生成细节。
