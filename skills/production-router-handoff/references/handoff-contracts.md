# 最小交接对象

默认展示边界和严格记录路由见 [轻量生产与严格记录合同](interaction-modes.md)。以下对象可以在后台完整存在；普通生产回合不得因此逐项回显。

## 项目数据绑定卡

提供项目 ID、项目数据根目录、登记表相对路径、资产文件根目录、绑定版本与确认状态。未绑定项目只能生成待确认卡，不能登记正式资产。

## 项目锁定卡

提供全项目不应被下游改变的事实。

## 创作任务单

提供当前单元目标、完成定义、输入版本、允许与禁止变化、输出格式、格式例外、责任 Skill 和预计成果清单。摄影相关任务还要写明三种工作模式之一、全片/场戏摄影卡引用及 Profile 继承或例外状态。每张任务单使用稳定任务 ID 和任务单版本，并在 `tasks/任务索引.csv` 留一行；索引通过 `handoff-task.schema.json` 检查。任务返回的一项或多项成果各自使用稳定成果 ID 与独立版本，写入 `tasks/任务成果索引.csv`，不得把任务单版本复制为成果版本。已入表成果文件保持不可变；文件正文即使只改错字或排版也建立下一成果版本，只有索引中的状态与复核管理字段变化不升级成果内容版本。

完整任务单是后台权威对象。跨对话只先提供 `assets/短交接包模板.md`，其中保存任务 `ID@版本`、完整任务单路径、最小数据切片、唯一目标、一个待决定事项、禁止事项和返回条件。恢复任务时由短包定位完整任务单，不要求用户阅读全部管理字段。

### 专业顾问任务

发现专业事实缺口时，任务单必须从“专业点分级与最小路由、证据核验与结论形成、结论兼容与影响复核”中只选一种。每个顾问问题先归为 `必须准确 / 允许艺术化 / 纯虚构规则`，只设一个主专业领域；次领域最多一个，且必须说明为什么同一裁决无法拆分、次领域怎样实质改变答案。不能用“更全面”同时加载无关专家。

分级任务产生 `CQP-...@v###` 顾问问题包；证据核验任务产生 `CED-...@v###` 证据集和 `CCR-...@v###` 顾问结论卡。三者分别进入任务成果索引，问题包和结论卡的成果类别为“顾问任务”，证据集为“任务数据集”。结论卡必须精确引用问题包和证据集；无可靠来源、冲突未解或适用范围不符时只能写“暂不可裁决”，问题包或暂不可裁决结论不得进入正式创作事实。

美术、资产、调度和镜头只接收当前 `可交接 + 当前有效=是` 的结论卡，并填写 `CCR@版本 + 主张ID／采用字段 + 结论状态 + 适用条件`。顾问成果在长期风格卡中只进入“顾问任务成果引用集合”，不能写入“输入控制卡引用集合”，也不能成为四卡直接上游。危险问题只交付非操作性可见现象、后果、安全禁区和专业复核需求；不得下传可执行步骤、配比剂量、关键参数、采购改装、规避侦测、提高伤害或解除安全装置的方法。

### 场戏剧作任务

任务单只选择“场戏节拍建立”或“剧本／上游换版兼容复核”。进入前必须携带稳定场次 ID、唯一剧本内容版本、可复现原文定位、剧本事实 ID、锁定台词／动作、事件顺序、因果和出入场；重要角色另携带当前有效表演母档最小切片，简单角色跳过时写明理由。影响场戏因果的专业事实只采用当前可交接的 `CCR@版本 + 主张ID／采用字段 + 结论状态 + 适用条件`。

`dramaturgy-scene-beats` 先建立 `BDT-...@v###` 逐节拍权威表，再建立精确引用该表的 `DSB-...@v###` 场戏节拍卡。前者以“任务数据集”、后者以“创作短卡”分别进入任务成果索引；节拍表只引用剧本事实、表演母档与顾问结论，节拍卡引用节拍表，禁止反向引用或合并版本。两项成果都必须保存场次、剧本内容版本、原文定位、锁定保护结论和独立版本。

下游只有两个：`directing-blocking` 只读取 BDT 和 DSB 的成果身份／原文保护门／导演调度最小切片，接收场戏问题、逐拍触发、信息／权力变化、进出状态、不可缺失事件、锁定顺序与因果；`acting-direction` 模式 B 只读取 BDT 和 DSB 的成果身份／原文保护门／场戏表演最小切片，接收逐角色目标、障碍、失败代价、策略、可见行为、潜台词、人物已知／未知信息、进出状态和锁定台词引用。完整编剧／剧作 Profile 在节拍卡交付后关闭；DSB 的 Profile 采用审计区不下传，下游不得收到主体姓名、片名或未采用方法。剧作任务不得预设景别、构图、机位、摄影机距离、焦段、运镜、灯光、剪辑切点或正式 Prompt。

上游换版后由剧作 Skill 返回“继续兼容／需要下一版本／输入不足”。影响分析本身不写成果状态；需要状态变化时使用任务成果索引事务。若用户要求改写锁定剧本，先返回 `script-truth-index` 建立新剧本内容版本，再重新复核节拍，不在旧版本内静默改写。

### 场戏导演调度任务

任务单只选择“场戏调度建立或重设计”或“上游或空间换版兼容复核”。进入前必须有匹配且当前可交接的 `DSB@版本 + BDT@版本`、重要角色当前有效表演母档或简单角色跳过理由、适用于当前场景状态的空间圣经/坐标/锚点；会影响路径、接触或反应时另携带当前生命体运动、VFX时序/接触和顾问结论最小切片。

`directing-blocking` 先建立 `DBD-...@v###` 逐调度单元表，再建立精确引用该表的 `DBC-...@v###` 场戏调度卡。前者以“任务数据集”、后者以“创作短卡”分别进入任务成果索引；DBD 只引用剧作、表演母档、空间、生命体、VFX 与顾问上游，不反向引用 DBC。DBC 以 DBD 为唯一直接成果上游，保存场戏级观众关系、轴线、出入场/画外规则、Profile采用审计、专项场景视图缺口和下游切片。

每个调度单元必须绑定节拍和行动人物，写观众跟随/知情关系、必须看见/暂不可见信息、起止坐标或分区、相对距离、朝向、视线、遮挡/揭示、出入场、移动触发、路径、目的、权力空间变化、轴线/银幕方向和连续性结束状态。移动必须有触发、目的、路径与结束；保持位置也必须有行动目的。故意越轴必须同时写叙事理由和重新建立空间的方法。

导演 Profile 在本阶段重新询问，项目风格意图阶段的选择不自动授权。完整 Profile 在 DBC 交付时关闭；下游只读取 DBD 调度行、DBC 成果身份/保护门/执行切片，不读取审计区或主体姓名、片名、未采用方法。现有场景图片不足时提出 `SV3` 缺口，写相对锚点观察关系、必须可见/遮挡/离画锚点和调度用途，再返回资产计划与场景生产；缺口不是正式资产或已定机位。空间事实未知属于调度事实阻断；空间事实已成立而只缺正式专项视图时可先交场戏表演适配，但该视图登记并完成兼容复核前不得交逐镜设计。

交接先到 `acting-direction` 模式 B，再由调度卡与场戏表演卡共同进入 `cinematography-direction` 场戏摄影约束，最后交 `shot-visual-design` 落地逐镜。导演调度不决定具体焦段、逐镜机位/构图/运镜，不建立表演母档，也不写分镜表。上游换版只返回“继续兼容／需要下一版本／输入不足”；DBD 内容或精确引用变化时先升级 DBD，再升级 DBC，只有 DBC 场戏级内容变化时可只升级 DBC。

### 剪辑与节奏任务

任务单只选择“剪辑节奏审查或重设计”或“上游或分镜换版兼容复核”。进入前必须有当前分镜组草案快照、逐镜稳定ID/版本/首尾状态，以及来源一致的 `DBD/DBC` 调度切片、场戏表演卡和场戏摄影约束卡。剪辑从这些上游已转译成果读取节拍依据，不绕过导演/表演直接读取原始节拍或其Profile审计区。

`editing-rhythm` 先建立 `ERT-...@v###` 逐镜及其出向剪辑关系表，再建立精确引用该表的 `ERC-...@v###` 剪辑节奏卡。前者以“任务数据集”、后者以“创作短卡”分别进入任务成果索引；ERT 不反向引用 ERC。每个当前镜头到下一镜头或场末建立稳定 `CUT` 关系，记录当前/建议时长、可定位切点、情绪/信息/动作/声音理由、动作/声音接点、相邻首尾状态和生成单元决定。

剪辑不按平均时长机械切分，不因对白轮次自动建立正反打。生成单元成员或内部顺序改变、拆分或合并时建立新单元ID并标记旧ID被替代；成员和内部顺序未变、仅整单元重排时保留ID。平台临时最大时长只在C07实际使用时核对，不固化为剪辑永久规则。

完整剪辑 Profile 在 ERC 交付时关闭；下游只读取 ERT修订行、ERC成果身份/保护门/分镜写回切片。`editing-rhythm` 不直接改写分镜，`shot-visual-design` 对每项建议写明采用或不采用理由并建立新分镜组快照，随后 `cinematography-direction` 才执行逐镜摄影审核。摄影审核退回时长/生成单元时重新建立下一ERT/ERC并再次走写回—审核链。

涉及风格锁定时，任务单必须从“项目风格意图基线、四卡专业基线链、P0风格测试与诊断、组合快照与批量放行”中只选一种。四卡链固定为唯一直接上游：项目风格无上游、美术只引项目风格、全片摄影只引美术、项目灯光只引摄影；祖先约束沿链传递，顾问任务成果使用独立字段，不得跨级重复、反向引用或引用尚未形成的评审卡/风格包。Profile只在阶段合同允许的责任Skill中询问和读取，到失效点后只下传已转译的项目规则切片。P0测试必须绑定既有需求槽位、预留正式资产ID、唯一责任资产Skill与单一命题，再走正常资产设计和图片Prompt流程；测试通过不等于登记。每个P0任务只使用业务状态为“待执行/测试中”且任务成果为“可交接+当前有效”的评审版本中，绑定本测试ID和预留ID的临时短执行切片；四卡确认生效只允许进入这种受控验证，不放行批量生产。测试输入、状态或结论变化时建立下一评审成果版本。评审卡和组合快照各自使用稳定成果 ID/独立成果版本进入任务成果索引；组合快照只组合四张当前有效基线、业务状态为“已通过”且必做测试和冲突门均通过的当前评审卡，以及下游短切片，不进入长期基线索引。来源卡替代或失效后通过影响分析，在一次事务中把受影响的当前评审和旧快照标记待复核且不得用于新任务。普通批量资产任务必须携带业务状态为“可用于批量生产”且任务成果为“可交接+当前有效”的风格包精确版本及对应切片，不能继续使用P0临时切片。

逐镜交接遵循单写入规则：`editing-rhythm` 只写 `ERT/ERC` 修订提案，`shot-visual-design` 生成并修改分镜表，`cinematography-direction` 只返回逐镜摄影审核卡。剪辑写回完成后才开始摄影审核；审核结论为摄影技术修正时，仍由镜头设计写回并重新做结构检查。

### Seedance 2.0 视频 Prompt 任务

任务单只选择“单镜头正式Prompt装配”“镜头组正式Prompt装配”或“Prompt层返修或上游换版重装配”。进入前必须有当前生成单元身份/成员/内部顺序、剪辑写回和逐镜摄影审核完成的分镜快照、正式可调用媒体、表演/灯光/声音/VFX/顾问最小切片及生成就绪结论。Prompt阶段不询问或读取任何完整Profile。

`video-prompt-production` 先建立 `VRM-...@v###` 参考映射数据集，再建立 `VPR-...@v###` 正式Prompt交付卡。VRM逐行保存参考顺序、平台引用名、唯一用途、允许/禁止继承、适用镜头、当前服装/状态、平台处理方式与本次能力核对；每名人物只允许一张匹配状态的五视图总览卡，动作/运镜视频不得继承人物身份、服装、场景或光线。VRM以“任务数据集”、VPR以“Prompt”分别进入任务成果索引，VRM不得反向引用VPR。

单镜正文按“参考与风格→空间与摄影→第一帧→动作/表演→物理接触→台词/声音→光影→稳定结束→最小禁项”装配。镜头组另写总时长、镜头数、逐镜完整执行块和CUT接点；逐镜时长之和必须等于总时长，不得把镜头组写成一镜到底。正文只用平台引用名，不复制内部ID、版本、路径、Profile或管理语言。

Prompt表达修订只升级VPR；参考映射改变先升级VRM；镜头设计改变先返回上游建立新分镜版本。生成单元拆分/合并、成员或内部顺序改变时建立新的生成单元、VRM与VPR身份。当前Seedance能力在使用时核对，不把临时限制写成永久规则。正式节点只由用户手工复制到外部平台；系统不得提交、查询、下载或声称已上传。

涉及正式镜头生产时，任务单携带分镜组 ID/版本、镜头 ID/版本集合、生成单元 ID 和正式 Prompt ID/版本。状态解释与版本递增使用 [分镜、正式 Prompt 与可用镜头的版本状态规则](shot-prompt-version-state.md)。

涉及表演时，任务单选择“角色表演母档”或“场戏表演适配”之一，并携带表演母档 ID/版本。重要角色没有当前有效母档时先建立母档；简单角色跳过时写明理由。母档与场戏卡都由 `acting-direction` 唯一写入，不进入资产登记。母档版本的确认生效和表格更新使用[表演控制对话激活指令](../../acting-direction/assets/表演控制对话激活指令模板.md)在项目专用对话中完成；普通场戏对话只读当前有效母档。

涉及发声角色时，任务单选择“角色声音身份建档”“独立声音候选生产”或“场戏声音适配”之一，并携带声音身份卡 ID/版本。实际音频候选另携带需求槽位、预留正式声音资产 ID、来源/授权和外部声音模型或服务决定；场戏适配另携带正式声音资产 ID/版本与调用方式，或用户确认的临时声音原文。身份卡不进入资产登记；临时镜头内声音只有被单独形成音频文件并收到明确登记指令后，才另走登记申请。

涉及世界资产时，任务单必须写资产工作模式、正式资产类型和唯一责任生产 Skill。明确单一类别使用“直接分类生产”，交人物、场景、道具/载具、生物/怪物或VFX对应 Skill；只有混合或类别不清时才使用“世界资产二级路由”并交 `world-asset-production`，且该路由任务的返回物只能是拆分、依赖和顺序。组合候选必须携带全部已登记基础资产精确版本，不能把未登记的多个身份一次生成后再补依赖。

人物任务还必须从“选脸与脸母图、五视图基础卡、服装妆造版本、剧情状态版本、人物—道具交互、版本兼容复核”中选择一个工作模式。选脸槽位和五视图槽位使用不同预留正式资产 ID；五视图任务携带已登记脸母图精确版本，后续变体/交互携带正确父人物版本和全部附加资产版本。未完成专用登记回执时不得把上一层候选写成正式输入。

场景任务还必须从“场景母图、空间圣经建档或更新、预制剧情视图、专项或英雄视图、场景状态变体、光影状态、版本兼容复核”中选择一个工作模式。场景母图另写“默认3/4空间母图”或用户明确要求的“剧照式母图”；后者必须携带用户原文。视图、场景状态和光影状态分别使用独立预留 ID，并携带已登记母图/状态/视图精确版本；空间圣经、锚点表和投影表由场景空间Skill形成任务数据，光源地图由灯光Skill形成任务数据集，它们都不进入正式图片资产表。

灯光任务必须从“项目灯光长期基线、场景光源地图、人物受光设计、多视图灯光继承、镜头灯光短执行”中只选一种。项目基线只把全片摄影规则作为直接上游长期卡；光源地图单向精确引用空间圣经/锚点和光影状态，空间圣经不得回引地图；人物、多视图和镜头短卡逐层引用当前地图。换摄影机不改变世界光场，时间、天气、灯具开关、主光或VFX阶段改变时另建光影状态。所有灯光短卡进入任务成果索引，不进入正式资产登记。

道具/载具/图案文字任务还必须从“基础对象、对象状态变体、图案文字母版、对象表面应用、对象装配、交互接口定义、载具舱内接口交接、版本兼容复核”中选择一个对象工作模式。产图任务另写交付形态。表面应用携带一个已登记同类型父对象和全部图案文字母版；装配携带主承载对象与全部已登记部件；交互接口与舱内接口只作为任务数据交接，不进入正式图片资产表。

生物/怪物任务还必须从“基础形态、结构变体、生理状态变体、持物穿戴组合、运动约束定义、转化阶段拆分、版本兼容复核、登记回执绑定”中选择一个生命体工作模式。产图任务交付一张生命体总览卡；结构变体携带一个已登记基础/上一结构形态，状态变体携带状态发生前的已登记生命体，组合携带生命体父版本及全部已登记道具/载具。形态定义、解剖锚点和运动约束集只作为任务数据交接；运动约束集必须绑定预留/正式生命体版本。登记回执产生正式版本后，登记对话不代写任务数据；路由器应建立“登记回执绑定”任务，完成生产卡、解剖表和运动表绑定，才能进入下游。转化中可停留且跨镜复用的阶段另建结构变体，单镜过渡交 VFX 与正式 Prompt。

VFX任务还必须先写“建立VFX图片资产”或“单镜执行交接”，再从“视觉母版、状态/强度变体、接触参考、时序与接触定义、单镜执行交接、版本兼容复核、登记回执绑定”中选择工作模式。图片任务只交付一张代表阶段参考；状态携带一个母版/上一状态，接触参考携带VFX父版本和全部已登记来源/接触实体。VFX定义、行为分阶段设计板、时序集和接触集只作为任务数据；登记回执后另建绑定任务，只把正式版本写入生产卡及本候选实际持有的数据行，沿用父数据集时不得改写原绑定。单镜效果不建假图片资产，但必须携带可见阶段、时长、来源、接触、受光、残留和稳定结束状态。

产图任务在责任资产 Skill 完成当前生产卡后，另写图片工作模式与稳定 `图片PromptID@版本`，交 `image-prompt-production` 装配。首次交付为 `v001`；正文、参考映射、平台设置、上游生产卡或正式依赖发生可复现变化时递增，相同输入原样重跑不升级。图片 Prompt 写入任务成果索引，不进入正式资产登记表；结果必须返回原责任资产 Skill 复核。图片 Prompt Skill 收到明确登记措辞时也只能把用户原文、唯一候选和交付卡返回责任资产 Skill，不能自行输出登记申请。

## 镜头生产进度同步包

生产对话只输出当前对话可确认的 Prompt 与生成结果状态，不直接写表。用户明确要求同步时，交接包还应携带同步指令原文和[镜头进度记录对话激活指令模板](../../generation-version-log/assets/镜头进度记录对话激活指令模板.md)；专用记录对话核验后写入绑定项目的镜头生产进度表。

## 严格记录交接

正式资产登记、项目创作控制版本事务、镜头进度/详细失败记录、正式就绪审计和正式视频 QC 都属于严格记录。生产对话只输出对应申请或同步包、用户授权原文和短激活指令；专用对话重新读取项目绑定卡后才可写权威数据。普通生产反馈、候选调整、即时 QC 和内部就绪检查不能自动切换严格记录模式。

## 登记申请

创作 Skill 只能输出候选结果说明；登记申请不是批准。必须等待用户明确登记命令。申请至少携带项目 ID、绑定卡路径、预留正式资产 ID、用户指定资产名、唯一候选、用途和登记指令原文；正式写表由独立登记对话完成。

专用登记对话的激活指令使用 `approval-asset-registry/assets/登记对话激活指令模板.md`，要求加载 `approval-asset-registry`，读取指定绑定卡和登记申请，只执行核验、写表、可调用映射与回执；禁止继续资产创作或修改候选。

## 可调用资产切片

只列当前任务实际需要、在正式资产登记表与可调用资产表均为 `可调用`，且资产状态传播表没有未处理依赖冲突的正式资产 ID、版本、文件、平台引用名和用途。每个派生资产同时携带生产依据和当前兼容依赖；状态为待复核、停用或历史时禁止下传。

## 创作控制版本切片

长期项目基线、表演母档与声音身份只列 `已生效 + 当前有效=是` 的稳定卡片 ID、项目版本、适用范围、源定义引用和Profile引用。中央源/Profile与项目卡版本独立；不得用中央目录“最新版”静默替换项目固定引用。Profile任务另须填写允许阶段、本体失效点和唯一可跨阶段继承的项目规则切片；同一Profile从一个允许阶段进入另一个阶段也必须重新取得用户选择。场戏节拍、调度、表演、摄影约束、逐镜摄影审核、剪辑和声音短卡由任务成果索引按稳定 ID/独立版本追踪，只有 `可交接 + 当前有效=是` 的精确版本可以下传。
