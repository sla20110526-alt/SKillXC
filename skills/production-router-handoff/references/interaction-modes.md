# 轻量生产与严格记录合同

## 1. 两种模式

### 轻量生产模式（默认）

用于创作问答、方案选择、候选比较、Prompt 交付和返修。后台仍建立完整任务单、稳定 ID/版本、任务索引、任务成果索引和校验依据，但当前对话只显示：

1. 当前步骤与本轮唯一目标；
2. 已经确认、且本次决定真正需要知道的约束；
3. 会改变方向或阻断下一步的必要缺口；
4. 候选、Prompt、诊断或其他本轮创作结果；
5. 现在需要用户明确回答的一个决定点，必要时合并为同一组互斥选择；
6. 下一步。只有切换对话、恢复、同步或对象容易混淆时，才加一行恢复锚点。

不要在普通回合逐项展示完整任务单、Schema、CSV 行、索引字段、绝对路径、内容指纹、全部资产表、完整 Profile 或后台检查日志。用户明确要求查看依据时，提供相关局部，不倾倒整个项目数据。

### 严格记录模式（按明确请求进入）

只在用户明确要求下列操作时进入相应专用数据对话：

- 项目绑定、正式资产登记或待复核解除：`approval-asset-registry`；
- 项目长期创作控制卡、表演母档或声音身份的版本/生效事务：`creative-control-versioning`；
- 镜头进度同步、详细生成版本、失败原因保存：`generation-version-log`；
- 保存正式连续性/就绪审计：`continuity-readiness-audit` 的严格审计记录模式；
- 保存正式视频 QC 或项目复盘记录：`video-qc-review` 的正式记录/项目复盘模式。

生产对话收到授权时，只冻结当前对象和用户原文，输出相应最小申请/同步包与短激活指令；不在原生产对话直接写登记表、进度表、失败记录、控制索引、正式审计表或 QC 表。

## 2. 共享硬规则

轻量只改变“向用户展示多少”，不降低生产约束。两种模式都必须遵守：

- 先核对项目 ID、绑定卡和数据根目录；没有具体项目时不虚构数据；
- 只引用精确且当前有效的控制卡、任务成果和正式资产版本；
- 只有明确的登记措辞触发登记申请，失败候选不登记，失败原因不自动记录；
- Profile 只在责任阶段询问并经用户选择，不批量加载；
- 分镜、Prompt 放行、生成结果可用和正式资产登记保持不同状态；
- 正式 Prompt 前必须完成连续性/就绪门；轻量模式可以只显示 `可继续 / 有条件继续 / 暂停` 和阻断缺口，但后台检查不能省略；
- 结构检查不能替代用户批准、业务复核或创作质量判断。

## 3. 完整后台包与短交接包

每个跨 Skill 或跨对话任务都保留完整任务单；短交接包只做入口，不复制完整后台字段。短包必须包含：

- `项目ID`、`任务ID@任务单版本`、当前阶段、唯一责任 Skill；
- 完整任务单路径；
- 本次允许读取的最小数据切片及精确版本；
- 当前唯一目标、用户尚需决定的事项、禁止事项和返回条件。

恢复时先读短包，再按其中路径读取完整任务单和列出的最小切片。短包没有列出的 Skill、Profile、项目目录或数据不得自行扩展；发现需要扩展时返回总路由说明原因并重新征得用户确认。

短包是完整任务单的派生投影，文件名绑定同一 `任务ID@任务单版本`，例如 `TASK-001@v003-短交接包.md`；任务单升级时重新生成对应短包，旧短包只用于恢复旧任务版本。短包没有独立业务版本、不能覆盖完整任务单，也不单独冒充任务成果。

## 4. 轻量回显顺序

使用 `assets/轻量生产回显模板.md`，按当前回合删去空段。优先直接给创作结果；只有缺口会改变结果时才先问。一次不要让用户同时处理后台管理决定和创作决定。

确认后只回显一行状态，例如：

`已确认：候选继续调整；未登记。下一步：按你的修改方向重做。`

需要恢复锚点时使用：

`恢复锚点：TASK-…@v…｜短包：项目内相对路径`

恢复锚点不是要求用户检查的字段，也不在每轮重复。
