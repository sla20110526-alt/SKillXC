# 生产路由与交接

这是路由器，不承担专业创作。

## 交互模式门

先读取 [轻量生产与严格记录合同](references/interaction-modes.md)。默认使用轻量生产模式：完整任务单、稳定 ID/版本、任务/成果索引和校验仍在后台形成，但普通生产回合使用 `assets/轻量生产回显模板.md`，只显示当前目标、必要缺口、创作结果、一个决定点和下一步。不要把完整任务单当成对话回复。

只有用户明确要求绑定、登记、同步、保存失败原因、正式审计或复盘记录时，才进入相应严格记录对话。生产对话只输出冻结范围后的最小申请/同步包和短激活指令，不直接写权威表。

## 强制确认门

在调用任何通用创作 Skill 前：

1. 告知用户准备调用的 Skill、原因、所需输入和预期产物。
2. 询问是否确认使用。
3. 得到明确确认后再加载。

严格按 `film-profile-library/references/phase-routing.md` 进入 Profile：导演在“项目风格意图基线”和“导演与人物调度”分别询问，前一阶段选择不自动授权后一阶段；美术、编剧/剧作、剪辑只在各自责任阶段询问。列候选时同时显示成熟度和证据边界，不默认选择。摄影 Profile 只在 `cinematography-direction` 的“全片摄影基线”模式常规询问一次；场戏摄影约束、镜头视觉设计、逐镜摄影审核和 Prompt 生产均继承摄影规则卡，不重复询问或读取完整 Profile。只有用户明确要求摄影重释，或现有规则无法完成已成立的场戏风格断裂时，才先说明冲突与最小范围，取得本次用户确认后建立限时场戏例外。

## 路由原则

- 每个任务只加载完成它所需的最少 Skill 和最小数据切片。
- 完整任务单是后台权威交接对象；对话切换或恢复只先交付 `assets/短交接包模板.md`。短包必须指向完整任务单，不得复制全部管理字段，也不得成为第二份权威任务单。
- 资产类型明确且单一时直接提出对应分类生产 Skill，不强制加载 `world-asset-production`；混合、类别不清或生产顺序冲突时才先确认并加载该二级路由。它只返回拆分与路由，不与分类生产 Skill 同时写资产设计。
- 不把整个剧本、完整资产总表或完整 Profile 库塞进每个对话。
- 控制 Skill 只管理事实和状态；创作 Skill 只产生候选方案。
- `tasks/任务索引.csv` 只负责任务调度；没有专用权威索引的任务产物统一进入 `tasks/任务成果索引.csv`。一项任务可以产生多项独立成果，任务状态不得代替成果状态。
- Prompt 装配 Skill 不重新导演；登记 Skill 不修改创作结果。
- 上游资产改变时，把任务退回真正负责的 Skill，不在下游打补丁。
- 登记新资产版本后读取资产状态传播表；任务切片不得包含 `待复核/停用/历史` 资产。待复核资产先交责任生产 Skill 比较，再由用户明确决定沿用或重做；只有 `approval-asset-registry` 可写状态和当前兼容依赖。
- 项目长期创作基线、表演母档和声音身份卡只读取 `已生效 + 当前有效=是` 的精确项目版本。风格四卡只采用唯一直接上游链，顾问成果独立引用；P0评审和风格包只进入任务成果索引，旧四卡组合对应的可交接快照不得用于新任务。中央源/Profile版本与项目版本分开：项目只调用不升级源文件；专业Skill产出新草案，`creative-control-versioning` 是项目控制索引版本与状态的唯一写入者。
- 分镜表只允许 `shot-visual-design` 写入；`cinematography-direction` 在逐镜阶段只输出审核卡，由镜头视觉设计写回不改变叙事功能的技术修正。
- 项目灯光基线、场景光源地图、人物受光、多视图灯光继承和镜头灯光短执行只由 `lighting-direction` 写入。场景空间任务只能提供光源/控光空间锚点并引用当前地图；Prompt Skill 只翻译当前可交接灯光短卡，不临时发明新光源。
- 分镜、正式 Prompt 与可用镜头遵循 [版本状态规则](references/shot-prompt-version-state.md)。Prompt 放行和生成结果可用是两个状态；不得用一个“通过”覆盖两者。
- 生产对话只维护轻量检查点并继续生产，不写镜头生产进度表。只有用户明确要求同步时才输出同步包和专用记录对话激活指令，由 `generation-version-log` 写绑定项目的进度表。
- 重要角色首次进入 `dramaturgy-scene-beats` 与 `directing-blocking` 前，路由 `acting-direction` 模式 A 建立或核对当前有效的角色表演母档；剧作、导演、镜头或 Prompt Skill 不得临时补写。简单角色可在任务单写明跳过理由。
- 有台词、独白或持续画外发声且需要跨镜声音连续的角色，在首次场戏声音适配前路由 `sound-voice-direction` 模式 A 建立或核对当前有效的声音身份卡；需要独立参考音频时再进入模式 B。模式 C 发现没有正式声音资产时，必须让用户选择返回模式 B 或为本生成单元使用 Seedance 临时镜头内声音，未选择不得进入正式 Prompt。
- 首次进入具体项目时核对项目 ID、项目数据根目录和 `项目数据绑定卡.md`；未绑定时路由到 `approval-asset-registry` 建立待确认绑定卡，不在中央 Skill 仓库创建项目数据。

## 后台完整任务单必须包含

- 项目、阶段、当前目标和完成定义
- 项目 ID、项目数据绑定卡路径与版本
- 任务索引与任务成果索引的绑定卡相对路径
- 当前需求槽位或镜头范围
- 涉及资产时填写资产工作模式（不适用/直接分类生产/世界资产二级路由）、正式资产类型和唯一责任生产 Skill；二级路由任务另写待拆分身份与返回 `asset-demand-plan` 的条件
- 人物任务另填人物资产工作模式和父/附加资产精确版本；脸母图与五视图卡必须来自两个预留正式资产 ID，五视图、服装、状态和交互任务不得越过未登记父层
- 场景任务另填场景空间工作模式、母图构图子模式、空间圣经版本和空间依据/附加资产精确版本；场景视图、状态和光影不得越过未登记空间父层
- 道具/载具/图案文字任务另填对象工作模式、交付形态、对象/文字定义版本和父/附加资产精确版本；表面应用、装配及主体交互不得越过未登记对象或图案母版
- 生物/怪物任务另填生命体工作模式、形态定义版本、父/附加资产精确版本和运动约束集版本；结构、状态与组合不得越过未登记父形态或对象，转化过渡不得伪装成静态形态资产；登记完成后另以“登记回执绑定”模式把正式版本写回生命体任务数据
- VFX任务另填独立资产判定、VFX工作模式、定义/时序/接触集版本和父/附加资产精确版本；状态与接触不得越过未登记VFX父版本或接触实体，单镜效果不得伪造正式图片资产；登记完成后以“登记回执绑定”模式写回VFX任务数据
- 涉及镜头时填写分镜组 ID/版本、镜头 ID/版本集合、生成单元 ID；涉及正式 Prompt 时再填写 Prompt ID/版本
- 涉及角色表演时填写表演工作模式、表演母档 ID/版本，或简单角色跳过母档的理由
- 涉及发声角色时填写声音工作模式、声音身份卡 ID/版本、正式声音资产 ID/版本或临时声音决定；无发声角色时明确写“无需独立声音资产”
- 已确认输入及版本
- 正式资产版本必须来自可调用表，并核对资产状态传播表无未处理的待复核依赖
- 必须继承、允许变化、禁止变化
- 需要加载的 Skill 与已确认 Profile
- 当前已生效创作控制卡ID/版本、源定义引用与Profile引用；没有适用长期卡时写明理由
- 美术任务另填美术工作模式（不适用/项目LookDev长期基线/资产类别执行交接/场次美术状态适配/美术规则兼容复核）、目标资产类别或场次范围、当前美术LookDev基线ID@版本和美术四层边界；资产类别执行包不得代替P0评审或风格包放行
- 摄影任务的工作模式、摄影规则卡引用与 Profile 继承/例外状态；非摄影任务写“不适用”
- 灯光任务另填“灯光工作模式”“当前项目灯光基线ID@版本”“场景光源地图ID@版本与光影状态ID”“人物受光卡ID@版本集合”“多视图灯光继承卡ID@版本”“镜头灯光短执行卡ID@版本”；非灯光任务写“不适用”
- 输出格式
- 用户指定的格式例外；没有时写“无”
- 明确禁止的越权行为
- 下游接收者和返回条件

## 数据交接门

项目数据默认遵循 [项目数据三层契约](references/project-data-contract.md)：Markdown 卡片负责确认和摘要，CSV 负责多行记录，JSON Schema 负责结构检查。任务单由 `tasks/任务索引.csv` 追踪；没有专用权威索引的创作短卡、Prompt、任务数据集、组合快照和审查记录由 `tasks/任务成果索引.csv` 追踪，规则见 [任务成果索引](references/task-artifact-index.md)。

下游交接前，先用 `scripts/update_task_artifact_index.py check` 检查任务—成果引用、版本链、路径、指纹、当前版本唯一性，以及风格评审/快照所引四卡仍是当前组合，再使用 `scripts/validate_project_data.py` 检查本次涉及的 CSV 与 Schema；真实项目必须传入项目 ID，并把 `数据校验报告.md` 写到绑定项目数据目录。只有成果为 `可交接 + 当前有效=是` 才能作为当前任务产物被下游精确引用。结构通过不代表资产批准、Prompt 放行、生成结果可用或其他业务引用有效。

## 输出

后台使用 [交接对象](references/handoff-contracts.md)、`assets/创作任务单模板.md`、`assets/任务索引模板.csv` 与 `assets/handoff-task.schema.json` 生成完整 Markdown 任务单和任务索引行；面向用户或新对话只输出 `assets/轻量生产回显模板.md` 或 `assets/短交接包模板.md`。任务返回后，责任 Skill 使用 `assets/任务成果索引说明卡模板.md`、两份任务成果操作 JSON、`assets/任务成果索引模板.csv`、`assets/task-artifact.schema.json` 和 `scripts/update_task_artifact_index.py`，一次原子事务写入一项或多项成果。信息不足但不影响方向时在后台标缺口，只向用户显示与当前决定有关的部分；缺口会改变创作方向时暂停并只问该决定点。
