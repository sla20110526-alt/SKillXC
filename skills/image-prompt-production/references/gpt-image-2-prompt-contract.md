# GPT Image 2 图片 Prompt 合同

## 两层交付

图片生产必须分开：

1. **交付卡**：保存项目、任务、版本、正式依赖、参考映射、平台设置、检查点和返工节点。
2. **Prompt 正文**：只保留模型需要执行的可见目标和高风险约束，可完整复制到 GPT Image 2。

Prompt 正文不得包含图片 Prompt ID、任务状态、项目路径、Schema、登记方式、Profile 文件名或“请读取上游卡”等管理语言。

## 输入优先级

从高到低使用：

1. 用户在当前任务中的明确锁定与调整方向
2. 当前任务单和当前版本的责任资产生产卡
3. 已登记父资产及附加资产精确版本
4. 当前有效风格、美术、灯光短执行切片与顾问结论
5. 用户提供但尚未登记、且用途已明确的参考图

低优先级输入与高优先级事实冲突时暂停并指出冲突，不平均融合。任何参考都必须写“只继承什么”和“禁止继承什么”；同一图承担多个职责时，这些职责必须相容。

## 最小参考负载

- 只加载完成本轮任务必需的参考，不因“可能有帮助”堆叠图片。
- 参考编辑必须有一个明确主底图。其他参考不能覆盖主底图负责的身份或结构。
- 正式父资产优先于未登记参考；附加资产只提供已登记的对象身份、图案、材质或接触结构。
- 人物变体通常只需要正确父人物卡；发生过脸漂移或用户明确要求时，才增加脸母图并限定为“仅身份”。
- 场景新视图以空间依据图为主；补充视图只提供对应锚点，风格和光影参考不得改空间。
- 平台实际参考容量不足时返回上游拆成阶段，或请用户选择最低优先级参考；不得静默丢弃父资产或关键依赖。

## 正文骨架

按任务需要写成自然、完整、具体的语言，顺序如下：

1. 本次唯一任务和资产身份
2. 参考图编号、唯一用途和优先关系
3. 主体/空间的可见身份与结构
4. 排版、视角、透视、占比、可见面和背景
5. 材质、表面、尺度、状态与接触
6. 光源、受光、反射、阴影和曝光
7. `PRESERVE EXACTLY`
8. `CHANGE`
9. `ONLY CHANGE`
10. 本任务最容易漂移的少量禁项

“保持一样”“高质量”“8K”“电影感”“照片级”“真实物理”“解剖正确”不能代替具体的脸部锚点、锚点位置、部件数量、连接、承重、材料层级或光源方向。

## 新生成与参考编辑

### 新生成

仍需写三类变化合同：

- `PRESERVE EXACTLY`：剧本事实、资产身份锚点、版式和短执行卡中不得漂移的项目
- `CHANGE`：本轮允许模型求解的明确视觉字段
- `ONLY CHANGE`：相对已确认设计，本轮唯一需要产出的视觉决定集合

它们不是假装存在父图，而是限制模型不要顺带改写已确认设计。

### 参考编辑

明确写出：

- 哪一张是主编辑底图
- 保持到可识别精度的身份、几何、结构、空间、图案和光源项目
- 被允许改变的部位、范围、侧别、程度、材质和状态
- 未列入 `CHANGE` 的内容全部保持不变

若必须改变主底图的身份或结构角色，这不是“只编辑”，应返回责任资产 Skill 重新定义任务。

## 类别切片

### 人物

按脸部身份、身体比例、妆造/服装、剧情状态、交互、版式顺序写。五视图总览卡必须是同一人物、同一时刻和同一状态；左三分之一为正面与同侧 3/4 侧面特写，右三分之二为正面、同侧纯侧面、背面全身，三个全身均保留完整头手脚。

### 场景

按场景身份、摄影机世界位置与朝向、视场/透视、锚点投影、遮挡/画外、未知区、材质与光源地图写。摄影机变化只改变投影，不搬动门窗、家具、树山或太阳。

### 道具、载具与图案文字

按轮廓、尺度、部件数量、连接、方向、功能、材质、交互锚点和交付版式写。图案文字逐字给出内容、大小写、标点、行列、方向和应用区域；生成后必须另做逐字符/图形检查。

### 生物与怪物

按轮廓、质量分布、支撑、肢体/器官数量、连接、关节范围、固定不对称、表皮和静止姿态写。静态资产只展示一个形态或稳定阶段；运动约束用于姿态可行性，不把完整动作时间轴写进图片。

### VFX

按来源、代表阶段、主体轮廓、材料层级、颗粒尺度、密度/透明度、颜色、自发光/受光、尺度、接触和背景可分离性写。接触参考同时锁定父 VFX 与接触对象精确版本；静帧不承诺完整传播时序。

## 平台设置

交付卡只记录当前界面能够确认的选项：

- 模型：GPT Image 2
- 操作：新生成 / 参考编辑
- 当前实际可选的画幅或尺寸
- 参考图片编号与加载顺序
- 用户明确要求且当前平台支持的透明背景或其他选项

不知道或界面不可确认的参数写“当前不可确认”，不编造采样器、种子、权重、分辨率或参考上限。

## 版本与候选

- Prompt 内容、输入版本、参考映射或设置改变：同一图片 Prompt ID 递增版本。
- 完全相同的 Prompt 与输入再次生成：版本不变。
- 资产角色、需求槽位或预留资产 ID 改变：建立新的图片 Prompt ID。
- Prompt 版本只说明“模型收到了什么”，不说明“生成结果是否成功”。
- 候选是否符合资产设计由责任资产 Skill 检查；候选是否登记只由用户明确指令启动。

## 回流判断表

| 可见问题来源 | 处理节点 | 图片 Prompt 版本 |
|---|---|---|
| Prompt 漏译、歧义、冲突、参考职责不清 | `image-prompt-production` 完整重写 | 递增 |
| 人物/场景/对象/生物/VFX设计本身需改 | 对应责任资产 Skill 先升级生产卡 | 随新上游版本递增 |
| 长期美术、材质或灯光规则需改 | 对应专业 Skill 与项目版本流程 | 生效后递增 |
| Prompt 正确、模型随机漏执行，原样再跑 | 原 Prompt 再生成 | 不变 |
| Prompt 正确，但用户要求加强表达或改变参考顺序 | `image-prompt-production` 完整重写 | 递增 |

不在旧 Prompt 末尾连续叠加“再注意”“一定不要”等补丁；每版都必须是可以独立替代上一版的完整正文。
