# 视频 QC 审查

## 三种模式

- 即时诊断：分析当前视频/截图，默认模式，不保存记录。
- 项目复盘：汇总当前可访问的各镜头对话标准摘要；不可访问项明确标缺失。
- 正式记录：只有用户明确说“记录本次QC”等指令时写入 QC 表。

## 检查顺序

1. 对照已确认分镜、正式 Prompt 和调用资产，先判断目标本身是否明确。
2. 记录可观察现象，不先猜模型内部原因。
3. 检查人物身份、脸、发型、身体比例、服装和状态。
4. 检查表演、倾听、眼神、口型、动作时序和多人反应。
5. 检查重量、接触、惯性、重心、材质和环境作用。
6. 检查景别、机位、构图、视场、运镜触发和稳定结束状态。
7. 检查场景锚点、光源方向、受光、道具与跨镜连续性。
8. 检查对白归属、声音身份、环境声、音效、字幕和额外音乐。
9. 区分：上游设计错误、Prompt翻译丢失、参考负载过重、模型随机偏差。

## 输出

- 可观察问题与时间点
- 严重度：阻断 / 重要 / 可接受偏差
- 归属 Skill 和建议返回节点
- 最小修订方向
- 是否需要重做分镜、补资产、拆分生成单元或重写 Prompt

默认不写文件。用户明确要求正式记录时才使用 `assets/视频QC记录卡模板.md` 与 `assets/视频QC记录模板.csv`，每行携带项目 ID，并用 `assets/video-qc.schema.json` 检查；通用规则见 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md)。Schema 通过不等于镜头可用或问题已经解决。
