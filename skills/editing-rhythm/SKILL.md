# 剪辑与节奏

剪辑先判断观众何时已经接收信息、动作何时真正完成、反应何时开始产生意义，再决定是否切换。节奏不是平均分配秒数，也不是为对白自动补齐正反打。

## 唯一职责与工作模式

`editing-rhythm` 是剪辑节奏数据集与剪辑节奏卡的唯一写入者，只提出节奏修订，不直接改写分镜表、镜头设计或正式 Prompt。每张任务单只选择一种模式：

- `A｜剪辑节奏审查或重设计`：审查初版分镜、处理用户认为节奏或镜头关系错误的问题，或接收逐镜摄影审核退回的时长/生成单元问题，建立新的 `ERT` 数据集和 `ERC` 卡。
- `B｜上游或分镜换版兼容复核`：比较新旧分镜、调度、表演或摄影约束，只返回 `继续兼容 / 需要下一版本 / 输入不足`；影响分析本身不改成果状态。

## 进入门

1. 先由 `production-router-handoff` 说明通用 Skill 的用途、输入和产物并取得用户确认。
2. 本阶段单独列出剪辑 Profile 候选、代表作品、成熟度和证据边界，询问是否调取。未明确选择时只用已确认的通用方法，不继承过去项目或其他阶段的选择。
3. 默认最多一个主 Profile；补充 Profile 必须另行确认唯一问题、作用范围和失效点。完整 Profile 只用于本次节奏判断，`ERC` 交付后关闭。
4. 以下必要输入必须属于同一项目且精确版本可定位，否则不开始模式 A：
   - `shot-visual-design` 当前分镜组快照、分镜设计卡和逐镜版本集合；
   - 匹配的 `DBD@版本 + DBC@版本` 调度执行切片与场戏表演卡；
   - 当前场戏摄影约束卡；
   - 锁定对白、画外声音事件及当前分镜中的第一帧/稳定结束状态。
5. 调度、表演、摄影来源必须与分镜设计卡一致。剪辑只读取这些上游已转译的节拍来源，不绕过上游直接读取节拍成果、原始剧作 Profile 或 DSB 的 Profile 审计区。

## 最小输入切片

- 从分镜只读取镜头稳定 ID/版本、当前顺序、时长、叙事任务、观众视点、人物动作/表演、原台词、声音事件、第一帧、稳定结束状态、剪辑接点和生成单元。
- 从调度与表演只读取与切点相关的移动触发/结束、视线、遮挡、动作准备—执行—恢复、停顿、听见—判断—反应和不可打断动作；不得重写位置、动作目的或表演策略。
- 从摄影约束只读取运动完成所需时间、方向/轴线、曝光/焦点可读性和物理可执行边界；不得在本阶段加载摄影 Profile 或重新设计机位。
- 声音依据只限剧本锁定台词、已成立画外声音事件、表演停顿和当前镜头声音意图。可以提出提前进入、延后离开、静默或环境延续等接点，不建立声音身份、不选择正式/临时声音来源，也不冒充后续场戏声音卡。

## A｜剪辑节奏审查或重设计

### 1. 先判定镜头是否有新增价值

逐镜写出它新增的情绪、信息、动作阶段、空间定位或人物反应。镜头不能只因对白轮到某人而存在；反应镜必须提供新的判断、权力变化或信息差。功能重复时提出删并或返回 `shot-visual-design`，不得自行删除镜头。

### 2. 决定顺序和时长

1. 顺序服从锁定事件因果、观众知情关系、动作连续和信息揭示，不按素材清单顺序机械排列。
2. 时长从可观察过程反推：信息读清、动作准备/执行/结果、听见/判断/反应、必要停顿和稳定结束状态分别需要多少时间。
3. 不使用某位大师、某类型或平台的平均镜头长度代替逐镜理由；同一场可以有明显不等长镜头。
4. 既定时长装不下动作、运镜、VFX必要阶段或可读反应时，提出延长、拆镜或拆生成单元，并把具体镜头实现返回唯一责任 Skill。

### 3. 为每条边界建立切点

每个当前镜头到下一镜头或场末建立稳定 `CUT-###` 剪辑关系，至少写清：

- 切点时机：相对于台词词句、动作阶段、视线变化、信息揭示、声音事件或稳定停留的可定位瞬间；
- 理由类型：`情绪 / 信息 / 动作 / 声音 / 组合 / 场末`；
- 具体理由：切早、切中或切后怎样改变观众的预期、理解、冲击或余韵；
- 动作接点和声音接点；
- 当前镜头离开状态、下一镜头进入状态及其匹配结论。

邻接双方改变时必须建立新的 `CUT` ID，旧关系不得被重用于另一对镜头；只调整同一关系的时机或理由时保留 ID 并升级 `ERT` 版本。

### 4. 设计动作、声音与相邻状态

- 动作接点说明是否切在准备、动作中、接触、结果或恢复，并核对手脚位置、道具接触、视线、银幕方向和速度趋势。
- 声音接点说明同期保持、声音先入、声音延出、画外延续、环境连续或刻意静默，以及它服务的信息/情绪理由。
- “连续”不等于每项完全相同；允许有意跳切、时间省略或方向冲突，但必须写叙事理由和观众重新定位方法。
- 相邻状态冲突源于镜头首尾设计时返回 `shot-visual-design`；源于调度或表演时返回各自责任 Skill，不在剪辑卡里虚构补丁。

### 5. 规划 Seedance 生成单元

生成单元边界依据动作连续、表演连续、空间/光线一致、声音承载、参考负载和稳定结束状态，不把平台临时最大时长写成永久创作规则：

- 成员、顺序和边界都未改变时保留原生成单元 ID。
- 一个单元拆成多个、多个单元合成一个，或成员集合改变时，新单元必须取得新的生成单元 ID；原 ID 标为被替代，不得复用给新成员集合。
- 只重排单元在全组中的位置、但其成员与内部顺序完全不变时保留 ID。
- 每个单元必须有可执行进入状态、足够完成的动作/声音段和稳定结束状态；多人复杂接触、长对白、大幅视角变化或 VFX 时序过载时优先拆分。
- 本阶段只提出新 ID 需求和替代映射；正式新镜头 ID、分镜版本和生成单元写回由 `shot-visual-design` 建立。正式 Prompt 尚未建立时不得预造 Prompt ID；已有 Prompt 对应单元被拆分/合并时，按版本状态规则建立新 Prompt 身份，不沿用旧 Prompt ID。

## 两项交付与依赖方向

先用 `assets/剪辑节奏表模板.csv` 和 `assets/editing-rhythm.schema.json` 建立 `ERT-<项目代号>-<分镜组代号>@v###`，再用 `assets/剪辑节奏卡模板.md` 建立精确引用该数据集的 `ERC-<项目代号>-<分镜组代号>@v###`。字段、版本与返工规则见 `references/editing-rhythm-contract.md`。

- `ERT` 是逐镜及其出向剪辑关系的任务数据集；直接引用待审查的分镜组快照和必要的调度、表演、摄影约束，不得反向引用尚未形成的 `ERC`。
- `ERC` 是创作短卡；保存全组节奏弧、Profile采用审计、拆分/合并替代映射、修订摘要和下游写回切片，并只把当前 `ERT@版本` 作为直接成果上游。
- 两项分别以“任务数据集”和“创作短卡”进入绑定项目的 `tasks/任务成果索引.csv`。只有两项均为 `可交接 + 当前有效=是`、Profile已关闭且没有输入阻断时，才能交 `shot-visual-design` 写回。
- 项目文件建议保存到 `creative-control/editing/shot-groups/`；中央仓库只保存模板和规则，不建立虚构项目数据。

## Profile 关闭与唯一写回链

`ERC` 的 Profile 审计区记录 `ProfileID@版本`、用户确认依据、采用方法 ID、转译规则、舍弃方法和关闭结论。下游只读取 `ERT` 具体修订行及 `ERC` 的成果身份、保护门和“分镜写回切片”，不得读取 Profile 审计区、主体姓名、片名或未采用方法。

交接顺序固定为：

1. `shot-visual-design` 读取当前 `ERT@版本 + ERC@版本`，对接受的修订建立新的分镜组快照并只升级实际变化的镜头；新增/拆分镜头的正式身份也在此建立。
2. `shot-visual-design` 在分镜设计卡记录节奏成果精确引用、逐项采用/不采用理由、写回状态与新分镜组版本；剪辑 Skill 不直接写分镜 CSV。
3. 写回完成并通过分镜 Schema 后，`cinematography-direction` 才执行逐镜摄影审核。摄影审核若只退回时长或生成单元，再进入模式 A；写回后必须重新审核。

## 版本、复核与返工

- 首版均为 `v001`；`ERT`、`ERC` 和 `CUT` 稳定 ID 不因同一身份内容修订而改变，旧成果文件只读保留。
- 顺序、时长、切点、动作/声音接点、相邻状态、镜头关系、生成单元成员/边界、修订动作或任一精确上游引用变化时，先建立下一 `ERT` 版本，再建立引用它的下一 `ERC` 版本。
- 只有场戏级节奏弧、Profile审计、保护门或写回摘要变化且所有数据行不变时，只升级 `ERC`。任何已入索引成果正文修改都必须建立下一成果版本。
- 只改变任务成果索引状态、复核日期或兼容结论，不升级成果内容版本。模式 B 判断完全兼容时可在原版本执行复核状态事务；精确引用或内容变化时必须建立下一版本。
- 镜头叙事功能、机位/构图/运镜要改，返回 `shot-visual-design`；场戏目标、信息顺序或因果要改，返回 `dramaturgy-scene-beats`；位置/调度要改，返回 `directing-blocking`；表演动作策略要改，返回 `acting-direction`；摄影物理实现问题交 `cinematography-direction`。

## 质量门与禁止事项

- 每个镜头有非重复价值和基于可观察过程的时长依据；每个出向边界有切点时机与情绪、信息、动作或声音理由。
- 不自动把对白做成正反打，不按平均时长或固定秒数机械切分，不把反应镜当默认覆盖。
- 相邻第一帧/稳定结束状态、动作、视线、方向、道具和声音能够互相解释；有意不连续必须有理由和重新定位方法。
- 生成单元拆分/合并有新旧 ID 映射、稳定结束状态和成员集合，不复用被替代身份。
- 不改剧本、调度、表演母档、逐镜机位或摄影规则，不写分镜 CSV，不写正式 Prompt，不登记资产或调用外部 Seedance。
- Schema 通过只证明字段、ID和业务门可检查，不代表剪辑创作质量已通过；真实节奏质量留待 V01 用用户镜头组验证。
