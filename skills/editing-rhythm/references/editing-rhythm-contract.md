## 职责与成果

`editing-rhythm` 只拥有两类成果：

- `ERT-<项目代号>-<分镜组代号>@v###`：逐镜与出向剪辑关系的任务数据集；
- `ERC-<项目代号>-<分镜组代号>@v###`：全组节奏摘要、Profile审计、生成单元替代和分镜写回切片。

`ERT` 直接引用当前分镜组快照以及调度、表演、摄影约束的精确版本；`ERC` 只把同版 `ERT` 作为直接成果上游。不得让 `ERT` 反向依赖尚未形成的 `ERC`，也不得把两者合成一个无法独立版本化的文件。

剪辑数据是修订提案，不是分镜权威表。`shot-visual-design` 仍是分镜设计卡和逐镜 CSV 的唯一写入者。

## 逐行语义

`ERT` 一行代表“当前镜头及其出向边界”。最后一个镜头仍保留一行，`下一镜头ID与版本或场末=场末`，用来说明场末停留、声音尾部和生成单元稳定结束。

- `剪辑关系ID`：当前镜头到下一镜头或场末这一条关系的稳定身份，格式 `CUT-###`。
- `剪辑序号`：本版建议关系顺序，不代替稳定身份。
- `当前镜头ID与版本`：待审查快照中的精确镜头身份。
- `下一镜头ID与版本或场末`：当前关系的另一端；不得用模糊镜头名。
- `镜头新增价值`：相对前一镜头新增的情绪、信息、动作阶段、空间定位或人物反应。
- `修订动作`：保持、调时、重排、修改切点、拆/并镜或拆/并生成单元的明确提案；多项用中文分号分隔。

`CUT` 绑定一对邻接端点。任一端点变成另一个镜头，必须建立新 `CUT` ID；同一对端点只改切点时机、理由或接点时保留 ID 并升级 `ERT`。

## 时长和切点

时长必须由可观察过程构成，至少说明适用的下列项目：

1. 信息出现后让观众读清的时间；
2. 动作准备、执行、接触、结果与恢复；
3. 角色听见、判断和反应；
4. 台词语义完成、必要停顿和抢话/重叠；
5. 摄影运动或VFX必要阶段完成；
6. 稳定结束状态和场末余韵。

不能只写“节奏更快”“按平均3秒”“更电影感”。当前时长和建议时长相同时，仍写为什么应保持。

切点时机必须可定位到具体事件，例如“手指离开门把且门锁声结束后”“对方说出锁定词前一拍”“视线第一次落到空椅时”。只写“动作中”“对白后”“情绪点”不足以交接。

切点理由类型只表示主导原因，具体理由必须说明切在该时机而不是更早或更晚对观众理解、预期、冲击或余韵的作用。`组合`必须写出至少两个共同起作用的类别。

## 动作声音与相邻状态

动作接点至少核对动作阶段、身体/道具接触、速度趋势、视线和银幕方向。声音接点至少说明声音相对画面是同期、先入、延出、画外延续、环境连续还是刻意静默，以及它服务的原因。

声音接点只是剪辑时间关系，不建立角色声音身份、正式声音资产或场戏声音卡。正式/临时声音来源仍由 `sound-voice-direction` 和用户在规定节点决定。

相邻状态按下列次序检查：

1. 当前镜头第一帧是否与上一个关系的离开状态兼容；
2. 当前镜头稳定结束状态是否提供可生成、可剪切的离开点；
3. 下一镜头第一帧是否保持或有意改变人物位置、姿态、视线、道具、空间、光线和声音；
4. 有意跳切、省略时间、越轴或状态突变是否有叙事理由和重新定位方法。

状态冲突不能靠含糊词遮盖。镜头首尾状态错误返回 `shot-visual-design`；调度或表演本身错误返回对应上游。

## 生成单元身份

生成单元是一次外部视频生成所承载的一个镜头或一组镜头。其身份由成员集合和内部顺序共同界定：

- 成员、内部顺序和边界均未改变：保留原生成单元 ID；
- 一个拆多个、多个合一个、增加/删除成员或改变内部顺序：每个新成员组合建立新生成单元 ID，旧 ID 标为被替代；
- 只改变整个单元在分镜组中的排列位置，但成员和内部顺序不变：保留 ID；
- 只改变镜头时长但成员不变：生成单元 ID可保留，分镜组和实际变化镜头升级版本；后续正式 Prompt正文变化时升级 Prompt版本。

剪辑表中的“建议生成单元ID”可以写“待shot-visual-design建立”，同时必须填写新成员集合和被替代旧 ID。剪辑 Skill 不预造正式镜头或 Prompt 身份。

拆分/合并后，旧 Prompt 不能换成员后继续沿用。`shot-visual-design` 完成新单元写回，再由正式 Prompt 责任流程按版本状态规则为新单元建立新 Prompt ID。

每个生成单元必须以可执行状态开始，以相对稳定状态结束。边界不能落在不可中断接触、不可读口型、未完成镜头运动或 VFX 必要阶段中间，除非该中断本身是明确剪辑设计且模型可以分别生成两端。

## 唯一写回链

顺序不可调换：

1. `shot-visual-design` 建立当前分镜组草案快照；
2. `editing-rhythm` 建立 `ERT` 与 `ERC` 修订提案；
3. `shot-visual-design` 逐项决定并写回，保存新的分镜组快照；
4. 分镜设计卡记录 `ERT/ERC` 精确引用、写回结论和新快照版本；
5. `cinematography-direction` 对写回后的快照执行逐镜摄影审核；
6. 摄影审核只因时长或生成单元退回时，重新进入剪辑模式 A；每次写回后重新审核。

剪辑建议如果要求改变镜头存在理由、观众视点、景别对象、机位意义、构图或运镜动机，只能形成返回项，不能直接写分镜。`shot-visual-design` 不采用某条建议时必须在分镜设计卡写明原因，不能静默遗漏。

## 版本与兼容复核

首版 `ERT`、`ERC` 均为 `v001`。成果 ID 在同一分镜组作用域内稳定；旧版文件只读保留。

以下变化先升级 `ERT`，再升级引用它的 `ERC`：

- 输入分镜组、镜头版本或其他精确上游引用变化；
- 镜头顺序、时长、关系端点、切点、动作/声音接点或相邻状态变化；
- 生成单元成员、内部顺序、边界、替代映射、进入或结束状态变化；
- 修订动作或返回责任 Skill 变化。

只有全组节奏摘要、Profile采用审计、保护门或分镜写回摘要变化，而所有 `ERT` 行与上游引用完全不变时，才可只升级 `ERC`。任何已入任务成果索引的成果正文发生字节变化都必须建立下一版本；只改索引状态、状态依据或复核日期不升级内容版本。

模式 B 只做影响判断：

- `继续兼容`：新上游不会改变任何 `ERT/ERC` 内容或精确引用，可在原版执行复核状态事务；
- `需要下一版本`：内容或引用变化，按数据集优先顺序建立新版本；
- `输入不足`：无法唯一定位新旧输入，不作创作推断。

## 阻断与返工

- 分镜快照、镜头版本、调度/表演/摄影来源不一致：返回 `production-router-handoff` 或对应上游核对。
- 镜头叙事功能、机位、构图或运镜问题：返回 `shot-visual-design`。
- 场戏目标、事件因果或信息顺序需要改变：返回 `dramaturgy-scene-beats`；未经授权不得改剧本。
- 人物位置、距离、出入场或移动触发需要改变：返回 `directing-blocking`。
- 表演动作、反应策略或不可打断行为需要改变：返回 `acting-direction`。
- 摄影物理实现问题：返回 `cinematography-direction`；若其结论是可通过时长/单元调整解决，再回本 Skill。

结构校验、自动测试和兼容复核都不能代替用户对实际节奏的创作判断；真实镜头组在 V01 验证。
