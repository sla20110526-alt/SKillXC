# 连续性与就绪审计

## 只认正式资产与有效控制卡

先读取项目数据绑定卡。资产只读取项目 ID 一致的正式资产登记表、可调用资产表与资产状态传播表；任一正式资产版本为 `待复核`、`停用` 或 `历史` 时，都不能进入可调用切片。表演只读取绑定项目 `creative-control/acting/` 中 `已生效 + 当前有效=是` 的母档版本，以及任务索引可追溯的场戏表演卡；声音身份只读取 `creative-control/sound/` 中 `已生效 + 当前有效=是` 的身份卡版本和任务索引可追溯的场戏声音卡。候选/失败资产、待确认/已替代控制卡、临时声音、其他项目数据均不能冒充正式声音资产。

项目风格、美术、全片摄影和灯光长期基线只读取 `creative-control/项目创作基线索引.csv` 中 `已生效 + 当前有效=是` 的精确项目版本，并核对源定义与Profile引用可追溯。中央源或Profile发布新版不构成项目卡自动升级，也不使旧项目引用失效。

## 两级检查

### 场次就绪

- 当前剧本版本和范围有效
- 人物脸母图与单张五视图卡使用不同正式资产 ID，五视图卡精确依赖正确脸母图版本；实际调用的人物卡与当前服装、妆造、伤口/污迹状态匹配，全部版本可调用且没有未处理待复核
- 场景母图、当前场景状态、所需正式视图和光影状态使用不同正式资产 ID 并形成正确精确依赖；空间圣经/锚点表版本与空间依据一致，镜头所需锚点、遮挡、未知区处理和光源地图均可追溯
- 道具/载具、生物/怪物和 VFX 分别满足场次需求；三列各自列出正式版本与缺口，没有需求时明确写“不适用”，VFX另核对视觉母版和时序卡是否匹配本场
- 有台词、独白或持续画外发声的角色已明确声音身份卡和正式声音资产，或已标出需要用户选择的临时声音路线；没有发声角色时明确写“本场无需独立声音资产”

### 生成单元就绪

- 分镜组 ID/版本、镜头 ID/版本集合和生成单元 ID 可唯一对应
- 重要角色引用当前有效的表演母档版本，并且本场表演卡版本与分镜一致；没有适用重要角色或简单角色跳过时写明理由
- 当前镜头实际引用名可用
- 参考负载未超过 Seedance 2.0 当前工作配置
- 人物、场景、道具之间没有版本冲突
- 开始/结束状态、左右手、银幕方向、视线和动作接点可承接
- 对白、声音身份卡版本、声音来源、环境声和禁用声音已明确

## 声音来源门

- 逐个核对当前生成单元的发声角色，不能用“本场有声音”笼统通过。
- 正式声音资产必须有 `声音资产ID@版本`、平台引用名、调用方式与限制；当前工作配置不支持直接音频参考时，不能把它写成已上传。
- 用户明确选择 Seedance 临时镜头内声音时，本单元可记 `有条件继续`，并保存确认原文和跨镜一致性风险；不能把临时声音写入正式资产切片。
- 需要发声但既没有正式声音资产也没有用户临时声音决定时，结论必须为 `暂停`，返回 `sound-voice-direction`；审计 Skill 不替用户选择。
- 只有非发声场次可以在没有声音资产的情况下直接通过声音门。
- 就绪表中的声音身份、正式资产和临时决定三列都必须显式填写；不适用时写“不适用”，不得留空掩盖缺口。

## 变更传播

1. 以正式/可调用表的当前状态为准，读取资产状态传播表中对应资产版本的最新事件及 `传播处理状态`，沿依赖路径核对尚未处理的原因；不能把保留在历史中的旧待复核结果误当成当前状态，也不能只靠资产名或最新版推断。
2. 对场次或生成单元调用到的待复核资产，结论必须为 `暂停`，缺口返回责任生产 Skill；不得用最接近的旧资产替代。
3. 责任生产 Skill 可以给出 `可继续／需重做或新登记／资料不足` 的兼容比较；审计只记录比较结果，不直接恢复资产状态。
4. 用户明确确认唯一待复核版本继续使用后，返回 `approval-asset-registry` 专用登记对话更新当前兼容依赖并解除待复核；解除完成后重新审计。
5. 正式父资产更新时，依据传播表列出派生变体、场景视图、场次、生成单元、分镜和 Prompt 的复核范围，不自动认定子资产继续有效，也不直接改写分镜或 Prompt。

缺口路由使用 `world-asset-production/assets/asset-responsibility-map.json`：道具/载具/图案文字、生物怪物和 VFX 必须分别返回各自唯一责任 Skill。只有缺口本身混合多个身份或类别不清时才返回世界资产二级路由；不得因为就绪表汇总而把生物与 VFX 合并生产。

## 输出

- `就绪审计卡.md`
- `场次资产就绪表.csv`
- `生成单元就绪表.csv`（进入正式 Prompt 前）
- 审计结论：`可继续 / 有条件继续 / 暂停`
- 缺口列表：责任 Skill、所需输入、返回节点
- 资产状态传播事件与仍待复核版本

使用 `assets/就绪审计卡模板.md`、两张 CSV 模板、`scene-readiness.schema.json` 和 `generation-readiness.schema.json`，按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 生成检查报告。两张表都必须写相关传播事件和待复核资产版本；没有时明确写“无”。Schema 通过不替代正式资产、版本依赖、参考负载与连续性业务复核。

不得用最接近的旧资产代替缺失资产，也不得在 Prompt 中掩盖上游缺口。
