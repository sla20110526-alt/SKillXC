# 剧作与场戏节拍

把“剧本已经写定什么”“本场如何推进”“下游怎样执行”分开。只解释并组织锁定材料，不在本 Skill 内改写剧本。

## 唯一责任

`dramaturgy-scene-beats` 唯一负责场戏戏剧问题、节拍边界、人物目标、障碍、策略、潜台词、信息变化、权力变化和进出状态；也是场戏节拍卡与逐节拍数据的唯一写入者。

- `script-truth-index` 提供剧本事实、锁定台词、事件顺序、因果与原文定位。
- `acting-direction` 模式 A 提供重要角色当前有效表演母档的最小行为边界；本 Skill 不修改母档。
- `directing-blocking` 把戏剧节拍转成人物空间行动与观众视点；本 Skill 不决定走位或镜头。
- `acting-direction` 模式 B 把节拍与调度转成可执行表演；本 Skill 不写呼吸、眼神或肢体微动作。

每张任务单只选择一种工作模式。

## 进入条件

读取以下最小输入：

1. 已确认项目数据绑定卡、项目锁定卡与唯一项目 ID。
2. 当前 `剧本内容版本`、稳定 `场次ID`、本场原文范围与可定位的页码／段落／行号／时间码。
3. 本场剧本事实切片，包括原台词、动作、事件、出入场、进入／结束状态、事件顺序和因果。
4. 重要角色当前有效表演母档最小切片；缺失时返回 `acting-direction` 模式 A。简单角色只有在任务单写明理由后才可跳过。
5. 会改变本场事实判断的专业结论，只读取当前可交接的 `CCR@版本 + 主张ID／采用字段 + 结论状态 + 适用条件`；“暂不可裁决”返回 `specialist-consultant-router`。

任一锁定台词、关键事件、顺序或因果没有原文依据时，标为缺口并暂停该部分，不用常识补成剧本事实。

## Profile 进入门

到达本阶段后，列出编剧／剧作 Profile 候选、代表作品、成熟度与证据边界，并询问用户是否调取。用户未明确选择时使用通用方法，不读取完整 Profile。

- 默认最多一个主 Profile；补充 Profile 必须另行确认唯一问题、最小范围与失效点。
- Profile 只改变分析顺序、冲突组织与节拍检验方法，不能授权改写锁定内容。
- 在卡片记录采用方法、舍弃方法、作用范围和用户选择原文。
- 场戏节拍卡交付后关闭完整 Profile；下游不得收到主体姓名、片名、Profile 原文或未采用方法。

## A｜场戏节拍建立

### 决策顺序

1. **固化出处**：先写 `剧本内容版本`、`场次ID`、原文定位、事实 ID 集合和全部锁定项，禁止先凭印象概括。
2. **锁定场戏状态**：写明场戏进入状态、离开状态、不可缺失事件、场戏问题与场戏结束时必须发生的变化。
3. **确定人物行动线**：逐个主要人物写“此刻想从谁那里得到什么”、障碍和失败代价；目标必须指向对象或结果，不能只写情绪。
4. **识别真正转折**：只在触发导致策略、信息、权力、关系或进入／离开状态发生变化时建立新节拍；不要按每句台词机械切分。沉默或反应只有产生实际变化时才单独成拍。
5. **连接因果**：说明本拍由什么触发、人物为何改用此策略、可见行为造成什么结果，以及该结果如何触发下一拍。
6. **分开四层**：人物目标回答“要什么”，障碍回答“什么阻止”，策略回答“怎样争取”，可见行为回答“观众能看到什么”。四者不得互相替代。
7. **建立潜台词与依据映射**：只从已知处境、台词与行为的矛盾、关系和当前信息差推导；不得凭空补传记或隐藏事件。为触发、目标、策略、可见行为、潜台词、信息变化和权力变化分别记录事实 ID／分析依据与标签，不能用一个总标签覆盖整拍。
8. **记录变化量**：分别填写信息、权力与总体状态的进入、变化和离开；“没有变化”的片段应并入相邻节拍或说明不可省略的结构原因。
9. **执行原文保护**：逐拍核对锁定台词／动作、事件顺序和因果。未获授权时，任何同义改写、重排、增删或补因果都判为不通过。
10. **生成两个成果**：先完成逐节拍权威表，再由其生成场戏节拍卡与两个下游最小切片。

### 输出

1. 使用 `assets/场戏节拍表模板.csv` 写逐节拍权威数据，以 `assets/scene-beat.schema.json` 检查。
2. 使用 `assets/场戏节拍卡模板.md` 写人读摘要、原文保护门、版本、Profile 关闭和交接切片。
3. 使用稳定 `BDT-<项目代号>-<场次代号>@v###` 标识节拍数据集，行内节拍使用 `BT-001` 起的稳定 ID；使用 `DSB-<项目代号>-<场次代号>@v###` 标识场戏节拍卡。
4. 把节拍表作为“任务数据集”、节拍卡作为“创作短卡”分别写入任务成果索引。节拍表只引用剧本事实、表演母档与已采用顾问结论；节拍卡引用节拍表精确版本，不得形成循环依赖。
5. 结构校验通过只代表字段与格式完整，不代表戏剧质量、原文保护或用户采用已经完成。

## B｜剧本／上游换版兼容复核

1. 输入当前可交接的节拍表与节拍卡精确版本、旧上游引用和新上游引用。
2. 逐项比较剧本原文定位、锁定台词、事件、顺序、因果、角色目标与限制、顾问采用结论。
3. 只返回以下一种结果：
   - `继续兼容`：内容与精确上游引用均无需改变；在原成果版本上执行复核状态事务。
   - `需要下一版本`：任何节拍内容、适用范围或精确上游引用实质变化；建立下一节拍数据集版本，再建立引用它的下一节拍卡版本。
   - `输入不足`：差异或原文定位不完整；保持旧成果待复核，不猜测。
4. 发现上游换版只输出影响分析；由明确的数据事务执行“标记待复核”或“复核后继续使用”，不得在分析时静默改状态。

## 原文保护与改写边界

- 未收到用户对明确剧本内容与范围的改写授权时，锁定台词必须逐字保留，事件不得增删或重排，因果不得替换。
- 即使用户授权修改，本 Skill 也不直接把修改混入旧剧本版本。先返回 `script-truth-index` 建立新的剧本内容版本和差异，再用模式 B 复核或重建节拍。
- 可以提出“此处目标不清”“因果缺口”“两种解释会改变节拍”等问题；不得把建议写成已发生事实。
- 对未写明的心理只使用 `SCRIPT_INFERRED` 或 `CREATIVE_PROPOSAL`，并写依据；不能确认时使用 `UNKNOWN`。

## 版本与返工

- 首版节拍数据集和节拍卡均为 `v001`，稳定 ID 不随内容变化。
- 节拍边界、触发、目标、障碍、策略、可见行为、潜台词、信息／权力／进出状态、原文定位、锁定内容、事件顺序、因果、适用范围或精确上游引用变化时，建立下一成果版本。
- 只改任务状态、成果索引状态、复核日期或“继续兼容”结论时，不升级内容版本。
- 节拍表变化必然使引用它的节拍卡升级；只允许“表先升级、卡后引用”，不得让表反向依赖卡。
- 已入表旧版文件只读保留，不覆盖旧路径。文件正文任何字节变化都按任务成果索引规则建立下一版本。
- 剧本、表演母档或顾问结论替代／失效时，先做影响分析；未完成复核前，旧节拍成果不得用于新下游任务。

## 下游最小交接

只交给以下两个责任 Skill：

- **给 `directing-blocking`**：`DSB@版本 + BDT@版本`、场戏问题、总体目标、逐拍触发、信息／权力变化、进入／离开状态、不可缺失事件、锁定顺序与因果、专业结论适用条件。不得交付 Profile 身份或预设机位。
- **给 `acting-direction` 模式 B**：`DSB@版本 + BDT@版本`、逐角色目标、障碍、失败代价、策略、可见行为、潜台词、人物知道／不知道什么、节拍进出状态和锁定台词引用。不得代写呼吸、眼神、步态或表演微动作。

导演调度先完成；场戏表演适配随后同时读取节拍与调度。其他 Skill 若需要戏剧依据，只能经这两个已成立的下游成果继续交接，不能绕过责任边界读取完整 Profile。

## 禁止事项

- 不决定景别、构图、机位、摄影机距离、焦段、景深、摄影机运动、支撑方式、灯光、剪辑切点或正式 Prompt。
- 不按预想镜头反推节拍，不让现有资产视图迫使场戏变平。
- 不把抽象情绪词当策略或可见行为，不把人物“知道剧本结局”写成潜台词。
- 不把表演母档、人物资产外貌或编剧 Profile 当作新增剧本事实。
- 不自行登记、批准资产或写项目进度。

## 质量门

- 每个节拍都有可定位触发、人物目标、障碍、策略、可见行为、潜台词、信息变化、权力变化与进出状态。
- 每个新节拍都存在可说明的变化；相邻节拍之间因果可追溯。
- 场戏进入／离开状态与逐拍首尾闭合，事件顺序和锁定台词与剧本事实切片一致。
- 事实、推断、创作建议和未知项逐字段分离；缺口没有被伪装成确定结论。
- 两个下游切片都引用精确成果版本，且不含摄影、灯光、剪辑或 Prompt 决定。
- Profile 已在交付点关闭，任务成果索引与 Schema 均通过，业务复核另有明确结论。
