# 人物资产生产

首次进入时说明当前人物、工作模式、准备使用的正式输入与预期交付，询问用户是否确认使用。图片模型固定为 GPT Image 2；不要重新询问图片模型。

## 职责边界

- 负责真人及以可识别人脸、人体和人物表演身份为核心的类人角色。
- 负责人物脸母图、五视图人物卡、服装/妆造、人物剧情状态和以人物为主体的持握/穿戴组合。
- 不从外貌推断性格，不编写表演母档或声音身份；分别交 `acting-direction` 和 `sound-voice-direction`。
- 非人生命体或怪物交 `creature-monster-production`；服装、武器、机械或历史事实缺口按需返回 `specialist-consultant-router`。
- 只定义人物、版本和候选验收。把确认的设计交 `image-prompt-production` 装配完整 Prompt；生产对话不写正式登记表。

## 输入门

读取最小数据切片：

- 项目 ID、已确认绑定卡、任务 ID/版本、人物工作模式
- 需求槽位、预留正式资产 ID、父/附加预留 ID 与完成定义
- 剧本明确的人物事实、用户锁定信息和参考图用途
- 当前有效的人物资产短执行卡；P0任务只接受当前可交接评审卡中的测试ID切片，批量任务只接受当前可交接风格包中的人物切片，且来源四卡必须仍是当前组合；如任务确需拆分核对，只读取其中引用的项目风格、美术和展示灯光最小字段，不读取完整 Profile 或完整摄影规则
- 已登记父资产和附加资产的精确 `正式资产ID@版本`
- 必须继承、允许变化、禁止变化
- 服装/妆造含可见图案文字时，读取已登记图案文字母版精确 `ID@版本`、逐字/图形校对通过结论和目标服装区域；不得自行重画、改字或把母版当作人物身份参考

缺少会改变人物身份、年龄感、基础妆造、身体比例、服装结构或伤口因果的信息时暂停并列出最小问题；不凭惯例补成事实。使用 [人物资产生产卡模板](assets/人物资产生产卡模板.md) 固化本轮输入、身份锚点、变化范围和候选状态。

## 六种工作模式

任务单必须选择一种模式，不在同一生成尝试中跨模式补设计：

1. **选脸与脸母图**：生产或核对清晰人物剧照，锁定脸部身份；等待明确登记。
2. **五视图基础卡**：仅基于已登记脸母图，生产一张单人物五视图总览卡；等待明确登记。
3. **服装/妆造版本**：基于已登记五视图卡或正确服装版本，只改指定服装、发型或妆容。
4. **剧情状态版本**：基于正确人物/服装精确版本，只叠加伤口、流血、雨湿、污迹、疲态或战损。
5. **人物—道具交互**：人物是画面主体；人物和附加对象必须先分别登记，候选携带全部精确版本。
6. **版本兼容复核**：比较父版本变化前后对现有派生版本的影响，只输出 `可继续 / 需重做或新登记 / 资料不足`，不改正式状态。

详细继承层级和 ID 链读取 [人物身份与变体继承](references/character-identity-inheritance.md)。

## 正式资产依赖链

不要把脸母图和五视图基础卡登记为同一正式资产 ID 的连续版本。拆解阶段必须为二者预留不同 ID；后者精确依赖前者。

| 层级 | 正式资产类型/角色 | 生产依据 |
|---|---|---|
| 脸母图 | 人物 / 脸母图 | 父与附加依赖均写“不适用” |
| 五视图基础卡 | 人物 / 五视图基础卡 | 父资产写脸母图 `ID@版本` |
| 服装/妆造卡 | 服装妆造 / 服装妆造 | 父资产写五视图基础卡或正确服装卡 `ID@版本` |
| 剧情状态卡 | 人物或服装妆造 / 状态变体 | 父资产写状态发生前的正确人物/服装卡 `ID@版本` |
| 人物—道具组合 | 人物 / 交互组合 | 父资产写人物卡，附加资产逐项写道具/武器/装置 `ID@版本` |

脸母图只作为后续图片生产的身份源，在可调用表中把范围写为“人物图片身份参考，不直接作为 Seedance 单人物卡”；供 Seedance 2.0 调用的是与当前服装和状态匹配的一张五视图总览卡，不同时上传五张人物图。

## 模式 1：选脸与脸母图

1. 优先使用用户明确指定的参考；逐张写身份、服装、气质、光线或构图用途，不让同一图承担冲突职责。
2. 制作能判断骨相和五官的清晰近景：自然闭嘴、低表情强度、无遮挡、不过度美颜、不过分戏剧化透视。
3. 保护眼睛可读性。即使眼睛颜色很深，也保留虹膜/瞳孔层次和来自既定光源的微弱自然眼神光；不要做发光眼或无来源双高光。
4. 核对年龄感、骨相、眼距、眉眼、鼻、唇、下颌/下巴、耳朵、发际线、肤色/皮肤纹理、固定痣疤与不对称识别点。
5. 用户上传的现成剧照也先作为候选；只有明确登记后才成为脸母图正式版本。

## 模式 2：五视图基础卡

读取 [人物五视图总览卡](references/character-overview-card.md)，严格交付一张总览卡：左三分之一为正面特写和朝同一侧的 3/4 侧面特写，右三分之二为正面、纯侧面、背面全身。三个全身都保留头部；不得使用旧的“正面全身无头部”规则。

画幅只服从五视图可读性。选择当前平台支持的合适横向尺寸，不继承项目成片画幅，也不虚构平台不支持的分辨率。若人物过小，先优化画布比例、留白和面板占比，不改成交付五张独立图片。

## 模式 3—5：变体和交互

每次生成前输出：

- `PRESERVE EXACTLY`：脸部身份、未授权改变的身体比例、父版本中的其余服装/妆造/状态和构图版式
- `CHANGE`：本轮允许调整的精确字段、部位、材质、颜色、位置、程度和覆盖范围
- `ONLY CHANGE`：一句话列出唯一变化集合

服装变化不重选脸；妆容、胡须或发型变化不得顺带改变骨相和年龄。脸部伤口或流血是覆盖层：保持五官几何、肤色基线和固定识别点，只改变伤口位置、形态、阶段与邻近组织反应。需要跨镜调用的变体继续使用单张五视图版式；所有视图中的服装、伤口侧别和状态阶段必须一致。服装含标志、编号或可见文字时，把图案文字母版列为附加依赖，并逐视图复核字符、方向和位置；本 Skill 只负责在服装载体上的应用成图，不改写母版内容。

人物持物时先判断是否值得建交互资产。固定佩戴、长期绑定或近景接触反复出现时建立组合；短暂普通持物可在镜头阶段调用人物卡与道具卡，不把道具永久画进人物基础卡。组合必须写清左右手、握点、接触面、遮挡、重量反馈和道具朝向。

## Prompt 交接与候选回流

向 `image-prompt-production` 交付：人物生产卡、目标版式、身份锚点、参考图用途、精确父/附加版本、三类变化清单和生成后检查项。参考负载采用最小集合：

- 五视图基础卡以已登记脸母图为身份参考。
- 变体以正确父人物卡为主参考；只有已发生脸漂移或任务明确需要时，才额外引用脸母图并限定为“仅身份”。
- 交互组合把附加正式资产限定为对象结构/外观参考，不让它覆盖人物身份。

用户回传结果后，从身份、跨视图、身体、服装/状态、接触、光线和排版七层检查。资产设计错误由本 Skill 重写完整人物生产卡，再交 `image-prompt-production` 建立下一 Prompt 版本；漏译、歧义、参考映射或模型随机偏差直接返回后者处理。本 Skill 不自行维护第二份完整 Prompt，也不在旧 Prompt 末尾叠加补丁。候选状态只写 `待用户判断 / 继续调整 / 待明确登记指令`；不得自行写“已批准”。

## 登记门与失败边界

- 只有“登记这张”“确认登记”等明确、指向唯一候选的措辞才输出登记申请。
- “不错”“继续”“这个方向”“就用这张”“上一版可以”均不触发登记。
- 失败图、仍需调整的图和无法唯一定位的图不进入登记申请；用户是候选是否失败的最终决定者。
- 用户给出调整方向或参考时直接迭代；只有用户明确要求记录失败原因时才转 `generation-version-log`。
- 登记申请复用 `approval-asset-registry/assets/登记申请模板.md`，必须携带绑定卡、需求槽位、预留 ID、用户指定名称、唯一候选、精确生产依据、继承/变化、用户原文和对话日期；同时附上 `approval-asset-registry/assets/登记对话激活指令模板.md`，让独立登记对话核验和写表。
- 专用登记对话完成写表并返回回执前，不得把候选称为可调用资产，也不得开始依赖该正式版本的下一层生产。

## 兼容复核

脸母图新版本使依赖它的五视图卡及全部下游派生版本进入待复核；五视图、服装或道具新版本使对应下游状态和交互组合进入待复核。本 Skill 比较脸部锚点、身体比例、服装结构、状态侧别、遮挡和接触关系，提供理由与重做范围。只有用户对唯一待复核版本明确确认继续使用后，才交 `approval-asset-registry` 更新当前兼容依赖；本 Skill 不解除状态。

## 输出

- 人物资产生产卡与当前工作模式
- 五视图版式定义或变体/交互继承定义
- GPT Image 2 Prompt 装配输入与生成后检查清单
- 候选检查结论与下一轮调整方向
- 用户明确登记后的登记申请与登记对话激活指令，或待复核版本兼容结论
