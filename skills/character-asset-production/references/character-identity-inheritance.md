# 人物身份与变体继承

## 身份层级

按以下顺序锁定；下层可以增加信息，但不得静默改写上层：

1. **脸部身份层**：年龄感、骨相、眼距与眼型、眉、鼻、唇、下颌/下巴、耳、发际线、肤色/皮肤纹理、固定痣疤和不对称识别点。
2. **身体身份层**：身高感、头身比、肩宽、胸廓、腰胯、四肢比例、手脚尺度、基础体态与明确身体限制。
3. **基础妆造层**：基础发型、眉毛/胡须、基础妆面、服装结构、鞋、首饰和固定佩戴物。
4. **剧情状态层**：伤口、流血、污迹、雨湿、疲态、战损、肿胀或阶段性生理变化。
5. **交互接触层**：持握/穿戴对象、左右手、接触面、遮挡、重量反馈和对象方向。

“严格锁脸”不是要求不同角度逐像素相同，而是让可见三维身份锚点在角度、光线和表情变化后仍指向同一人。不要用磨皮、妆容或光影相似代替骨相一致。

## 预留 ID 与版本链

对每个需正式生产的角色，至少预留两个不同正式资产 ID：脸母图和五视图基础卡。使用项目既有编号规则；以下仅示意：

```text
CHR-001-FACE@v001          脸母图
  └─ CHR-001-CARD@v001     五视图基础卡
       ├─ CST-001@v001     服装/妆造卡
       │    └─ STA-001@v001 剧情状态卡
       └─ INT-001@v001     人物—道具交互卡 + PROP-003@v002
```

- 预留 ID 在 `script-asset-breakdown` 建立；版本只在明确登记时由 `approval-asset-registry` 分配。
- 同一正式资产 ID 的 `v002` 表示同一资产身份的替代版本，不表示从脸母图“升级”为五视图卡。
- 五视图、服装、状态和交互均保留原始生产依据。父版本被替代时依赖者先进入待复核，不自动随父版本升级。

## 各模式的继承和变化

| 模式 | 必须继承 | 允许变化 | 禁止顺带变化 |
|---|---|---|---|
| 五视图基础卡 | 脸部身份层 | 从剧本/用户锁定补齐身体与基础妆造；推断不可见角度后等待用户确认 | 年龄、骨相、肤色基线、固定识别点 |
| 服装/妆造 | 脸部与身体身份层；未指定的基础妆造 | 指定衣物、发型、胡须、妆面、配件 | 五官、骨相、年龄、体型、未授权伤势 |
| 剧情状态 | 正确人物/服装版本的全部稳定层 | 指定状态的部位、侧别、面积、阶段、湿度/污染/损伤程度 | 身份、服装结构、伤口漂移、状态强度跨视图跳变 |
| 人物—道具交互 | 正确人物版本与附加对象版本 | 接触、遮挡、手指包覆、受力姿态和对象朝向 | 人脸、身体比例、对象结构/尺寸、左右手关系 |

## 脸部伤口与妆造

脸部发生剧情变化时先描述不变的骨性与软组织锚点，再定义覆盖层：

- 用左/右、解剖部位、边界形状、长度/面积、深浅、颜色阶段和渗流方向定位。
- 让肿胀、血迹和污迹遮挡局部纹理，但不重塑鼻梁、眼距、下颌、嘴唇厚度或头型。
- 伤口若跨场发展，分别建立清楚阶段，不让“更严重”成为无上限随机变化。
- 美容妆、老化妆或特效妆若实质改变年龄感或轮廓，先让用户确认它是妆造版本、剧情状态，还是身份级新变体。

## 参考图用途优先级

1. 正式父人物卡：人物、身体和当前妆造的主依据。
2. 正式脸母图：只用于补强脸部身份，不替代父卡中的身体和服装。
3. 正式附加对象：只用于对象结构、尺寸与外观。
4. 用户效果参考：只用于用户明确指定的妆容、伤口、材质、姿态或光线，不继承参考人物的脸。
5. 项目短执行卡：约束真实度、美术、材质与展示光，不作为人物身份来源。

参考之间冲突时停止并说明冲突项，让用户决定主从；不要平均多张人脸，也不要用风格参考重选角色身份。

## 兼容复核清单

父版本变化后逐项比较：

- 脸部身份锚点是否仍一致
- 身体比例和基础体态是否改变
- 服装版型、开合、配件和遮挡是否仍适配
- 伤口/污迹/雨湿的身体侧、位置和阶段是否仍成立
- 道具尺寸、手别、握点、接触和受力是否仍成立
- 单张五视图作为下游参考是否仍清晰、无冲突

资料足够时输出可继续或需重做；看不到关键角度、父版本或接触区域时输出资料不足，不猜测。
