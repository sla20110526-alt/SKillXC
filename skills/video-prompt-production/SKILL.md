# Seedance 2.0 视频 Prompt 生产

默认使用轻量生产模式：完整 Prompt 属于当前创作结果，可以完整显示；后台任务单、参考映射、成果索引和检查日志不逐项展开。每轮只附必要引用说明、一个检查点和一个下一步决定。

## 唯一职责与工作模式

`video-prompt-production` 是 `VRM` 视频参考映射数据集和 Seedance 正式 Prompt 交付卡的唯一写入者。它只翻译已经成立的镜头，不重做剧作、导演、表演、剪辑、摄影、灯光、声音或资产设计。每张任务单只选择一种模式：

- `A｜单镜头正式Prompt装配`：一个生成单元只含一个连续镜头。
- `B｜镜头组正式Prompt装配`：一个生成单元含两个或以上已锁定镜头，逐镜写时长、切点和跨切状态。
- `C｜Prompt层返修或上游换版重装配`：先判断是表达/优先级/参考映射问题，还是上游设计已改变；前者建立下一 Prompt 版本，后者返回责任 Skill 后再重装配。

## 进入门

1. 先由 `production-router-handoff` 说明本 Skill 的用途、输入、外部人工生成边界并取得用户确认。
2. 不询问或加载任何大师 Profile。只读取当前卡片中已经采用并关闭 Profile 后下传的项目规则切片；Prompt 正文不得出现主体姓名、片名或未采用方法。
3. 必须拥有同一项目、同一生成单元的当前精确版本：
   - 已写回 `ERT@版本 + ERC@版本`、不再含“待剪辑建立／待剪辑检查”的分镜组快照；
   - 当前生成单元 ID、成员与内部顺序，逐镜稳定 ID/版本、时长、切点和首尾状态；
   - 逐镜摄影审核完成，摄影技术修正已经由 `shot-visual-design` 写回；
   - 正式可调用资产、场戏表演卡与母档、镜头灯光短执行卡、场戏声音卡、VFX/生命体/顾问最小切片及生成单元就绪结论；不适用项必须明确写“不适用”，不能留空。
4. 生成就绪结论为“暂停”、声音来源为“未决定”、正式资产待复核、精确版本冲突或平台必须能力尚未核对时不交付正式 Prompt。
5. 当前平台工作配置、可接受媒体类型、参考加载方式、时长/镜头数和声音能力在使用时核对并写入交付卡；不把本次界面上限固化为长期规则，也不凭记忆声称平台支持。

## 最小输入切片

- 从分镜读取当前生成单元内逐镜空间、摄影、第一帧、动作/表演、接触、台词/声音、光影、VFX、切点和稳定结束状态；不读取旧分镜版本拼接补充。
- 从正式资产只读取当前服装/状态/形态/阶段匹配的可调用版本和平台引用名。每个出场人物只调用一张匹配当前服装与状态的五视图总览卡；不再叠加脸母图、单独特写或五张独立视图。
- 从表演只读取本镜可见的目标、策略、倾听、眼神、呼吸、重心、停顿和动作状态；不把抽象情绪词当执行指令。
- 从灯光只读取当前镜头短执行卡的来源、人物受光、阴影/反射、变化触发、曝光护栏和禁项；不从长期基线临时发明逐镜光线。
- 从声音只读取说话者、锁定原句、声音来源、逐场表现、环境/动作声接点、静默与禁项；不自行选择临时声音或新增对白、旁白、字幕、音乐。
- 从 VFX/生命体只读取当前镜头所需的正式身份、运动约束、时序阶段、接触、受光和残留；不增加肢体、能力、第二来源或未定义阶段。
- 从专业顾问成果只读取 `CCR@版本 + 主张ID／采用字段 + 结论状态` 指向的当前镜头最小切片，并继承适用条件与禁用边界；问题包、证据集或暂不可裁决内容不能进入 Prompt。

## 参考素材映射

先用 `assets/视频Prompt参考映射表模板.csv` 与 `assets/video-prompt-reference.schema.json` 建立 `VRM-<项目代号>-<生成单元代号>@v###`，再写 Prompt。详细规则见 `references/seedance-prompt-contract.md`。

1. 只列本次真正会进入平台、转译成描述或用于外部声音/后期的媒体参考；风格卡、表演卡等文本成果不是平台参考素材。
2. 按实际加载顺序建立唯一 `参考序号` 和 `平台引用名`。每项只承担一个主要用途，并写允许继承与禁止继承；“全部参考”“保持一致”“综合风格”不是合格用途。
3. 同一用途存在多个冲突参考时选定一个，或暂停让用户决定；不能平均融合身份、场景结构、动作、摄影或声音来源。
4. 每名人物只能有一行“人物五视图总览卡”，且必须匹配本单元当前服装/妆造/伤势/污迹状态。动作或运镜视频参考不得继承其中人物身份、脸、服装、场景或光线。
5. 正式资产必须来自当前可调用表；用户确认的一次性动作/运镜参考可不登记为资产，但要记录定位、授权范围和禁止继承项，不得冒充正式资产。
6. 平台处理方式为“使用时待核对”时不能交付；核对后选择直接上传、Prompt描述转译、外部声音/后期参考或仅人工核对，并如实写入交付卡。

`VRM` 是“任务数据集”成果，直接引用当前分镜组与正式媒体来源，不反向引用尚未形成的正式 Prompt。正式 Prompt 交付卡引用当前 `VRM@版本`。二者分别进入任务成果索引；Prompt 正文只使用平台引用名，不复制内部 ID、版本或路径。

## 装配优先级

先选择 `assets/单镜头Prompt正文模板.md` 或 `assets/镜头组Prompt正文模板.md`，严格按以下顺序装配：

1. **参考绑定与风格执行基准**：用平台引用名说明唯一用途；把风格包转成短的可见结果，不堆 Profile、片名或质量口号。
2. **空间与摄影**：场景锚点、人物/物体关系、景别对象、摄影机位置、视场/透视、构图、运镜、触发与停止；不重新选择镜头。
3. **第一帧**：人物与物体已存在的位置、前中后景、距离、身体朝向、视线、姿态、道具接触、VFX/声音/光线开始状态。
4. **动作与表演**：按时间顺序写触发、准备、执行、反应、停顿与镜头运动；身体朝向与眼睛方向分开，移动世界方向与银幕方向分开。
5. **物理接触**：写接触对象/部位、力量来源、重量、惯性、摩擦、重心、形变/结果与恢复；没有接触时明确省略，不写空泛“真实物理”。
6. **台词与声音**：锁定说话者与原句、口型范围、声音来源、停顿/呼吸/空间距离、环境声、动作/VFX接点、静默与禁项；非说话者不动嘴。
7. **光影**：只翻译灯光短卡中的来源、人物受光、阴影/反射、变化触发、曝光保护和 VFX 环境承接。
8. **稳定结束状态**：写可见、可保持、可供后续镜头承接的最终姿态、视线、道具、空间、VFX残留、声音尾部、光线和摄影机状态。
9. **最小高风险禁项**：只保留本单元最容易漂移且上文无法充分正向锁定的禁项；删除“8K、IMAX、电影级、超真实、非3D”等互相重复或与具体规则冲突的口号。

## 单镜头与镜头组

- 单镜头正文必须写“连续单镜头”和准确总时长，只允许一个主摄影运动链；开始—过程—结束均来自同一镜头版本。
- 镜头组正文必须写生成单元总时长、镜头数和已成立切法。每镜单独写时长和上述执行顺序；各镜时长之和必须等于总时长，镜间使用分镜中的 `CUT` 时机、动作/声音接点和相邻状态，不把组内镜头误写成连续一镜到底。
- 跨切保持人物身份、服装/妆造/伤势、道具/左右手、空间锚点、轴线/方向、VFX阶段/残留、声音桥和世界光源逻辑。分镜有意跳切或状态变化时逐字保留其理由与重新定位方法。
- 一个生成单元负载超出本次平台能力或无法稳定承载既定动作时，不在 Prompt 中删镜头、压缩因果或降低表演；返回 `editing-rhythm` 提出拆分，再由 `shot-visual-design` 写回并重新审核。

## 交付与版本

使用 `assets/正式Prompt交付卡模板.md` 保存 `VRM@版本`、精确上游、平台能力核对、正文模板、正式 Prompt ID/版本和完整正文。建议正式身份为 `VPR-<项目代号>-<生成单元代号>`，首次为 `v001`。

- Prompt 正文、参考映射、参考顺序/用途、平台设置、上游精确版本或可复现执行含义变化时，交付完整替代正文并递增 Prompt 版本；旧版不覆盖。
- 只调整 Prompt 表达、优先级或消除歧义，不改变镜头设计时，只升级 Prompt，不升级分镜组或镜头版本。
- 需要改变镜头叙事任务、机位/构图/运镜、动作、表演、资产、声音决定、灯光或时长时，先返回唯一责任 Skill；收到新上游版本后，在同一生成单元身份仍成立时升级 Prompt 版本。
- 生成单元拆分/合并、成员或内部顺序变化时建立新生成单元 ID、新 `VRM` ID 和新正式 Prompt ID；不得把新成员集合塞进旧 Prompt ID。
- 完全相同的 Prompt、参考、顺序和设置原样再次生成不升级版本。平台随机结果不是 Prompt 版本；详细批次只在用户要求时交 `generation-version-log`。

`VRM` 可在媒体来源、顺序、用途、允许/禁止继承、平台处理方式或生成单元身份变化时升级；只改 Prompt 措辞而参考映射不变时复用当前 `VRM`。正式 Prompt 新交付先以 `草案 + 当前有效=否` 入任务成果索引，用户明确放行该版后才激活为 `可交接 + 是`；这不等于视频可用。

## 外部人工生成与轻量检查点

- 新 Prompt 交付后回显：`正式PromptID@版本｜Prompt：待人工检查｜生成结果：未生成或未回报`。
- 用户明确说“Prompt 没问题，我去生成”等，只把该版 Prompt 标为“已放行生成”。用户说“镜头可用／成片可用”时，只更新可唯一定位结果的轻量结论；不要求上传视频。
- “继续”“可以”“不错”不单独改变正式状态；“上一组通过”无法区分 Prompt 或结果时只问清这一个决定点。
- 当前节点只把完整 Prompt 交给用户手工复制到 Seedance。不得提交生成任务、查询进度、下载视频、声称已上传参考或虚构平台返回。
- 生产对话不写项目进度、失败原因或正式 QC。用户明确要求同步时输出进度包交独立记录对话；需要系统化视频诊断时进入 `video-qc-review`。

## 最小返修路由与禁止事项

- Prompt 漏译、歧义、冲突、优先级或参考映射错误：本 Skill 建立下一完整 Prompt 版本；参考映射变化时先升级 `VRM`。
- 上游设计错误：返回对应资产、表演、声音、灯光、剪辑、镜头或摄影 Skill，不用文字强化掩盖。
- Prompt 正确但模型随机未执行：用户可原样再生成，版本不变；需要系统诊断时交 `video-qc-review`，失败原因只在明确要求时记录。
- 接收 QC 返回时只按其唯一主根因执行：Prompt漏译建立下一VPR；参考映射/负载先建下一VRM再建下一VPR；上游设计错误返回相应唯一写入者；模型随机偏差保持VPR/VRM/设置不变并交外部原样重试。QC不得直接改写本Skill成果。
- 不改剧本、镜头、调度、表演母档、摄影/灯光/声音卡或正式资产，不登记素材，不写进度/QC表，不调用外部生成接口。
- 自动检查只证明结构、版本、映射和权限边界可执行；真实 Seedance 生成质量与至少一个可用镜头留待 V01 由用户外部操作验证。

## 输出

- `VRM@版本` 视频 Prompt 参考映射数据集
- 单镜头或镜头组正式 Prompt 交付卡及 `VPR@版本`
- 可完整替代上一版、可手工复制到 Seedance 的正文
- 当前轻量检查点、最小返修或上游返回节点
