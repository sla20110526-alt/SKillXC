## 成果与依赖方向

一次生成单元生产两类项目成果：

- `VRM-<项目代号>-<生成单元代号>@v###`：实际媒体参考的顺序、来源、唯一用途、允许/禁止继承和平台处理方式，成果类别为“任务数据集”；
- `VPR-<项目代号>-<生成单元代号>@v###`：正式 Prompt 交付卡与完整正文，成果类别为“Prompt”。

`VRM` 直接引用分镜组、正式可调用资产或用户确认的一次性参考，不引用尚未形成的 VPR。VPR 把当前 VRM、分镜组、镜头集合、剪辑、摄影、表演、灯光、声音、VFX、顾问和就绪审计精确版本列为上游。不得让 VRM/VPR 互相循环引用。

完整正文只使用平台引用名，例如“人物参考A”“办公室空间参考”，不写 `ASSET-...@v###`、项目路径、任务状态或“请读取某卡”。卡片和映射表保存可追溯信息，Prompt 正文保存生成模型需要执行的内容。

## 参考素材选择

先列所有候选媒体，再用以下问题减载：

1. 这项参考是否改变本单元必须可见的身份、空间、对象、动作/VFX或声音结果？
2. 它是否承担一个没有被更强参考覆盖的唯一用途？
3. 平台是否在本次工作配置中支持所选处理方式？
4. 它的允许继承和禁止继承能否清楚分开？

任一答案为否时，不把它作为平台参考上传；必要信息改由当前上游短切片转译成正文。参考多并不等于控制强，重复或冲突参考会争夺模型注意力。

建议按“身份锚点 → 空间锚点 → 关键交互对象/生命体/VFX → 动作或运镜 → 声音”的依赖顺序安排，但最终顺序必须根据当前平台输入方式和本单元的第一风险确定。每一行只写一个主要用途：

- 人物卡：只锁人物身份、当前服装与状态；
- 场景图：只锁空间结构、当前视图和可见锚点；
- 道具/载具：只锁对象结构、尺度、文字或交互面；
- 生物/VFX：只锁正式形态或视觉身份；运动和阶段仍由正文时间线控制；
- 动作/运镜视频：只锁时间结构、身体动力或摄影运动，不继承演员身份、服装、场景、光线或美术；
- 声音参考：只锁已允许的声音身份或外部同步依据，不改变说话者、原句和画面节奏。

“用于整体风格”“全部参考”“综合保持一致”会同时争夺多个职责，不允许作为唯一用途。两个参考都声称主身份、主空间或主动作时必须选择一个，不得平均融合。

## 人物参考单卡规则

同一生成单元、同一人物最多一张五视图总览卡。该卡必须对应当前分镜调用的服装、妆造、伤势、污迹和持物前状态，并包含左侧正面/3⁄4侧面特写与右侧正面/侧面/背面全身。

不得同时上传：脸母图、单独人物剧照、另一服装五视图、基础版与流血版两张人物卡，或五张拆开的视图。需要在镜头内发生状态变化时，选择匹配第一帧的当前人物卡，把已经由上游批准的变化过程和稳定结束状态写入正文；如果模型无法在一个单元内稳定完成，返回剪辑拆分，不用第二张人物卡制造身份竞争。

多名人物时每人各一张匹配卡，并使用不同平台引用名。人物卡不能替代场景、道具或动作参考。

## 正文翻译规则

正文中的每条执行语句必须能回溯到当前分镜或一个已列上游切片。按以下优先级组织：

1. 参考绑定与短风格基准；
2. 空间与摄影；
3. 第一帧；
4. 动作与表演；
5. 物理接触；
6. 台词与声音；
7. 光影；
8. 稳定结束状态；
9. 最小高风险禁项。

可观察指令优先于抽象形容词。例如把“紧张表演”翻译为呼吸、停顿、视线、重心和动作时机；把“电影光”翻译为来源、受光、阴影、反射和曝光保护；把“真实物理”翻译为接触点、重量、惯性、摩擦和结果。

空间和摄影必须沿用已审核镜头，不在 Prompt 中换机位、补镜头、添加运动或把固定机位改成手持。第一帧只写开始时已经存在的状态，不把随后发生的动作提前放入第一帧。

动作时间线区分：身体朝向/眼神方向、世界移动方向/银幕方向、人物动作/摄影机响应。接触必须写对象、部位、力量、重心和可见结果；不适用时删除，不为了完整模板虚构接触。

声音保留锁定原句和说话归属。场戏声音卡未授权字幕、音乐、旁白或额外对白时不新增；临时镜头内声音必须有用户原文并明确“由本镜生成”，不能冒充上传音频。

光影只翻译镜头灯光短执行卡；世界光源逻辑、阴影方向和人物眼神光来自已成立来源。VFX自发光本体由VFX成果定义，灯光只翻译其对人物/环境的承接。

稳定结束状态必须可维持至少一个可剪切瞬间，并与分镜中的后续首帧或场末一致。不要用“自然结束”“画面稳定”代替人物、道具、摄影机、声音、VFX和光线的具体终态。

## 单镜头和镜头组

单镜头只允许一个连续摄影链。总时长等于该镜头时长；动作、声音、光影变化都必须装入该时间，不暗含剪辑。

镜头组以当前生成单元成员和内部顺序为准。检查：

- 镜头数与成员数相同；
- 每镜时长等于当前分镜；各镜时长之和等于单元总时长；
- 每个相邻边界使用当前 `CUT` 的可定位时机、动作/声音接点和状态结论；
- 每镜独立写完整执行块，不能用“同一场景继续”“同上”省略；
- 跨切状态与有意跳切都按分镜执行，不自行修复或创造不连续。

如果本次平台不支持当前镜头数、时长或参考负载，返回 `editing-rhythm` 决定拆分，并由 `shot-visual-design` 写回新生成单元身份；Prompt Skill 不自行删镜、压时长或沿用旧 VPR。

## 平台能力核对

平台规格是本次运行条件，不是永久创作规则。每次首次装配或已知界面变化时，在交付卡记录：核对日期、工作区/界面定位、可用媒体类型、加载方式、时长/镜头/参考限制、声音处理、临时设置、依据和未决项。

只有“当前界面”或用户提供的当前平台说明可以证明本次支持。未核对时写“待核对”，并暂停正式交付；不能用旧项目经验、模型名称或仓库固定数值推断。

`VRM` 的平台处理方式必须与核对结果一致。“直接上传（本次已核对）”不能用于实际上只被写成文字的素材；“Prompt描述转译”不能声称平台已加载原文件；“外部声音或后期参考”不能冒充Seedance内部声音参考。

## 身份版本与状态

生成单元 ID 决定 VRM/VPR 的稳定作用域。成员或内部顺序变化、拆分或合并时，新建生成单元、VRM和VPR身份。只改变成员外部排列但单元内部完全不变时可保留身份。

VRM 以下变化建立下一版本：媒体来源、参考顺序、平台引用名、唯一用途、允许/禁止继承、平台处理方式、适用镜头或服装/状态。只改Prompt措辞且映射完全相同，不升级VRM。

VPR 以下变化建立下一版本：正文、VRM精确版本、平台设置、上游精确版本或任何影响可复现执行的内容。完全相同输入原样再生成不升级；随机结果与生成批次不是 VPR 版本。

Prompt层修改不改变分镜版本。镜头叙事、摄影、动作、表演、资产、声音、灯光、VFX或时长改变时，先建立相应上游与分镜新版本，再升级同一生成单元的VPR；若生成单元身份也改变，则建立新VPR身份。

Prompt状态和生成结果状态独立。`已放行生成`不等于`可用`，旧Prompt被替代也不自动废弃它已经生成的结果；项目是否继续采用旧结果只按用户明确结论处理。

## 返工和外部节点

Prompt遗漏、歧义、冲突、优先级或参考职责错误，由本 Skill 重写完整正文。设计本身错误返回唯一上游；平台能力不足返回剪辑/镜头链调整生成单元。系统性结果诊断进入 `video-qc-review`，默认即时分析不落盘。

当前正式节点是外部人工生成：交付完整 Prompt 和参考顺序后，由用户在 Seedance 界面操作。本 Skill 不上传文件、提交生成、轮询进度、下载视频或把未看到的结果写成完成。

用户明确放行 Prompt 或确认镜头可用时，只维护当前对话轻量检查点。正式进度、批次、失败原因和 QC 记录必须由用户另行授权对应记录对话。
