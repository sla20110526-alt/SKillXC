# VFX 视觉资产生产

首次进入时先执行独立资产判定，说明本轮 VFX 工作模式、正式输入和预期交付，再询问用户是否确认使用。图片模型固定为 GPT Image 2；不要重新询问图片模型。Seedance 2.0 负责镜头内运动，静帧只能锁定视觉身份或一个代表阶段。

## 职责边界

- 负责已经离开实体本体或在环境中传播的能量、烟尘、火焰、流体、爆炸、碎裂、粒子、组织流动及超自然现象的视觉身份、时序和接触规则。
- 人物、道具、载具、生命体或场景上固定不动的发光结构、材质和损伤结果分别交对应资产 Skill；VFX 只负责释放过程、传播过程和动态环境反应。
- 破坏后的对象/场景稳定状态交 `prop-vehicle-production` 或 `location-spatial-production`；生命体转化前后可停留形态交 `creature-monster-production`；本 Skill 负责中间现象。
- 普通雨雪雾、时间和天气变化优先作为场景/灯光状态；只有具有剧情可识别身份、异常规则或跨镜一致要求的天气现象才建立 VFX。
- 镜头光晕、景深、运动模糊、眩光、色差等摄影/后期表现不建立 VFX 图片资产，分别交摄影规则或正式 Prompt。
- 只定义 VFX 和候选验收。完整图片 Prompt 交 `image-prompt-production`；逐镜叙事机位与时长由镜头/剪辑 Skill 决定；生产对话不写正式登记表。

## 独立资产门

满足以下任一条件才建立 VFX 图片资产：

- 跨镜或跨场反复出现，必须保持同一轮廓、色彩、材料层级或发光身份
- 是观众需要识别的力量、技术、异常现象或剧情线索
- 需要独立审批，或多个镜头必须共享同一来源、阶段与接触规则
- 接触形态复杂且要在多个镜头复用，单靠文字容易漂移

一次性普通尘土、火花、呼吸雾、轻微飞溅、短暂血雾或只服务单镜的环境反应不预留 VFX 图片资产 ID，直接走“单镜执行交接”。镜头运动模糊不进入该模式，返回摄影规则或正式 Prompt。若剧本拆解已经误建槽位，返回 `script-asset-breakdown` / `asset-demand-plan` 修正，不制造空资产。

## 输入门

读取最小数据切片：

- 项目 ID、绑定卡、任务 ID/版本、VFX 工作模式、需求槽位和预留正式资产 ID
- 剧情功能、触发因果、出现范围、独立资产判定、现实/艺术化/超自然边界
- 来源位置、方向、初始尺度、影响范围、目标阶段、镜头时长需求及结束状态
- 当前有效 VFX 短执行卡；P0任务只接受当前可交接评审卡中的测试ID切片，批量任务只接受当前可交接风格包中的世界资产切片，且来源四卡必须仍是当前组合；只读取风格、美术、灯光和摄影的最小相关字段
- 已登记父 VFX、来源/触发实体、接触对象和场景空间的精确 `正式资产ID@版本`
- 必须继承、允许变化、禁止变化、用户参考及逐张用途
- 火焰、爆炸、流体、破坏、危险现象或异常物理所需的 VFX/物理顾问结论

来源、能量/质量规则、阶段、接触对象、自发光状态或残留会改变 VFX 身份与因果时，不得猜测；返回 `specialist-consultant-router` 或询问用户。使用 [VFX资产生产卡模板](assets/VFX资产生产卡模板.md) 固化决定，细节按需读取 [VFX视觉、物理与时序规则](references/vfx-visual-temporal.md)。

## 八种工作模式

1. **独立资产判定**：只判断建立图片资产或单镜执行交接，不产图、不登记。
2. **视觉母版**：建立稳定 `VFX定义ID@版本` 和一个代表阶段的单张视觉参考卡。
3. **状态/强度变体**：继承视觉母版或上一状态，只改变已批准的强度、颜色阶段、污染或破坏等级。
4. **接触参考**：以已登记 VFX 母版/状态为父资产、全部接触实体为附加资产，锁定需要跨镜复用的接触与照明关系。
5. **时序与接触定义**：建立或升级时序集、环境接触集，不产图、不登记。
6. **单镜执行交接**：为无需独立图片资产的一次性效果输出本镜阶段、时长、来源、接触、光照和残留条款，不产图、不登记。
7. **版本兼容复核**：比较父 VFX、来源、接触对象、场景、时序或灯光换版影响，只输出 `可继续 / 需重做或新登记 / 资料不足`。
8. **登记回执绑定**：读取专用登记对话回传的正式 `ID@版本`，只更新生产卡及本候选实际持有的时序/接触数据行，不产图、不登记、不改登记表；沿用父资产数据集时保留其原绑定。

同一生成尝试只执行一种会产图的工作模式。用户确认 VFX 定义、时序或接触任务数据不等于登记图片，也不要求使用“登记这张”。

## VFX定义与视觉身份

视觉母版建立稳定 `VFX定义ID@版本`，至少定义：

- 触发者、来源位置、初始方向、尺度/影响范围及能量或物质来源
- 材料类别、主体轮廓、内部层级、颗粒/碎屑尺度、密度、透明度、边缘和衰减
- 颜色来源、自发光/受光边界、相对亮度层级、照明范围和曝光风险
- 传播、湍流、浮力、重力、阻力、反作用或已锁定超自然例外
- 跨镜必须保持、允许按阶段变化及禁止无来源变化的项目

不要用“电影级特效”“真实物理”“能量流动”“粒子丰富”代替以上事实。可见身份、物理因果或源规则实质改变时升级 VFX 定义；只改变单镜机位、裁切或本次持续时间不升级定义。

## 单张视觉参考卡

每个可调用母版、状态或接触参考只交付一张与当前用途匹配的视觉参考卡：

- 最大面板只展示一个代表阶段；可附内部材料、边缘衰减或尺度细节，但不得做成六阶段连环图
- 自发光效果使用能辨认主体边缘且不过度污染的中性环境；非发光烟尘/流体使用足够分离的中性受光
- 保留来源方向、尺度、材料层级、密度、颜色和发光身份，不混入无关海报构图、镜头光晕或另一套效果
- 视觉母版尽量保持背景可分离；接触参考只加入任务指定的已登记接触实体和必要空间依据

需要人工审查多个阶段时可制作“行为分阶段设计板”，但它只用于审查，不进入正式图片资产表，也不得上传给 Seedance 作为直接视觉参考。Seedance 每镜优先使用与本镜阶段匹配的一张正式 VFX 参考；完整时序表不作为图片上传。

## 时序与环境接触

为当前定义建立独立版本化 `时序集ID@版本` 和 `接触集ID@版本`：

- 使用 `assets/VFX时序阶段表模板.csv` 与 `vfx-temporal.schema.json` 记录触发、形成、发展/传播、峰值、衰减、残留六阶段。无残留也建立“残留”行并写清归零条件。
- 使用 `assets/VFX环境接触表模板.csv` 与 `vfx-contact.schema.json` 逐项记录来源/目标、接触区域、发生阶段、照明/遮挡/反射/冲击/附着/沉积等作用、对象反应和残留。
- 持续时间写范围或可执行上限，不只写“快速”“慢慢”。镜头时长装不下必要阶段时返回 `editing-rhythm` 决定拆镜或选择可见阶段。
- VFX 规定自身发光的发生与衰减；`lighting-direction` 负责把它整合进场景受光、阴影和曝光。两者冲突时不能用 Prompt 偷改场景主光。

时序集和接触集是任务数据，不是图片资产。每个数据集只绑定其主承载候选的预留正式资产 ID：视觉母版通常持有定义与时序集，接触参考通常持有专用接触集；状态图可以只引用父资产的数据集，不复制或改写其绑定。主承载图片登记后，才把该数据集对应行绑定到精确 VFX 正式版本。只改变时序/接触规则时升级对应数据集，不自动升级图片资产；若代表阶段图片身份实际改变，仍需新候选和明确登记。

## 正式资产依赖链

| 交付 | 资产类型 / 角色 | 生产依据 |
|---|---|---|
| VFX视觉母版 | VFX / VFX视觉母版 | 父资产不适用；固定来源/触发实体按需列为附加版本 |
| VFX状态/强度图 | VFX / VFX状态变体 | 父资产为视觉母版或上一状态 `ID@版本`；附加依赖不适用 |
| VFX接触参考 | VFX / VFX接触参考 | 父资产为视觉母版/状态；附加资产为画面实际使用的全部来源/触发与接触人物、场景、对象、生命体或光影精确版本 |

三类交付使用不同预留正式资产 ID；同一 ID 的新版本只替代同一交付身份。接触参考不得从上一接触参考继续叠加；需要变化时回到正确母版/状态和当前接触实体重新制作。

登记回执产生正式 `ID@版本` 后，以“登记回执绑定”模式写回生产卡，以及 `预留正式资产ID` 等于本次候选 ID 的时序/接触数据行，再交分镜与 Prompt；引用父资产数据集的状态图不得改写父数据行。登记对话只写正式资产表与可调用表；本候选实际持有的任务数据仍为“未登记”时不得下传。父 VFX、来源或接触实体换版时，机器登记传播负责把派生图片标为待复核；时序/接触集换版则由任务成果索引的只读影响分析列出受影响成果，再由责任 Skill 决定待复核或重做。

## Prompt回流、登记与复核

向 `image-prompt-production` 交付 VFX 生产卡、定义/时序/接触最小切片、单张参考版式、精确父/附加版本、参考用途和 `PRESERVE EXACTLY / CHANGE / ONLY CHANGE`。结果从来源、轮廓、尺度、材料层级、密度、透明度、边缘、颜色、发光、接触、环境反馈和背景可分离性检查；VFX 定义、阶段或接触设计错误由本 Skill 重写完整 VFX 生产卡，再交后者建立下一 Prompt 版本，漏译、歧义、参考映射或模型随机偏差直接返回后者处理。本 Skill 不自行维护第二份完整 Prompt，也不在旧 Prompt 末尾叠加补丁。

只有“登记这张”“确认登记”等明确指向唯一图片候选的措辞才输出登记申请。“不错”“继续”“这个效果可以”不触发登记；分阶段设计板、时序/接触表、单镜条款、失败或待调整候选均不登记，失败原因只有用户明确要求才交 `generation-version-log`。

## 输出

- 独立资产判定与唯一 VFX 工作模式
- VFX 生产卡、定义、时序集和接触集
- 单张视觉母版/状态/接触参考定义，或单镜执行条款
- GPT Image 2 Prompt 装配输入与生成后检查结论
- 明确登记后的登记申请，或版本兼容复核结论

按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 检查结构。Schema 通过不代表任务数据已确认、图片已登记或镜头执行可用。
