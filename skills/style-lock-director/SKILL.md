# 风格锁定总控

首次进入时说明当前项目、工作模式、准备调用的专业抽屉和本轮完成定义，由 `production-router-handoff` 取得用户确认。没有具体项目、项目数据绑定卡、项目锁定卡或明确剧本范围时，只列缺口，不建立虚构风格包。

## 职责边界

- 本 Skill 唯一写入项目风格锁定基线内容，组织四张长期基线的有向依赖链，选择最小 P0 测试，判断跨专业一致性，并组装风格锁定包快照。
- `art-lookdev-direction`、`cinematography-direction` 和 `lighting-direction` 分别唯一写入美术、全片摄影和项目灯光基线；本 Skill 只给上游目标和待解决问题，不代写专业答案。
- 分类资产 Skill 负责测试候选的资产定义与业务验收，`image-prompt-production` 负责正式资产图片 Prompt。风格总控不直接写正式资产 Prompt、不生成登记申请、不改登记表。
- `creative-control-versioning` 唯一分配项目控制卡版本并执行待确认、原子生效、替代和停用。本 Skill 只提交版本操作申请。
- P0 评审卡与最终风格锁定包分别作为任务成果索引中的审查记录和组合快照；二者都不是长期基线，不反向写入四张基线。

## 先选择一种工作模式

每张任务单只执行一种模式；首次项目通常按 A → B → C → D 依次建立独立任务。

### A｜项目风格意图基线

读取项目锁定卡、剧本事实最小切片、参考材料用途说明和已有决定。参考必须逐项标明只借鉴什么、不得借鉴什么，不得把整部作品或创作者姓名当作结果。

1. 询问用户是否在本阶段调用导演 Profile；未明确选择时只使用已确认的通用方法。
2. 默认最多一个主导演 Profile；局部补充 Profile 必须再次确认，并写明唯一问题、作用范围和失效点。
3. 把剧本与用户目标压缩为观众关系、真实/风格化边界、时空可信度、情绪对比、视觉辨识目标、跨部门不变量和禁区。
4. 只提出美术、摄影、灯光和专业顾问需要回答的问题，不在上游卡中预判其技术方案。
5. 使用 [项目风格锁定基线卡模板](assets/项目风格锁定基线卡模板.md) 生成 `待确认 + 当前有效=否` 草案，并交 `creative-control-versioning`。

完整导演 Profile 在本模式结束后关闭；后续导演调度阶段是否再次调用，由该阶段重新询问，不自动继承完整资料。

### B｜四卡专业基线链

正式依赖固定为唯一直接上游链：

`项目风格锁定基线 → 美术LookDev基线 → 全片摄影规则 → 项目灯光基线`

1. 只把当前阶段需要的最小输入交给一个专业 Skill；不得把所有 Profile 和全剧材料一次加载进同一专业任务。
2. 进入美术阶段时由 `art-lookdev-direction` 询问美术 Profile；进入全片摄影基线时由 `cinematography-direction` 询问摄影 Profile；灯光阶段使用通用灯光 Skill。需要历史、科学、法律、职业或物理事实时按缺口调用 `specialist-consultant-router`，把已形成的顾问结论写入独立的“顾问任务成果引用集合”，不得塞进长期控制卡依赖集合。
3. 每张下游草案只精确引用前一张计划生效的直接上游版本：美术只引用风格、摄影只引用美术、灯光只引用摄影。祖先规则通过链传递，不得在下游重复列全，也不得引用尚未形成的 P0 评审卡或最终风格包。
4. 首次建立或上游改版时，把完整受影响链一起交 `creative-control-versioning` 原子生效，不留下引用旧上游的现行下游卡；停用上游时也必须把当前直接/间接依赖链一起停用。
5. 专业冲突返回真正责任 Skill：世界、材质、色彩交美术；视场、透视、摄影机与曝光保护交摄影；来源光、受光、阴影和反射交灯光；项目目标冲突才返回本 Skill。
6. 四卡尚未全部满足 `已生效 + 当前有效=是 + 唯一直接上游精确一致` 时，不进入 P0 测试。

四卡生效表示用户确认这些专业规则可进入受控 P0 验证，不等于批准资产批量生产。本模式不把下游版本反写进项目风格基线，也不因中央源或 Profile 更新自动改既有项目卡。

### C｜P0 风格测试与诊断

使用 [风格测试与评审卡模板](assets/风格测试与评审卡模板.md)，按风险选择最少测试，不按固定数量堆图：

- 有主要人物时，至少验证一次脸部身份可读性、真实皮肤、眼睛结构与微弱眼神光；
- 有主要场景时，至少验证一次默认 3/4 空间母图的深度、材质、色彩层级和主方向光逻辑；用户已明确选择剧照式母图时按该例外测试；
- 只有时代工艺、极暗曝光、复杂混合光、非人材质或 VFX 接触等高风险确实存在时，才增加一个针对该风险的测试。

每个测试都必须绑定需求槽位、预留正式资产 ID、唯一责任分类资产 Skill 和单一可判定命题。责任资产 Skill 先完成生产卡，再由 `image-prompt-production` 装配 GPT Image 2 Prompt；生成结果先返回责任资产 Skill 做资产验收，本 Skill 只判断跨专业目标是否成立。

每个测试还必须在评审卡中生成一个只对该 `测试ID + 预留正式资产ID` 生效的 P0 临时短执行切片，精确引用四张当前有效卡并写明失效点。评审卡使用稳定成果 ID/版本，以“审查记录”写入任务成果索引；四卡与测试计划闭合后，业务状态为“待执行”或“测试中”的当前可交接评审版本即可把该切片交给分类资产与图片 Prompt。测试输入、状态或结论变化时建立下一评审成果版本；最终风格包只接受业务状态为“已通过”且必做测试全部通过、无未决冲突的当前评审版本。临时切片不能用于其他资产、不能冒充风格包，也不能放行批量生产。

测试候选沿用正常资产候选边界：风格测试通过不等于资产登记，失败或待调整结果不登记。只有用户明确说“登记这张”“确认登记”等，才由责任资产 Skill 转独立登记对话。用户没有明确要求“记录失败原因”时，只保留测试状态和本轮调整指令，不建立失败原因档案。

诊断只选一个主要返回层级：

1. Prompt 漏译、歧义或参考映射错误：返回 `image-prompt-production`；
2. 人物、空间、对象、生命体或 VFX 设计错误：返回唯一责任资产 Skill；
3. 美术、摄影或灯光规则错误：返回对应专业 Skill，规则或精确引用变化时重建受影响项目卡版本链；
4. 项目观众关系、真实度边界或跨部门目标错误：返回本 Skill 的模式 A，并重走受影响链；
5. Prompt 与上游均正确、仅模型随机未执行：原样再生成不升级规则或 Prompt；用户要求改写表达时才升级 Prompt。

### D｜组合快照与批量放行

只有以下条件全部满足，才使用 [风格锁定包交付卡模板](assets/风格锁定包交付卡模板.md) 输出 `可用于批量生产`：

- 四张长期基线均为当前有效，项目 ID 与适用范围一致，依赖链精确闭合；
- 所有必做 P0 测试均通过，新增高风险项已有结论；
- 没有待处理的专业冲突、顾问硬事实缺口或用户未决选择；
- 三个资产短执行切片都能逐条追溯到四张当前有效卡，不含 Profile 姓名、片名或空泛“电影感”。

组合快照使用稳定 `SLP-{项目ID}` 和独立成果版本，以“组合快照”写入任务成果索引。四卡引用、测试评审卡、短执行切片或放行结论实质变化时递增；原样交接不升级。上游任一卡替代或失效后，先用任务成果影响分析定位受影响的旧评审卡和快照，再在一次事务中将它们标记待复核；待复核成果不得用于新任务。重做四卡链与 P0 后建立下一评审卡和快照版本，不把旧成果重新激活为新组合。

三个短执行切片分别面向人物资产、场景/道具/生命体/VFX 资产和资产展示灯光。它们只携带下游实际需要的结果，不传完整摄影规则或 Profile；具体场景光源地图、镜头灯光和逐镜摄影仍由对应后续 Skill 决定。

## 停止条件

遇到以下任一情况立即暂停并返回缺口：项目或剧本版本不唯一；参考用途未说明；Profile 未获用户选择；下游草案反向引用上游；四卡状态或精确依赖不一致；P0 测试没有预留 ID 或唯一责任 Skill；测试未通过却要求扩大批量；用户把“风格通过”当作“登记资产”。

## 输出

- 模式 A：项目风格锁定基线草案、Profile 采用/舍弃与版本操作申请
- 模式 B：四卡依赖链状态、专业任务单、冲突返回项与原子生效申请
- 模式 C：P0 风格测试与评审卡、单一诊断层级和下一步任务
- 模式 D：风格锁定包组合快照、三个短执行切片与批量生产门结论
