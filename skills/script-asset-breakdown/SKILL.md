# 剧本资产拆解

首次进入前说明本 Skill 的职责和产物，并询问用户是否确认使用；未确认时暂停。

## 输入

- 项目锁定卡中的项目 ID
- 已确认的项目数据绑定卡
- 剧本事实索引与当前范围
- 当前项目已有的预留正式资产 ID 与正式资产 ID 列表；没有时明确记为空

## 三遍拆解

1. 按场次识别明确出现的实体、状态和声音。
2. 识别跨场复用、状态变化、父子版本和连续性关系。
3. 为高优先级候选补齐生成所需但剧本未明确的信息缺口；不要擅自锁定创作建议。

## 拆解规则

- 人物：需要正式复用的角色至少把“脸母图”和“单张五视图基础卡”拆成两个不同的预留正式资产 ID，五视图卡的父预留 ID 指向脸母图；服装/妆造、剧情状态和人物—道具组合再各自预留独立 ID 并形成下游依赖。不得把脸母图和五视图卡当成同一 ID 的两个未来版本。
- 场景：每个需正式复用地点至少预留一个场景母图 ID；每个预制剧情视图、英雄视图、分镜返回的专项视图、需跨镜复用的场景状态和光影状态分别预留独立正式资产 ID，并把母图/状态写为父预留 ID。不默认生产完整360度，也不为文字版空间圣经和锚点表预留图片资产 ID。
- 道具/载具/图案文字：基础对象、需跨镜复用的对象状态、图案文字母版、对象表面应用和对象装配分别预留独立正式资产 ID。表面应用的父预留 ID 指向被应用对象，图案母版列为附加依赖；装配的父预留 ID 指向主承载对象，其余部件列为附加依赖。人物/生物交互组合另由主体责任 Skill 预留组合 ID；只需镜头内生成的临时物不建资产。
- 生物/怪物：基础形态、每个需跨镜复用的结构变体、生理状态变体和持物/穿戴组合分别预留独立正式资产 ID。结构变体的父预留 ID 只指向基础形态或上一结构变体；状态变体指向状态发生前的正确生命体；组合的父预留 ID 指向生命体，全部道具/载具列为附加依赖。转化中可稳定停留且跨镜调用的阶段按结构变体拆分；只存在于单镜过渡的中间形变不建静态资产。形态定义、解剖锚点和运动约束进入任务成果索引，不预留图片资产 ID。
- VFX：先判断是否需要独立图片资产。跨镜需保持视觉身份、剧情可识别或需独立审批的效果，为视觉母版、状态/强度变体和接触参考分别预留正式资产 ID；状态父预留 ID 指向母版/上一状态，接触参考父预留 ID 指向母版/状态并把全部接触实体列为附加依赖。一次性普通尘土、火花、呼吸雾、轻微飞溅和单镜反应只记录单镜执行需求，不预留图片资产 ID。VFX定义、时序集、接触集和行为分阶段设计板进入任务成果索引，不预留图片资产 ID。
- 声音：只把需要跨镜复用的角色声音参考音频拆成独立资产。对有台词、独白或持续画外发声且需要声音连续的说话者，每人最多先预留一个基础声音资产 ID；语言、口音、音色等稳定边界由 `sound-voice-direction` 的声音身份卡管理。
- 无台词角色不建立声音资产。环境底声、动作音效、非语言反应、逐场声音表现和 Seedance 临时镜头内声音只进入场次/镜头声音需求，不进入候选资产表，也不预留正式资产 ID。

向资产需求计划交接时使用以下责任路由：人物/服装妆造 → `character-asset-production`；场景/场景视图/光影 → `location-spatial-production`；道具/载具/图案文字 → `prop-vehicle-production`；生物怪物 → `creature-monster-production`；VFX → `vfx-asset-production`；声音 → `sound-voice-direction`。一个描述混合多个可独立复用身份时分别预留 ID，并用父子/附加关系连接；类别仍不清时在资产信息缺口表把责任 Skill 写为 `world-asset-production`，不得把它写成候选资产的正式生产者。候选资产表不新增“负责Skill”列，唯一责任字段由 `asset-demand-plan` 写入资产需求总表。

## 信息来源

每项标记 `剧本明确 / 用户锁定 / 创作建议 / 待确认`。创作建议不得伪装成剧本事实。

## ID 预留

- 为去重后的每个候选预留项目内稳定的 `正式资产ID`，例如 `CHR-001`、`SCN-002`；变体也有独立 ID，并记录父正式资产 ID。
- 预留 ID 只标识未来资产身份，不代表已有正式资产，也不带 `@版本`。
- 分配前检查当前项目已有的预留和正式 ID；同一项目中不得重复使用，不得读取或延续其他项目的编号序列。
- 用户确认登记时沿用此 ID；正式名称以用户登记时明确给出的名称为准。

## 输出

按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 输出：

- `资产拆解卡.md`：汇总范围、数量、去重关系、缺口和下游动作
- `候选资产拆解表.csv`：项目 ID、预留正式资产 ID、暂定名称、类型、父预留 ID、附加预留 ID 集合、出处和信息来源；多个附加 ID 使用中文分号分隔，没有时写“不适用”
- `资产信息缺口表.csv`：缺失信息、责任 Skill 与返回节点
- 使用 `asset-candidate.schema.json` 和 `asset-gap.schema.json` 逐行检查，并在拆解卡引用校验报告

使用 `assets/` 下对应模板和 Schema。Schema 通过不代表候选已登记；交给 `asset-demand-plan` 复核去重、建立需求槽位和排产，不得直接调用生成模型或正式登记。
