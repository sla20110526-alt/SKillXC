# 剧本资产拆解

首次进入前说明本 Skill 的职责和产物，并询问用户是否确认使用；未确认时暂停。

## 输入

- 项目锁定卡中的项目 ID
- 已确认的项目数据绑定卡
- 剧本事实索引与当前范围
- 当前项目已有的预留正式资产 ID 与正式资产 ID 列表；没有时明确记为空

## 三遍拆解

1. 按场次识别明确出现的实体、状态和声音。
2. 识别跨场复用、状态变化、父子版本和连续性关系。
3. 为高优先级候选补齐生成所需但剧本未明确的信息缺口；不要擅自锁定创作建议。

## 拆解规则

- 人物：基础身份、五视图基础包、服装/妆造版本、剧情状态版本。
- 场景：基础空间、必要光影状态和可预见的拍摄视图；不默认生产完整360度。
- 道具：区分独立资产、人物固定佩戴物和只需镜头内生成的临时物。
- 生物/怪物：区分基础形态、结构变体、状态变体和运动需求。
- VFX：记录来源、物理/超自然边界、环境接触和时序。
- 声音：只把需要跨镜复用的角色声音参考音频拆成独立资产。对有台词、独白或持续画外发声且需要声音连续的说话者，每人最多先预留一个基础声音资产 ID；语言、口音、音色等稳定边界由 `sound-voice-direction` 的声音身份卡管理。
- 无台词角色不建立声音资产。环境底声、动作音效、非语言反应、逐场声音表现和 Seedance 临时镜头内声音只进入场次/镜头声音需求，不进入候选资产表，也不预留正式资产 ID。

## 信息来源

每项标记 `剧本明确 / 用户锁定 / 创作建议 / 待确认`。创作建议不得伪装成剧本事实。

## ID 预留

- 为去重后的每个候选预留项目内稳定的 `正式资产ID`，例如 `CHR-001`、`SCN-002`；变体也有独立 ID，并记录父正式资产 ID。
- 预留 ID 只标识未来资产身份，不代表已有正式资产，也不带 `@版本`。
- 分配前检查当前项目已有的预留和正式 ID；同一项目中不得重复使用，不得读取或延续其他项目的编号序列。
- 用户确认登记时沿用此 ID；正式名称以用户登记时明确给出的名称为准。

## 输出

按 [项目数据三层契约](../production-router-handoff/references/project-data-contract.md) 输出：

- `资产拆解卡.md`：汇总范围、数量、去重关系、缺口和下游动作
- `候选资产拆解表.csv`：项目 ID、预留正式资产 ID、暂定名称、类型、父预留 ID、出处和信息来源
- `资产信息缺口表.csv`：缺失信息、责任 Skill 与返回节点
- 使用 `asset-candidate.schema.json` 和 `asset-gap.schema.json` 逐行检查，并在拆解卡引用校验报告

使用 `assets/` 下对应模板和 Schema。Schema 通过不代表候选已登记；交给 `asset-demand-plan` 复核去重、建立需求槽位和排产，不得直接调用生成模型或正式登记。
