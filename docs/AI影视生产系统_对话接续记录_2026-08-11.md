## 1. 当前任务目标

重新设计一套只用于以下情况的 AI 影视生产系统：

- 已经有完整剧本、剧本片段，或生产内容已经比较明确。
- 系统不负责从零构思一个模糊项目。
- 系统必须是“抽屉式”的：不同 Skill 可以随意组合、单独调用、用完卸载。
- 将登记、记录、索引、计划等生产控制工作，与剧作、导演、表演、摄影、美术、资产 Prompt、剪辑等创作生产工作分开。
- 各 Skill 不能互相覆盖职责，必须通过固定交接对象传递信息。
- 所有正式资产都必须经过用户确认后才能登记为“可调用”。

核心治理原则：

> 控制类 Skill 管理“什么已经被确认”；创作类 Skill 决定“下一步应该创造什么”；用户是两者之间唯一的批准门。

## 3. 三份 Skill 的关键结论

### 3.1 ACTING SKILL

核心原则：

> 表演不是展示情绪，而是人物在压力下，为获得某样东西而采取的行为。

每场戏需要：

1. 目标：人物现在想从某个对象那里得到什么。
2. 障碍和代价：什么阻止人物，失败会失去什么。
3. 策略：恳求、试探、施压、拖延、威胁等。
4. 表演节拍：通常 2–4 次策略或权力变化。
5. 潜台词：说出来的内容和真正想要的内容不同。

重要表演规则：

- 对方台词结束前，听者的反应已经开始。
- 回答前要有判断和思考。
- 人物需要具体身体生活：呼吸、重心、步态、距离、手上正在做的事。
- 最强的动作重音经常是突然停止手上的事情。
- 每个习惯动作必须有触发条件。
- 每个人物都应有“面具”和明确的面具破裂条件。
- 眼神是强制项：微扫视、眨眼、眼神光、眼睛先于头部转动。
- 角色表演母档应稳定；每场戏的表演段落必须重新适配，不能原样复制。
- 稳定声音身份与逐场声音表演要分开。
- 视频模型更擅长清楚动作状态，不擅长过长、复杂的动作过渡链。

### 3.2 CINEDANCE HIGGSFIELD SKILL

定位：Seedance/Higgsfield 视频 Prompt 的镜头执行与防错系统。

关键点：

- 最终 Prompt 只写当前镜头，不带场号、旧上下文和无关 `@tag`。
- 空间关系在摄影机风格之前。
- 第一帧必须明确是否已有全部必要人物。
- 位置要量化：画面左/右、前/中/后景、距离、身体朝向、眼神目标和移动方向。
- 身体朝向与眼睛方向分开写。
- 默认单一连续镜头；使用多镜头时逐镜头定义时长、机位、人物、动作和切法。
- 跨切镜保持人物、道具、伤口、血迹、污迹、光线、手部和空间连续。
- 光学控制优先写可观察结果：摄影机距离、视场角、透视扩张、背景压缩、景深。
- 每个镜头只有一个主要运镜意图。
- 物理必须有质量、惯性、摩擦、接触、重心和材质延迟。
- 灯光是优先约束：明确光源方向、摄影机位于光源哪一侧、人物受光结果和曝光保护对象。
- 对白只说提供的原句，其他角色不动嘴，不自动生成字幕、音乐和画外音。

### 3.3 LIRA SKILL

定位：图片生成、资产制作、图片修改和模型路由。

核心路由：

- 人物、选角、角色一致性：Higgsfield Soul 2.0；AI Cast 可做快速人物参考表。
- 场景、环境、电影静帧：Soul Cinema。
- 道具：NBP 或 GPT Image 2。
- 所有成片图片修改：优先 NBP。
- Seedream 4.5：只做皮肤、织物、表面等 AI 质感修复，不做点修改。
- GPT Image 2：NBP 无法完成时用于极小局部修改，也适合同场景新视角。

编辑纪律：

```text
CHANGE：只改变一件事。
PRESERVE EXACTLY：穷尽列出必须保持的内容。
ONLY CHANGE：再次强调只改变目标内容。
```

其他规则：

- Prompt 使用自然语句，不堆砌关键词。
- 精确优于冗长。
- 宽高比、分辨率和质量属于平台参数。
- 图片生成优先正向描述，避免大量 `no/not` 堆叠。
- 跨图人物一致性不能只靠文字，必须依赖平台身份参考或正式脸部资产。

## 4. 对原 v1.0.1 系统的判断

原系统的优势：

- 有完整的阶段状态机。
- 通用规则与项目事实分离。
- 有项目锁定卡、阶段交接包和版本回归。
- 有稳定生产资产 ID 和场景视图 ID。
- 有 P0/P1/P2 优先级、生产包和审批门。
- 有 SV0–SV3 场景视图分级。
- 有可调用资产映射、场次资产就绪和实际上传资产锚定。
- 有参考资产负载闸门和外部生成返修闭环。

主要问题：

- 将登记、计划、映射、Prompt 生产、导演、摄影、分镜、QC 和返修混在同一套大阶段规则中。
- 阶段 2 同时承担风格中枢、资产 Prompt、并行分工、回流分析、资产映射和场次就绪。
- 阶段 3 同时承担实际资产锚定、导演、表演、摄影、剪辑、正式 Prompt、QC 和返修。
- 表演层不够深入，缺少角色表演母档、策略、节拍、潜台词、眼神和地位变化。
- 分镜虽然要求填写景别、焦段、机位和运镜，但缺少“为什么选择这个镜头”的视觉戏剧决策算法。
- 导致大量基础构图、固定机位和安全运镜，不能主动使用仰拍、主观视点、穿背、遮挡、手持跟拍等方式强化情绪。

总体判断：

> v1.0.1 是项目级生产操作系统；ACTING、CINEDANCE、LIRA 是单项专业执行引擎。新系统应该保留前者的数据治理能力，但把专业创作能力拆成可插拔抽屉。

## 5. 参考视频与 Prompt 分析

### 5.1 视频客观信息

- 时长：15.069 秒
- 分辨率：2206×946，约 2.33:1
- 帧率：24fps
- 共两个镜头
- 唯一硬切点：约 7.625 秒

镜头结构：

1. 0–7.625 秒：夜雨街道，摄影机从人物背后跟拍。
2. 7.625–15.069 秒：切到人物侧前方近景，人物低头持续行走。

### 5.2 Prompt 中明显起作用的内容

- 明确两个 CUT 和 HARD CUT。
- 第一镜背后手持跟拍。
- 第二镜侧面人物近景。
- 人物从第一帧开始行走。
- 人物低头、不看行人、不扫描。
- 夜间城市、暴雨、湿地、雨伞行人、车辆和反光。
- 高架位于街道左侧。
- 摄影机位于人物阴影侧，脸部保持暗部。
- 冷蓝灰环境、暖色路灯和红色人物识别锚点。
- 湿发、雨水、鼻梁红绷带和小胡子跨镜稳定。
- 无字幕，声音以环境底噪和雨声为主。

### 5.3 部分起作用的内容

- `85mm`：第二镜有长焦近景感，第一镜并不明显。
- `very shaky handheld`：有步伐反馈，但比“very shaky”克制。
- `60:30:10`：色彩层级存在，但不是可精确测量的百分比。
- `Rule of thirds`：第二镜有部分体现；第一镜主体接近居中。
- 行人给人物让路：有人群移动，但主动让路效果不强。
- 服装和挂件：大量细节因景别太远或近景不拍身体而无法识别。

### 5.4 弱、不可验证或冗余内容

- `8K IMAX`：实际不是 8K，画幅也不能证明 IMAX。
- `Physical cine lens`：没有明确透视、距离和景深结果。
- `180° shutter`：不能从结果证明真实执行。
- 毛孔、汗毛、非对称痣等：雨水、低照度和实际输出分辨率使其无法稳定辨认。
- `Hollywood acting`：抽象标签；真正有效的是低头、抿嘴、闭合下颌和不停步。
- `Golden ratio` 与三分法同时出现，但没有可执行的主体落点。

### 5.5 Prompt 内部冲突

1. `Natural light only` 与夜间路灯、霓虹和店铺灯冲突。更准确的说法应是“只使用有来源的现场实景光”。
2. `No jitter` 与 `very shaky handheld` 冲突。应区分有重量的有机手持和数字高频震颤。
3. “卢贝茨基自然手持”与两次 85mm、硬切的实际镜头语法并不完整一致。
4. 抽象悲伤描述与具体身体行为重复；后者更可执行。

结论：

> 真正稳定成片的是摄影机位置、人物行为、场景物件、光源方向、切镜结构和连续性，而不是顶部的风格名字或质量口号。

## 7. 建议的生产控制类 Skill

### C01｜项目接入与制作类别锁定

管理：

- 剧本版本与生产范围
- 真人写实、3D、2D或混合媒介
- 写实程度、表演夸张度、材质和渲染类型
- 画幅、目标视频模型、资产模型
- 参考图的具体用途
- 用户问答和确认结果

### C02｜剧本内容索引

建立：

- 场次索引
- 人物出场与关系
- 剧情事件和台词出处
- 人物、道具和环境状态变化
- 当前处理范围

### C03｜资产登记与关系索引

负责：

- 分配稳定资产 ID
- 维护总表和分类索引
- 维护父资产/子资产
- 维护变体、连续性和平台引用名
- 记录用户确认状态

### C04｜生产计划与就绪判断

负责：

- 优先级
- 前置依赖
- 生产批次
- 审批门
- 资产就绪、上传就绪和当前生成单元就绪

### C05｜版本与生成记录

记录：

- 使用模型
- Prompt 和版本
- 生成结果
- 通过、失败、随机偏差或返修
- 最终确认用途

### C06｜连续性与数据校验

检查：

- 人物脸、发型、服装、伤口和状态
- 道具持有人、左右手、数量和状态
- 场景视图、空间和光源
- 镜头间动作、视线和声音连续

## 11. 风格锁定包与大师 Skill/Profile

建议采用：

- 一个通用专业 Skill 负责工作方法。
- 每位大师作为独立 Profile 或资源文件。
- 风格锁定阶段临时加载，完成后卸载。
- 后续只读取该 Profile 产生的短执行卡。

示意结构：

```text
cinematography-director-skill/
├─ SKILL.md
├─ profiles/
│  ├─ emmanuel-lubezki.md
│  ├─ roger-deakins.md
│  └─ hoyte-van-hoytema.md
├─ references/
│  ├─ lighting-decision.md
│  ├─ optics-decision.md
│  └─ camera-movement.md
└─ templates/
   ├─ project-photography-bible.md
   └─ shot-photography-card.md
```

每次风格锁定建议：

- 一个主导演 Profile
- 一个主摄影指导 Profile
- 一个主美术/动画 Profile
- 必要时一个历史或文化顾问
- 必要时一个物理/VFX顾问

避免同时加载多个主摄影风格造成冲突。可以采用“一位主摄影＋一个局部补充特征”。

风格锁定包应输出：

1. 完整风格锁定包
2. 资产制作短执行卡
3. 场景与光影短执行卡
4. 分镜摄影短执行卡

后续不把完整大师资料复制进资产 Prompt。

## 12. 人物资产新流程

```text
选脸剧照
→ 用户确认
→ 登记脸部主资产
→ 制作脸部身份卡
→ 制作身体与服装基础卡
→ 用户确认
→ 登记人物基础版
→ 派生服装/妆造版本
→ 从对应服装版本派生伤口、血污、雨湿、持道具等状态
```

### 12.1 选脸剧照要求

- 脸部真实、可复现，不只追求漂亮。
- 五官、发际线和耳部清楚。
- 无强烈表情和五官遮挡。
- 自然皮肤纹理，不过度美颜。
- 深色眼睛中瞳孔和虹膜仍可分辨。
- 眼睛有微弱、自然、符合光源方向的眼神光。
- 避免环形美容灯形成夸张固定白点。

### 12.2 “正面全身去掉头部”的假设

用户的推论：

> 全身人物中的脸太小、太模糊，视频模型可能持续从该小脸提取身份。去掉正面全身头部后，模型只剩近景脸可以作为身份来源，可能让广角镜头中的人物脸轮廓更稳定。

当前判断：推论有合理性，但不能当作已证实底层规则。

支持理由：

- 参考图通常会整体缩放或编码成视觉特征，小脸可能损失身份高频细节。
- 更大的脸部近景通常提供更强身份信号。
- 去掉低质量小脸，可能减少多个脸部信号之间的冲突。

风险：

- 模型不是简单“选择唯一一张脸”，而是融合整张图的语义和视觉特征。
- 无头身体可能成为异常语义，产生颈部、头身连接和比例错误。
- 背面头部与正面身体可能缺乏统一的肩颈参考。
- 广角输出中的脸本身像素很少，高清参考不能突破最终画面的空间分辨率，只能改善轮廓和身份趋势。

当前推荐：不要马上写成硬规则，先做 A/B 测试。

测试组：

1. 全身正面带头＋脸部特写
2. 全身正面去头＋脸部特写
3. 脸部身份卡与身体卡分离

测试镜头：近景、中景、全景、侧脸转动。

评估：

- 人脸相似度
- 侧脸稳定度
- 头身连接
- 发型连续性
- 全景脸部轮廓
- 服装遵循度
- 异常率

### 12.3 推荐的双卡结构

#### A. 脸部身份卡

1. 正面近景
2. 3/4近景
3. 真侧面近景
4. 脸部明显不对称时补另一侧

#### B. 身体与服装基础卡

1. 正面全身，颈部以下或头部不作为身份来源
2. 背面全身带头，用于后脑、发型背面和整体比例
3. 3/4全身或侧面全身
4. 必要时增加手、鞋、腰带和关键佩戴物

侧面全身的使用条件：

- 普通现代服装：可选，3/4通常更有信息。
- 长袍、盔甲、背包、尾巴、披风、前后不对称：必需。
- 3D角色、怪物、生物：基本必需。

### 12.4 人物变体继承图

```text
脸部主资产
└─ 身体基础版
   ├─ 服装A
   │  ├─ 服装A雨湿
   │  ├─ 服装A战损
   │  └─ 服装A持道具
   └─ 服装B
      ├─ 服装B流血
      └─ 服装B烧伤
```

锁定层级：

1. 绝对不变：脸部骨相、五官关系、年龄和身份特征。
2. 当前造型锁定：发型、妆容和服装结构。
3. 允许变化：道具、污迹、伤口、雨湿和服装破损。
4. 局部覆盖：脸部伤口和流血可以增加，但不得重画底层脸。

## 13. 场景母图和多视图

“3/4 scale”在本讨论中理解为“三分之四斜角视图”，不是把画面缩放到四分之三。

### 13.1 默认空间母图

- 默认使用三分之四斜角广景。
- 同时看见至少两个相互垂直的空间平面。
- 有清楚纵深轴、入口、出口和人物活动区。
- 关键锚点不能被前景遮挡。
- 中等广度视角，不使用极端超广角。
- 较深景深，不把空间背景全部虚化。
- 空场景或只放尺度参照。
- 不追求封面式“漂亮剧照”。

例外：

- 对称大厅、神殿、法庭可用正面轴线。
- 走廊、桥梁和隧道可用纵向轴线。
- 山谷、城市和自然外景强调斜向纵深和地标关系。
- 用户明确要求漂亮剧照时，另做“场景英雄视图”，不覆盖空间母图。

### 13.2 光源逻辑

不建议写成“只能有一个光源”。正确规则：

- 一个主要方向性光源逻辑。
- 可以有多个有明确位置的实景辅助光源。
- 每个光源有位置、色温和影响范围。
- 不出现两个互相矛盾的太阳或主光方向。
- 新视图不能重新发明主光。
- 阴影和反射能追溯到光源地图。

### 13.3 场景空间圣经

母图确认后建立：

```text
局部坐标原点
正方向定义
母图摄影机位置、方向和高度
简化俯视平面图
门窗位置
柱、墙、楼梯和通道
沙发、床、桌椅和灯具
树、山、水体等室外锚点
人物站位区和通行路线
固定道具位置
主光源位置
辅助实景灯位置
阴影主要方向
不可改变锚点
允许补全的未知区域
```

### 13.4 其他视角 Prompt 的逻辑

```text
1. 明确唯一母图和空间圣经版本。
2. 定义新摄影机在世界空间中的位置。
3. 定义摄影机朝向、高度和视场范围。
4. 逐个说明固定锚点在新画面中的位置。
5. 说明遮挡、新出现和离开画面的物体。
6. 说明门、窗、灯、沙发、床、树、山的相对关系。
7. 保持材质、尺度、磨损、色彩和主光方向。
8. 只允许补全母图不可见区域。
9. 新视图确认后分配稳定场景视图 ID。
```

不能只写“生成这个房间的反向视图”，必须按新摄影机位置重新描述每个锚点的屏幕位置。

## 14. 每个资产新对话的最小加载内容

共享材料：

```text
制作类别锁定卡
对应资产类别的风格短执行卡
当前任务单和资产登记切片
当前父资产和正式参考图
直接相关的连续性切片
当前模型适配卡
```

分类补充：

- 人物：脸部主资产、基础身体卡、当前造型父版本。
- 场景：母图、空间圣经、视图 ID 和光源地图。
- 道具：尺寸、材质、持握和关联人物/场景。
- 生物：结构、比例、表皮、关节和运动逻辑。
- VFX：物理来源、运动、发光和环境接触。

如果任务单未确认模型，新对话必须先询问用户选择模型；一旦同一生产批次已确认，可记录在模型适配卡中，后续不重复询问，除非用户改变。

## 15. 分镜和正式 Prompt 的创作加载顺序

在创作前，控制 Skill 先检查：

- 剧本版本
- 人物和状态
- 服装和伤口版本
- 场景视图
- 道具
- VFX
- 声音
- 平台引用名

通过后依次加载：

```text
剧作与叙事
→ 导演与场面调度
→ 表演指导
→ 镜头设计与视觉戏剧
→ 摄影指导
→ 剪辑与节奏
→ 连续性/物理检查
→ Prompt装配
```

### 15.1 剧作与叙事

负责：戏剧目标、信息顺序、潜台词、母题、留白和原台词。剧本锁定后不得改写台词。

### 15.2 导演与场面调度

负责：观众视点、人物调度、权力变化、信息揭示、单镜头或镜头组。

### 15.3 表演

负责：目标、障碍、策略、节拍、潜台词、眼神、呼吸、重心、距离和状态惯性。

### 15.4 镜头设计与视觉戏剧

这是原 v1.0.1 最需要补充的模块。它必须输出：

```text
本镜叙事任务
观众视点
人物权力关系
景别对象
摄影机高度和角度
正面 / 侧面 / 背面 / 穿背 / 遮挡观察
镜头距离和透视
构图重心和负空间
前景遮挡
摄影机运动
运动触发点和结束点
剪辑落点
```

固定机位必须是叙事选择，不能成为默认值。

示例映射：

| 情绪/叙事 | 可考虑的选择 |
|---|---|
| 强势、压迫 | 低机位、近距离广角、人物侵占前景、向对手推进 |
| 脆弱、孤立 | 高机位、环境吞没人、长焦远距离观察 |
| 未知恐怖 | 主观视角、穿背、前景遮挡、视线外留白、摄影机迟于声音转向 |
| 身体性紧张 | 无稳定器手持近身跟拍、步伐冲击反馈 |
| 被监视 | 远距离长焦、前景遮挡、迟缓修正 |
| 关系靠近 | 横向跟拍或缓慢合拢人物距离 |
| 认知变化 | 有动机推进、焦点转移或构图重新平衡 |
| 被抛弃 | 摄影机后撤、人物变小、空间占据画面 |
| 无法逃脱 | 固定构图、门框和建筑线条形成视觉囚笼 |

### 15.5 摄影指导

在导演和场面调度完成后决定：

- 视场角或焦段
- 摄影机物理距离
- 高度和侧别
- 光线与曝光
- 景深和焦点
- 手持质量
- 运镜物理方式

通常加载通用摄影指导 Skill＋风格锁定阶段形成的摄影短执行卡。只有用户要求按特定大师重新解释一个场景时，才临时重新加载对应 Profile。

### 15.6 剪辑与节奏

负责：镜头数量、时长、动作接点、反应镜、声音桥和切点。

### 15.7 Prompt装配

只把已确认决定翻译为当前模型可执行语言，不能重新导演、重新摄影或改剧本。

## 16. 镜头诊断与重设计 Skill

用户觉得构图、景别或运镜不对时，不应只在 Prompt 末尾补一句“增加紧张感”。

P19 应先判断问题属于：

- 观众视点错误
- 情绪距离错误
- 摄影机高度错误
- 景别对象错误
- 镜头距离或透视错误
- 构图没有表现权力关系
- 运镜没有动机
- 固定机位被当作默认值
- 资产视图限制机位
- 镜头时长不支持动作
- Prompt翻译丢失设计

然后可输出 2–3 个明确不同的方案：

- 克制观察版
- 压迫强化版
- 主观恐惧版

用户选择后先更新分镜，再重写完整 Prompt。

## 17. 尚未解决、需要下次继续讨论的决定

1. 控制类 Skill 最终是 4 个、6 个，还是进一步合并。
2. 各 Skill 的正式中文名、英文名和目录结构。
3. 项目锁定卡、任务单、登记申请和资产总表的最终字段。
4. 人物脸部身份卡与身体卡的最终版式。
5. “全身正面去头”A/B测试的具体模型、样本数量和评价方式。
6. 场景空间圣经是否必须包含独立俯视图资产。
7. 室内、室外、自然景观、载具内部是否需要不同母图模板。
8. 真人、3D、2D媒介分别需要哪些大师 Profile 和专业 Skill。
9. 大师 Profile 的资料结构、证据来源和输出格式。
10. Prompt 使用中文、英文还是由模型适配卡决定。
11. 正式视频 Prompt 使用毫米焦段、视场角，还是同时使用物理距离和可见光学结果。
12. 风格锁定包四个版本的长度和字段。
13. 资产状态继承图如何在表格或 JSON 中表达。
14. 是否增加独立声音导演、动作导演、武术指导、怪物运动和动画表演 Skill。
15. 新系统的最小总控/路由 Skill 应负责什么，避免重新变成大而全规则。

## 18. 下次建议从这里继续

推荐顺序：

1. 先确定控制类与创作类 Skill 的最终清单和职责边界。
2. 设计四个最小交接对象：项目锁定卡、创作任务单、登记申请、资产调用表。
3. 单独讨论制作类别锁定卡及真人/3D/2D路由。
4. 确定真人角色资产包，并制定“去头全身图”A/B测试。
5. 确定场景空间圣经和多视图 Prompt 的结构。
6. 设计镜头视觉戏剧 Skill，这是改善基础构图和固定机位问题的重点。
7. 再设计导演、表演、摄影、剪辑和 Prompt 装配的实际交接卡。
8. 最后才开始创建正式 Skill 文件，不要先写大而全系统。
