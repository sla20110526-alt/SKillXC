# 真人写实 AI 影视生产总流程 v0.1

状态：首轮可执行结构；以各 Skill 内规则为准。系统只处理已有剧本或生产内容明确的项目，终点为正式 Seedance 2.0 镜头 Prompt 与生成可用镜头。

## 交互模式

- **轻量生产（默认）**：后台完整维护任务单、稳定 ID/版本、任务/成果索引和校验，当前对话只展示当前目标、必要缺口、创作结果、一个确认点与下一步。完整 Prompt 属于创作结果，可以完整展示；完整任务单、Schema、CSV 行、索引字段和检查日志不默认展开。
- **严格记录（按明确请求）**：项目绑定、正式资产登记、项目控制版本、进度/失败记录、正式审计、正式 QC 和项目复盘分别进入对应专用数据对话。生产对话只生成最小申请/同步包与短激活指令。
- 两种模式共享全部硬规则。轻量只减少展示，不减少项目绑定、版本、Profile确认、登记触发、连续性/就绪检查和状态分离。
- 跨对话或恢复使用短交接包：只携带任务 `ID@版本`、完整任务单路径、最小数据切片、唯一目标、禁止事项和返回条件；新对话再读取后台完整任务单。

## 资产生产循环

```text
控制类发任务单
→ 用户确认准备使用的通用 Skill 及可选 Profile
→ 创作类生产候选
→ 用户明确登记
→ 正式登记并进入可调用表
→ 就绪检查
→ 下一生产单元
```

## 正式镜头生产循环

```text
分镜组独立快照
→ 带ID和版本的正式Prompt
→ 用户人工检查Prompt
→ 外部人工生成
→ 用户确认镜头可用，或反馈返修
→ 生产对话继续下一组
→ 用户明确要求时才导出同步包并由独立记录对话写进度
```

镜头可用状态不进入正式资产登记表。只有后续要把视频或提取音频作为参考资产时，才另走资产登记流程。

## 主流程

1. `project-category-lock`：问答锁定真人写实、GPT Image 2、Seedance 2.0、画幅和参考用途。
2. `approval-asset-registry`：为具体项目确认项目 ID 和项目数据根目录；生产对话只收集并确认位置，严格记录对话建立项目数据绑定卡和必要空索引；没有具体项目时只提醒，不建虚构目录。
3. `script-truth-index`：建立不含创作建议的剧本事实索引。
4. `script-asset-breakdown`：识别候选资产与状态变化，并预留项目内稳定正式资产 ID；预留不等于登记。
5. `asset-demand-plan`：沿用预留正式资产 ID，建立独立需求槽位、依赖与生产批次；需求不是正式资产版本。
   - 从此处起任何阶段发现历史文化、职业法律、医学法医、建筑工艺、物理工程、军事武器、动物生态或危险VFX事实缺口，都按需询问是否加载 `specialist-consultant-router`。它先把专业点分为“必须准确／允许艺术化／纯虚构规则”，每个问题只路由一个主专业领域；再形成 `CQP` 问题包、`CED` 证据集和 `CCR` 结论卡。无可靠来源时保持“暂不可裁决”，不写成项目事实。
6. `style-lock-director`：依次执行“项目风格意图基线 → 四卡专业基线链 → P0风格测试与诊断 → 组合快照与批量放行”。导演只在项目风格意图阶段单独询问，美术与摄影分别在本部门基线阶段询问；责任 Skill 按“项目风格基线 → 美术 LookDev → 全片摄影 → 项目灯光”唯一写入长期基线，每张下游只引用前一张直接上游，顾问结论使用独立任务成果引用，摄影不引用尚未形成的最终风格包；`creative-control-versioning` 在专用对话中管理草案与原子生效。四卡均当前有效后，选择最少高风险正式资产槽位，并用绑定单个测试ID与预留ID的临时短切片走正常 GPT Image 2 生产验证；四卡生效和测试通过都不等于登记，也不单独放行批量生产。P0评审卡和最终风格包分别作为审查记录、组合快照进入任务成果索引；最终风格包只组合四张精确版本、当前评审和三个资产短执行切片，不反向改写上游，也不成为第五张长期基线。
   - 美术 LookDev 先从时代、地域、阶层、功能与剧本事实推导建筑陈设、服装妆造、道具、材料工艺、老化污迹、固有色和视觉母题，再把决定分为永久世界规则、资产类别规则、场次美术状态与镜头临时效果。完整美术 Profile 只在建立长期基线时询问并于基线形成后关闭；P0／批量前按目标资产类别派生美术执行交接包，由风格总控与摄影、灯光等规则组合，单独的美术包不能放行测试或批量生产。
   - 灯光阶段不读取大师Profile。项目长期基线承接全片摄影的相机侧曝光保护与动态范围目标；进入具体场景后，由 `lighting-direction` 唯一建立场景光源地图、人物受光、多视图灯光继承和镜头灯光短执行卡。场景空间只提供窗、灯具、反射面等空间锚点；VFX只定义自发光本体和时序；Prompt Skill只翻译当前灯光短卡。
7. 分类资产生产：人物进入 `character-asset-production`，场景进入 `location-spatial-production`，道具/载具/图案文字进入 `prop-vehicle-production`，特殊生物/怪物进入 `creature-monster-production`，VFX进入 `vfx-asset-production` 先做独立资产判定。产图任务由唯一责任资产 Skill 先确认设计卡，再搭配 `image-prompt-production` 选择新生成或参考编辑，交付带稳定 ID/版本的 GPT Image 2 完整 Prompt；结果必须返回原责任资产 Skill 验收。混合或类别不清的需求先经 `world-asset-production` 拆分生产顺序；它不产出候选。跨类别组合必须先分别生产并登记基础身份，再制作交互候选。有台词、独白或持续画外发声且需要跨镜连续的角色，由 `sound-voice-direction` 模式 A 建立声音身份卡，按项目需要进入模式 B 生产独立声音候选。无台词角色、环境/动作声和逐场声音表现不建立独立声音资产。
8. `approval-asset-registry`：只有“登记这张”“登记这段声音”“确认登记”等明确指令才把预留 ID 的正式版本写入绑定项目的登记表和可调用表；正式名称采用用户指定名称。
9. `continuity-readiness-audit`：分镜前只核对当前绑定项目的正式可调用资产；默认后台完成检查并只回显结论与阻断缺口，只有用户明确要求时才保存正式审计表。
10. 重要角色第一次进入场戏生产时，先由 `acting-direction` 模式 A 建立一角色一份的项目级表演母档，再由 `creative-control-versioning` 执行版本入表和用户确认生效。随后 `dramaturgy-scene-beats` 在唯一剧本内容版本、场次 ID、原文定位与锁定台词/事件顺序/因果齐全后，先建立 `BDT@版本` 逐节拍权威数据，再建立引用它的 `DSB@版本` 场戏节拍卡；两者分别进入任务成果索引，只把戏剧切片交 `directing-blocking` 与 `acting-direction` 模式 B。导演阶段重新询问是否加载导演 Profile，读取母档、节拍和当前空间圣经/锚点，先建立 `DBD@版本` 逐调度单元数据，再建立引用它的 `DBC@版本` 场戏调度卡；按节拍锁定观众知情关系、人物位置/距离/朝向/视线/遮挡/出入场、移动触发、权力空间变化、轴线与银幕方向。缺少必要空间依据时提出 SV3 缺口并返回资产计划和场景生产，不因现有参考图降低调度。表演指导再结合母档、节拍和 `DBD/DBC` 制作本场表演卡。后续场戏继承当前有效母档，只重做调度与场戏适配；简单角色可在任务单写明理由后跳过母档。
11. `cinematography-direction` 以“场戏摄影约束”模式继承全片摄影规则卡，把已定场戏、调度和表演翻译为本场摄影边界；不重复询问摄影 Profile，不决定逐镜方案。
12. `shot-visual-design` 形成逐镜草案 → `editing-rhythm` 建立 `ERT@版本 + ERC@版本`，逐镜提出顺序、时长、可定位切点、动作/声音接点、相邻状态与Seedance生成单元修订 → `shot-visual-design` 逐项记录采用/不采用理由，并作为分镜表唯一写入者建立新的分镜组快照。生成单元拆分/合并或成员变化建立新ID，旧ID标记被替代。
13. `cinematography-direction` 以“逐镜摄影审核”模式检查当前草案的摄影一致性与物理可执行性 → `shot-visual-design` 写回不改变叙事功能的摄影技术修正 → `sound-voice-direction` 模式 C 建立场戏声音卡；发声角色没有正式声音资产时，询问用户补做/上传独立候选，或明确选择本生成单元使用 Seedance 临时镜头内声音。
14. `continuity-readiness-audit` 做生成单元轻量就绪门，后台核对分镜版本、正式资产、当前有效表演母档和场戏表演卡引用，只回显结论与阻断缺口；通过后 `video-prompt-production` 先建立 `VRM@版本` 参考顺序/唯一用途映射，再按单镜头或镜头组模板建立 `VPR@版本`。每名人物只调用一张匹配当前服装/状态的五视图总览卡；正文按空间/摄影、第一帧、动作/表演、物理接触、台词/声音、光影和稳定结束装配。平台能力在本次使用时核对，用户放行后手工复制到外部Seedance生成；系统不提交、查询或下载。生产对话把Prompt放行和结果可用分开回显，不写项目进度表。
15. 用户明确要求同步本对话进度时，生产对话输出同步包，由独立 `generation-version-log` 对话写入绑定项目的镜头生产进度表；项目结束也可汇总各对话同步包。用户确认“镜头可用”即可，不要求上传视频。
16. 用户需要时调用 `video-qc-review` 独立诊断；默认只分析，明确要求后才登记 QC 记录。

## 硬规则

- 候选、失败、用户仅表示喜欢或准备继续修改的结果都不登记。
- 轻量生产只改变展示层；后台完整任务单、稳定ID/版本、索引和就绪检查不得省略。严格记录必须有用户明确授权和专用数据对话，生产对话不直接写权威记录。
- 每个项目使用独立项目数据根目录和绑定卡；生产对话只提交登记申请，登记对话只写绑定项目的表。
- 正式资产 ID 在资产拆解时预留，登记时沿用并增加版本；正式资产名称以用户明确指定的名称为准。
- 失败原因只在用户明确要求时由 `generation-version-log` 记录。
- 人物先分别预留并登记“脸母图”和“单张五视图基础卡”两个正式资产身份；五视图卡精确依赖脸母图，服装、状态和交互再逐层派生。Seedance人物参考只调用与当前服装/状态匹配的一张五视图总览卡：左1/3为正面特写和3/4侧面特写，右2/3为正面、侧面、背面全身，三个全身都保留完整头部。
- 人物资产画幅按排版需要，不跟随成片画幅。
- 场景默认使用能读取空间深度的3/4斜角母图；只有用户明确要求时才切换为剧照式母图，否则漂亮构图作为英雄视图而不覆盖母图。母图、场景状态、每张预制/专项/英雄视图和光影状态使用不同正式资产 ID，按精确父版本逐层依赖；空间圣经、锚点表和视图投影表由场景空间Skill形成任务成果，光源地图由灯光Skill形成任务数据集，它们都不作为图片资产登记。换摄影机只重新计算可见受光、屏幕阴影和反射；时间、天气、灯具开关、主光或VFX阶段改变时另建光影状态。
- 道具/载具基础对象、状态变体、图案文字母版、对象表面应用和对象装配使用不同正式资产 ID。图案文字先做正视清洁母版并逐字校对，再作为附加版本应用到指定对象锚点；对象交互接口不作为图片资产。载具外观由对象 Skill 负责，可拍摄舱内由场景空间 Skill 另建母图并把载具版本列为附加依赖。
- 生物/怪物基础形态、结构变体、生理状态和持物穿戴组合使用不同正式资产 ID。每个形态交付一张生命体总览卡，并以形态定义、解剖锚点和独立版本化运动约束集支持 Seedance；形态/运动数据不是图片资产。可停留且跨镜复用的转化阶段另建结构变体，单镜中间形变与能量/物质过渡交 VFX 和正式镜头 Prompt。
- `world-asset-production` 只做二级路由，不设计资产、不写 Prompt、不生成候选。人物、场景、道具/载具、生物/怪物、VFX 各有唯一责任生产 Skill；同一资产身份不得由多个 Skill 同时改写。
- 图片 Prompt 使用稳定 `图片PromptID@版本`，由任务成果索引追踪，不进入正式资产登记表。完整正文、参考用途/顺序、平台设置、上游生产卡或正式依赖改变时递增版本；相同输入原样再次生成不升级。`image-prompt-production` 只翻译已确认设计，候选业务验收和登记申请仍由唯一责任资产 Skill 负责。
- VFX 只有需要跨镜保持同一视觉身份、叙事上必须被认出、独立审批或复杂接触反复调用时才建立图片资产。正式角色分为 `VFX视觉母版 → VFX状态变体 / VFX接触参考`：状态变体只依赖一个母版或上一状态，接触参考依赖一个母版/状态并附加已登记接触环境。一次性普通尘土、火花、飞溅等不登记图片资产，先由 VFX Skill 给出单镜执行条款，再进入分镜与正式 Prompt。VFX定义、时序表、接触表、阶段审查板和单镜条款都是任务数据，不进入正式资产表，也不能互相替代。
- 专业顾问问题包、证据集与结论卡分别使用稳定 ID/版本并进入任务成果索引。美术、资产、调度和镜头只采用当前可交接结论卡的 `CCR@版本 + 主张ID／采用字段 + 结论状态 + 适用条件`；问题包和“暂不可裁决”只能作为缺口。顾问结论在长期风格卡中使用独立“顾问任务成果引用集合”，不能成为四卡直接上游。现实危险问题不得扩写成步骤、配比剂量、关键参数、采购改装、规避侦测、增伤或解除安全装置指南。
- 大师 Profile 独立存放；只在阶段合同允许的责任 Skill 中询问用户后调取。导演在项目风格意图和场戏调度分别确认；本体到失效点后关闭，下游只接收已转译的项目规则切片，不接收完整 Profile 或短卡本体。
- 风格批量放行必须同时满足四张长期基线当前有效且唯一直接上游依赖闭合、必做P0测试通过、没有未决专业冲突或顾问硬事实缺口。任一来源卡被替代或失效后，用任务成果影响分析在一次事务中将受影响的当前评审与旧风格包快照标记待复核；旧成果不得用于新任务。
- 中央源定义版本、Profile 卡片版本和项目控制卡版本独立递增。只有维护中央原始内容才升级中央源/Profile；中央 Profile 新版不自动替换项目固定引用。项目首次采用从 `v001` 建卡，内容或精确引用实质变化才建下一项目版本；状态变化不另建版本。
- 项目长期风格、美术、摄影、灯光基线及表演母档、声音身份只有 `已生效 + 当前有效=是` 的精确版本可下传。专业 Skill 写内容，`creative-control-versioning` 唯一写版本和状态；停用新版不自动恢复旧版。
- 摄影 Profile 的常规询问点只有风格锁定中的“全片摄影基线”；场戏约束、镜头设计、逐镜摄影审核与 Prompt 生产只继承规则卡。只有用户明确要求摄影重释，或全片规则不能完成已成立的场戏风格断裂时，才经用户确认建立限时场戏例外。
- `shot-visual-design` 是分镜表唯一写入者。摄影指导只建立规则与审核摄影实现，不重新决定镜头叙事功能，也不直接改分镜表。
- `acting-direction` 是表演母档和场戏表演卡的唯一写入者。母档按项目和角色建立并独立版本化，不按每场重建；场戏临时目标、伤势、道具动作和调度不固化进母档。母档属于创作控制数据，不进入人物或声音资产登记。
- `dramaturgy-scene-beats` 是逐节拍数据与场戏节拍卡的唯一写入者。锁定台词、事件顺序、因果和出入场未经授权不得改写；即使用户授权，也先建立新的剧本内容版本。节拍成果只交导演调度与场戏表演适配，不决定景别、构图、机位、焦段或运镜。
- `directing-blocking` 是逐调度单元数据与场戏调度卡的唯一写入者。它先决定观众与信息、人物和空间的关系，移动必须有触发、目的、路径与结束，保持位置也必须有行动目的；故意越轴必须写叙事理由和重建空间方法。它不建立表演母档、不决定具体焦段、不写分镜表；用户认为走位/关系错误时回到该 Skill 建下一版本，而构图、景别、逐镜机位和运镜问题交 `shot-visual-design`。
- `sound-voice-direction` 是声音身份卡和场戏声音卡的唯一写入者。身份卡属于创作控制数据；只有独立音频文件在明确“登记这段声音”等指令后才成为声音资产。Seedance 临时镜头内声音、环境声、动作声和逐场对白表现默认不登记。
- 发声角色没有正式声音资产时，用户必须明确选择补做/上传声音候选，或本生成单元使用 Seedance 临时声音；系统不得自行选择。可用镜头中的声音只有被单独形成音频文件、已有或补充预留声音资产 ID，并再次明确登记后，才能进入可调用表；不得由声音或登记 Skill 临时补号。
- 分镜组、单镜头、生成单元、视频参考映射和正式 Prompt 使用稳定身份与独立版本。组内变化形成新分镜组快照；只递增实际改变镜头的镜头版本；参考来源/顺序/用途变化递增VRM版本；每次完整Prompt重写递增VPR版本；生成单元成员或内部顺序变化时建立新的VRM和VPR身份。
- “Prompt 已放行生成”和“生成结果可用”是两个状态。“继续”“不错”“可以”不自动改变正式状态；含糊的“上一组通过”必须按上下文确认对象。
- 外部人工生成是当前正式节点；本系统暂不提交 Seedance 任务、查询进度或下载视频。
- 项目数据默认：Markdown 卡片供人确认，CSV 保存多行权威记录，JSON Schema 检查表头和逐行结构；所有项目 CSV 行携带项目 ID，检查报告写入绑定项目目录。用户指定特定格式时记录例外并服从用户。
- 结构检查通过不等于用户批准、正式登记、业务引用或创作质量通过；对应责任 Skill 仍须完成业务复核。
- 分镜每镜必须解释“为什么需要本镜”与“为什么选择本机位和运镜”。
