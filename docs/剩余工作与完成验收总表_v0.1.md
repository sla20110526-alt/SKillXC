# 剩余工作与完成验收总表 v0.1

## 1. 文档定位

本表是 SKillXC 真人写实第一版后续建设的唯一范围、顺序与完成验收清单。它只用于仓库维护，不参与具体影视项目的创作推理，也不替代各 Skill 正文、项目任务单或项目数据。

基线范围固定为：已有剧本或生产内容明确的真人写实项目；GPT Image 2 制作图片资产；Seedance 2.0 由用户在外部平台人工生成；终点为正式镜头 Prompt 和用户确认的可用镜头。

本表根据 2026-08-13 对 30 个 Skill、安装恢复拓扑、Profile 资料库、数据契约与测试覆盖的只读总审计建立。建立本表本身记为 `M00`，不占用下列 14 个剩余工作包。

## 2. 状态与变更规则

允许状态只有：

- `待实施`：尚未进入本项修复。
- `实施中`：用户已明确确认当前项，且只处理本项范围。
- `待用户验收`：文件、检查和证据已完成，等待用户确认。
- `已完成`：用户确认验收通过，且完成证据已经写回本表。
- `受阻`：缺少本项不可替代的用户资料或外部条件；必须写明阻断条件。
- `延期`：用户明确决定不纳入当前真人写实闭环。

执行规则：

1. 一次只实施一个工作包。未收到用户明确确认，不自动进入下一项。
2. 每项只修改其“允许修改范围”内的内容；发现新问题先登记候选，不顺手扩大实施范围。
3. 每项完成后逐文件检查 UTF-8、YAML/JSON/CSV、内部链接、调用边界、版本规则和相关回归测试，然后停下等待用户验收。
4. `结构检查通过`、`测试通过`和`创作质量通过`是三种不同结论，不得互相替代。
5. 新增、删除、合并、拆分或重排工作包，必须先说明原因和对总数/依赖的影响，经用户确认后升级本表版本；不能继续用无总数的“进入下一项”扩展范围。
6. 单纯更新某项状态、完成日期和证据链接不升级本表范围版本；范围、顺序或验收标准改变时才建立新版本。

## 5. 系统修复包验收卡

### S01｜任务成果索引与数据契约闭环

**问题**

现有 `任务索引.csv` 只登记任务单，没有足够字段追踪场戏节拍卡、调度卡、表演卡、摄影约束、摄影审核、图片/视频 Prompt、风格包及各类非图片任务数据的稳定 ID、版本、路径、依赖与当前状态。

**实施范围**

- 保留任务索引的“任务调度”职责，建立或等效实现独立的任务成果索引。
- 定义成果类型、成果 ID、版本、上版、当前有效、状态、文件路径、上游精确引用、责任 Skill、内容指纹和日期。
- 接入 Markdown＋CSV＋JSON Schema 三层契约、数据清单、路由交接和连续性审计。
- 修正所有“由任务索引追踪”的不实或含混表述。

**完成验收**

- 任务单与任务成果可以一对多关联，且不会把成果误当任务单。
- 同一项目、成果 ID 不能存在两个当前有效版本。
- 上游版本变化可以列出受影响成果，但不会自动伪造创作结论。
- 正常、重复当前版本、非法版本、跨项目引用和缺失文件均有自动测试。
- 数据契约清单、模板、Schema、验证报告和 README/流程引用一致。

**允许修改范围**

`production-router-handoff`、`creative-control-versioning`、`continuity-readiness-audit`、所有声明由任务索引追踪的 Skill，以及必要的项目数据契约和测试。

**执行能力**：可由 Codex 直接完成，不需要用户补资料。

### S02｜风格锁定四卡依赖与交接消除冲突

**问题**

美术基线把顾问结论混入长期控制卡依赖集合；全片摄影模板引用尚未形成的最终风格包；Profile、P0 测试和组合快照的阶段表达尚未完全一致。

**实施范围**

- 固定唯一有向链：项目风格锁定基线 → 美术 LookDev 基线 → 全片摄影规则 → 项目灯光基线。
- 顾问任务/结论使用独立字段或任务成果引用，不冒充长期基线。
- 删除全片摄影规则对最终风格包的循环引用。
- P0 测试、四卡生效和最终组合快照使用任务成果索引追踪；组合快照不得成为第五张长期基线。
- 同步风格路由、任务单、四张模板、版本事务、README 和流程文档。

**完成验收**

- 四卡只允许前向引用，无法建立循环或引用未生效上游。
- P0 通过不等于资产登记，四卡生效不等于批量放行。
- 任一卡替代后，旧组合快照不能用于新任务。
- 模板、Schema、事务检查和文字规则对同一依赖给出同一答案。

**执行能力**：可由 Codex 直接完成。

### S03｜Profile 阶段、来源与成熟度边界修复

**问题**

导演 Profile 的已声明阶段与项目风格意图阶段不一致；现有来源仍把聊天和 Git 历史作为定位；27 张卡片虽结构通过，但全部只是“初版、受限可选”。

**实施范围**

- 为各部门 Profile 明确允许阶段、作用域、失效点和可跨阶段继承的只有哪些“项目规则切片”。
- 统一风格锁定、导演调度、摄影、LookDev、剧作与剪辑阶段的询问规则。
- 使当前资料来源成为仓库内可保存、可定位、不会要求生产对话搜索聊天或 Git 历史的证据快照。
- 保持未核验方法为分析性归纳，不把结构检查伪装成事实核验。
- 明确中央 Profile 版本与项目采用版本相互独立。

**完成验收**

- 每张可选 Profile 的适用阶段与调用它的 Skill 一致。
- 新对话不需要访问聊天记录或 Git 历史即可理解证据边界。
- 校验器继续检查 27 张卡、目录、版本和来源引用。
- 没有具体来源支持的方法仍保持 `初版 / 受限可选`。

**执行能力**：阶段和来源契约可由 Codex 直接完成；任何 Profile 升级为 `已核验`，必须另有具体访谈、讲座、制作资料、作品时间点或用户认可的来源，逐张处理，不计入本 14 项闭环总数。

### S04｜Windows UTF-8、重装恢复与运行时发现验收

**问题**

部分测试依赖隐藏的 `PYTHONUTF8=1` 条件；恢复工具证明文件和链接存在，但还没有证明重装后 30 个 Skill 能在 Codex 新对话中正确发现和按规则触发。

**实施范围**

- 消除 Python 测试与验证脚本对 Windows 默认中文编码的隐式依赖。
- 明确开发态采用直接 Skill 链接；插件可在市场中存在，但不得与同名直接链接同时安装。
- 恢复验证同时检查中央源、30 个链接、插件市场状态、重复发现风险和关键命令可运行性。
- 建立重启后运行时发现验收清单，不靠磁盘存在推断 Codex 已加载。

**完成验收**

- 不设置临时 UTF-8 环境变量也能运行全部自动测试。
- 恢复脚本不会制造第二份中央源或同时启用两套同名 Skill。
- Codex 重启后的新对话能发现总路由；其余专业 Skill 只能在确认后显式调用。
- 30 个 SKillXC Skill 的实际发现结果与清单一致，没有缺失或重复。

**执行能力**：脚本和配置可由 Codex 完成；最后一步需要用户允许重启 Codex，并在新对话执行一次发现验收。

### S05｜轻量生产模式与严格记录模式

**问题**

现有系统把任务单、ID、版本、专用对话和检查点定义得较完整，但如果全部暴露给生产对话，会造成注意力负担并重新变得复杂。

**实施范围**

- 默认建立“轻量生产模式”：只向用户展示当前创作决策、必要缺口、候选结果和明确确认点；后台交接包保持完整，但不在对话里展开全部管理字段。
- 建立“严格记录模式”：只在用户要求同步、登记、审计或复盘时进入专用数据对话。
- 明确两种模式共享相同硬规则；轻量不等于跳过项目绑定、正式资产版本、登记触发或连续性检查。
- 路由交付短激活指令和最小数据切片，禁止一次加载全部 Skill/Profile。

**完成验收**

- 一般生产对话不直接编辑登记表、进度表和失败记录。
- 用户不需要阅读完整 Schema、索引和任务卡才能作出创作决定。
- 需要恢复、交接或同步时，能由短交接包找到完整版本依据。
- 用一个模拟生产回合验证对话只出现必要问题和决定点，并由用户确认交互足够简单。

**执行能力**：结构可由 Codex 完成；最终易用性必须由用户验收。

## 6. 创作 Skill 成熟化验收卡

每个 `C` 类工作包除本项专门条件外，还必须共同满足：

1. `SKILL.md` 明确进入条件、唯一职责、输入切片、决策顺序、交付物、版本触发、返工路由和禁止事项。
2. 至少有一份可实际填写的交付模板；需要多行权威记录时同时具备 CSV 与 JSON Schema。
3. 输出拥有稳定 ID/版本并进入 S01 的任务成果索引；不得只在文字中声称“可追踪”。
4. Profile 只在用户确认后、规定阶段和范围内读取；通用方法不伪装成某大师原话或意图。
5. 具备最小正例、缺失输入、越权写入和版本变化检查；自动检查只能证明结构/业务约束，不能宣称创作质量。

### C01｜美术与 LookDev 指导成熟化

**完成验收**

- 能从时代、地域、阶层、功能与剧本事实形成世界设计，而不是只输出“高级、电影感”。
- 分开永久世界规则、资产类别规则、场次状态和镜头临时效果。
- 明确建筑/陈设、服装/妆造、道具、材质工艺、老化污迹、色彩角色与视觉母题的交接。
- 形成长期 LookDev 基线模板、GPT Image 2 短执行切片和专业顾问缺口。
- 与项目风格基线、摄影和灯光的依赖方向符合 S02。

**执行能力**：可由 Codex 直接完成通用 Skill；具体项目参考在 V01 再提供。

### C02｜灯光指导成熟化

**完成验收**

- 区分主方向光、实景光、环境填充、反射、负补光和 VFX 自发光，不误写成“只能有一个光源”。
- 具备项目灯光基线、场景光源地图、人物受光、多视图继承和镜头短执行模板。
- 新视角能按空间锚点重新计算可见受光，同时保持光源、阴影、时间与天气逻辑。
- 明确曝光保护、暗部可读性、允许剪影/过曝范围及与摄影/VFX 的职责边界。

**执行能力**：可由 Codex 直接完成。

### C03｜专业顾问路由成熟化

**完成验收**

- 把专业点分为必须准确、允许艺术化、纯虚构规则，并只路由最小必要专业领域。
- 具备顾问问题包与顾问结论卡，记录稳定 ID/版本、剧本出处、当前假设、来源、证据强度、不确定性、决策截止点和返回节点。
- 无可靠资料时不擅自裁决为项目事实；现实危险内容不扩写成可执行伤害指南。
- 顾问结论可被美术、资产、调度或镜头精确引用，但不混入长期控制卡依赖集合。

**执行能力**：可由 Codex 直接完成通用路由；项目专业事实可能需要用户资料或另行检索可靠来源。

### C04｜剧作与场戏节拍成熟化

**完成验收**

- 具备场戏节拍卡，保存场次 ID、稳定卡 ID/版本、剧本内容版本和原文定位。
- 每个节拍能说明触发、人物目标、障碍、策略、可见行为、潜台词、信息变化、权力变化和进出状态。
- 保持锁定台词、事件顺序和因果；未授权时不改剧本。
- 只向导演调度和表演交付戏剧依据，不提前决定机位、焦段或运镜。

**执行能力**：可由 Codex 直接完成通用 Skill；真实质量在 V01 用用户剧本验证。

### C05｜导演与人物调度成熟化

**完成验收**

- 具备场戏调度卡和稳定版本，读取节拍、表演母档、场景空间圣经与必要 VFX/生物约束。
- 按节拍明确观众视点、人物坐标、距离、朝向、视线、遮挡、进入/离开、移动触发和权力变化。
- 明确轴线、银幕方向、故意越轴理由以及重新建立空间的方法。
- 能提出专项场景视图缺口，不因现有资产视角迫使调度平庸。
- 不越权决定具体焦段，不建立表演母档，不直接写分镜表。

**执行能力**：可由 Codex 直接完成；真实调度质量在 V01 验证。

### C06｜剪辑与节奏成熟化

**完成验收**

- 具备剪辑节奏卡，记录镜头顺序、时长、切点、生成单元、动作/声音接点和相邻状态。
- 每个切点说明情绪、信息或动作理由，不按平均时长机械切分，不自动把对白做成正反打。
- Seedance 生成单元的拆分/合并遵守稳定 ID 与替代规则。
- 只提出节奏修订，由 `shot-visual-design` 唯一写回分镜；摄影审核在写回后执行。

**执行能力**：可由 Codex 直接完成；真实镜头节奏在 V01 验证。

### C07｜Seedance 2.0 视频 Prompt 成熟化

**完成验收**

- 单镜头和镜头组模板都能精确引用分镜、正式资产、表演、灯光、声音、VFX 与连续性版本。
- 明确参考素材顺序和唯一用途；人物只调用一张与当前服装/状态匹配的五视图总览卡。
- Prompt 按空间与摄影、第一帧、动作/表演、物理接触、台词/声音、光影、稳定结束状态的优先级装配，并删除管理语言与互相冲突的质量口号。
- Prompt 表达修订与镜头设计变更使用不同版本规则；拆分/合并生成单元时建立新身份。
- 保持外部人工生成节点，不擅自提交、查询或下载任务；平台临时限制在使用时核对，不写成永久规则。
- 至少用一个真实生成单元完成“人工检查 → 外部生成 → 用户反馈 → 最小返修或可用确认”。
