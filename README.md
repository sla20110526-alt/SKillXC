- 8 个生产控制 Skill：类别锁定、事实索引、资产需求、路由交接、审批登记、创作控制版本、生成版本记录、连续性与就绪。

## 当前硬规则

- 只有用户明确说“登记这张”“登记这段声音”“确认登记”等，结果才进入正式资产登记表和可调用资产表。
- 每个具体项目必须先确认项目数据根目录和绑定卡；项目数据不写入本中央 Skill 仓库。
- 项目 CSV 每行必须携带项目 ID；交接前运行 Schema 检查。结构通过不等于创作批准、资产登记或业务引用有效。
- 正式资产 ID 在资产拆解时预留；登记时沿用该 ID、增加版本，并采用用户指定的资产名称。
- 失败结果不登记；失败原因只在用户明确要求时记录。
- 人物脸母图与五视图基础卡使用不同正式资产 ID；Seedance 2.0 实际调用与当前服装/状态匹配的一张五视图总览卡，不上传五张独立人物图。
- 场景默认使用3/4斜角空间母图；剧照式母图必须由用户明确指定。母图、场景状态、各视图和光影状态使用不同正式资产 ID 与精确依赖，空间圣经和锚点/投影表不作为图片资产登记。
- 道具/载具先锁定对象本体与交互锚点；状态、图案文字母版、表面应用和对象装配使用不同正式资产 ID 与精确依赖。文字必须先做可逐字校对母版，载具舱内作为场景空间另行生产并依赖载具外观版本。
- 生物/怪物先锁定单一形态、解剖锚点和独立版本化运动约束集；基础形态、结构变体、生理状态和持物穿戴组合使用不同正式资产 ID，单镜转化过渡交 VFX 与正式镜头 Prompt。
- VFX 先判断是否需要独立图片资产。跨镜复现时使用 `视觉母版 → 状态变体 / 接触参考` 的精确依赖链，并把 VFX 定义、时序和接触数据绑定到登记回执；一次性普通效果不伪造资产，只向分镜与 Prompt 交付单镜执行条款。
- 图片 Prompt 只翻译唯一责任资产 Skill 已确认的设计，使用稳定 `图片PromptID@版本` 并由任务成果索引追踪；相同输入原样再生成不升级，正文、参考映射、平台设置或上游版本变化时完整重写并递增。候选仍返回责任资产 Skill 验收，只有用户明确指令才提交登记。
- 风格锁定分为项目风格意图、四卡专业基线链、P0正式资产测试、组合快照与批量放行四种独立任务。四卡只按“风格→美术→摄影→灯光”引用唯一直接上游，顾问成果独立引用，摄影不引用尚未形成的最终风格包；P0通过不等于登记，四卡未闭合或测试未通过时不放行批量生产，评审卡和组合快照进入任务成果索引，组合快照不是第五张长期基线。
- 美术与 LookDev 从时代、地域、阶层、功能和剧本事实建立世界物质逻辑，分开永久世界规则、资产类别规则、场次美术状态与镜头临时效果；部门执行包只提供形制、材料、工艺、维护、固有色和母题切片，不能单独代替 P0 评审或风格包放行。
- 灯光不等于“只能有一个光源”：项目长期基线承接摄影的相机侧曝光边界，具体场景由灯光Skill唯一写入光源地图、人物受光、多视图继承与镜头灯光短卡。场景空间只提供光源/控光锚点，VFX只定义自发光本体与时序，Prompt只翻译当前可交接灯光成果。
- 专业事实先分为“必须准确／允许艺术化／纯虚构规则”，每个顾问问题只路由一个主专业领域。问题包、逐主张证据集和结论卡独立版本化并进入任务成果索引；无可靠资料时保持“暂不可裁决”，下游只按 `CCR@版本 + 主张ID／采用字段 + 结论状态` 精确引用。危险现实内容只保留非操作性现象、后果与安全边界，不扩写成可执行伤害指南。
- 场戏剧作只解释锁定剧本：先建立带原文定位的 `BDT@版本` 逐节拍权威数据，再建立引用它的 `DSB@版本` 场戏节拍卡。每拍必须有触发、目标、障碍、策略、可见行为、潜台词、信息／权力变化与进出状态；未经授权不改台词、事件顺序或因果，且只向导演调度和场戏表演适配下传戏剧切片。
- 导演调度先建立 `DBD@版本` 逐人物调度数据，再建立引用它的 `DBC@版本` 场戏调度卡；把观众知情关系、人物坐标/分区、距离、朝向、视线、遮挡、出入场、移动触发、权力空间变化、轴线与银幕方向落到当前空间圣经。缺少必要视角时提出 SV3 专项场景视图缺口，不让现有参考图迫使调度平庸；具体焦段、逐镜机位和分镜表仍由镜头视觉设计负责。
- 剪辑先建立 `ERT@版本` 逐镜关系数据，再建立引用它的 `ERC@版本` 节奏卡；每个切点都有可定位时机和情绪/信息/动作/声音理由，动作/声音接点、相邻状态与生成单元替代均可追溯。不按平均时长机械切分、不自动把对白变成正反打；剪辑只提案，镜头视觉设计唯一写回，随后才做逐镜摄影审核。
- Seedance正式Prompt先建立 `VRM@版本` 参考顺序与唯一用途映射，再建立引用它的 `VPR@版本`；单镜和镜头组分别装配，正文按空间/摄影、第一帧、动作/表演、接触、声音、光影与稳定结束执行。每名人物只调用一张匹配状态的五视图卡；平台能力本次核对，当前节点只供用户手工复制，不提交、查询或下载。
- 视频QC分即时诊断、项目复盘和正式记录三种模式；先说明视频/截图/文字反馈能核验什么，再按时间点记录可观察差异，区分上游设计、Prompt漏译、参考映射/负载和模型随机偏差，每条只返回一个责任节点。即时分析和复盘默认不落盘，用户明确要求后才保存QCR正式记录；AI不替用户判镜头可用。
- 通用创作 Skill 使用前先请用户确认；大师 Profile 只在阶段合同允许的责任 Skill 中询问。导演在项目风格意图和场戏调度分别确认；所有 Profile 到本体失效点即关闭，下游只拿已转译的项目规则切片。
- 中央源定义/Profile版本与项目创作控制卡版本分开；调用原始资料不升级源版本，中央 Profile 新版也不自动替换项目固定引用，项目内容或精确引用实质变化才建立下一项目版本。
- 摄影 Profile 只在建立/重建全片摄影基线时常规询问一次；场戏、逐镜与 Prompt 阶段继承摄影规则卡，只有用户确认的限时场戏例外可以重新调取。
- 镜头视觉设计是分镜表唯一写入者；摄影指导先建立规则、后审核摄影实现，不直接改写分镜或重定镜头叙事功能。
- 表演指导是角色表演母档和场戏表演卡的唯一写入者；重要角色在剧作/导演场戏工作前建立一项目一份当前有效母档，场戏只做适配，简单路人可写明理由后跳过。
- 声音指导把声音身份卡、独立参考音频和场戏声音卡分开；只有发声角色按需建立独立声音资产，Seedance临时镜头内声音须由用户选择且不会自动登记。
- 分镜组、单镜头和正式 Prompt 分别使用稳定 ID 与独立版本；Prompt 放行不等于生成结果可用。
- 轻量生产模式只简化对用户的展示，不跳过项目绑定、正式版本、登记触发、Profile确认、连续性/就绪门或状态分离；需要跨对话时用短交接包定位后台完整任务单。
- 生产对话不维护登记表、控制索引、进度表、失败记录、正式审计表或 QC 表；用户明确授权后，由相应严格记录对话写入。镜头进度同步可依据用户“镜头可用”结论，不要求上传视频。
