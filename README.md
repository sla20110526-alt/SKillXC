# SKillXC

本仓库用于设计和实现“抽屉式 AI 影视生产 Skill 系统”。当前第一版只覆盖已有剧本或生产内容明确的真人写实项目，使用 GPT Image 2 制作图片资产、Seedance 2.0 生成视频，终点为正式镜头 Prompt 与生成可用镜头。

## Skill 结构

- 8 个生产控制 Skill：类别锁定、事实索引、资产需求、路由交接、审批登记、创作控制版本、生成版本记录、连续性与就绪。
- 1 个世界资产二级路由：只拆分混合资产需求，不生产候选。
- 19 个创作生产 Skill：风格、分类资产、剧作、导演、表演、摄影、灯光、镜头、剪辑、声音与 Prompt 装配。
- 1 个独立影视大师 Profile 资料库。
- 1 个按需视频 QC Skill。

全部 Skill 位于 [`skills/`](skills/)。项目数据默认采用 Markdown 卡片、CSV 表格与 JSON Schema 检查：卡片供人确认，CSV 保存多行权威记录，Schema 检查表头与逐行结构；检查报告写入具体项目数据目录。单次创作短卡由任务索引承担结构化追踪，不复制冗余表格。完整规则见 [`项目数据三层契约`](skills/production-router-handoff/references/project-data-contract.md)。

## Codex 接入

- [插件清单](.codex-plugin/plugin.json) 将本仓库作为一套可持续更新的 `skillxc` 插件提供。
- [仓库级规则](AGENTS.md) 约束中央源、调用确认、维护边界和安装拓扑。
- 用户级 `.agents` 持久化根目录位于 D 盘，C 盘用户目录只保留标准发现入口；[重装恢复说明](docs/Codex用户级Skill重装恢复.md)与[恢复工具](deployment/windows/)随仓库备份。
- 本仓库、插件和 Skill 不保存历史讨论正文；新任务只按[现行规则源清单](active-rule-sources.json)规定的策略加载内容，列入清单不等于一次读取全部 Skill。只有用户在当前指令中明确提供归档路径并要求读取或比较时，才可访问该指定历史归档。
- 本地开发态通过持久化目录中的链接直接读取 `skills/`，不复制 Skill；中央源更新后各项目读取到同一版本。
- `production-router-handoff` 是唯一可自动识别的总路由入口；其余 29 个 Skill 必须在用户确认后显式调用。
- 个人插件市场入口与直接链接是两种接入方式，不同时启用，避免同名 Skill 重复发现。

## 当前硬规则

- 只有用户明确说“登记这张”“登记这段声音”“确认登记”等，结果才进入正式资产登记表和可调用资产表。
- 每个具体项目必须先确认项目数据根目录和绑定卡；项目数据不写入本中央 Skill 仓库。
- 项目 CSV 每行必须携带项目 ID；交接前运行 Schema 检查。结构通过不等于创作批准、资产登记或业务引用有效。
- 正式资产 ID 在资产拆解时预留；登记时沿用该 ID、增加版本，并采用用户指定的资产名称。
- 失败结果不登记；失败原因只在用户明确要求时记录。
- 人物脸母图与五视图基础卡使用不同正式资产 ID；Seedance 2.0 实际调用与当前服装/状态匹配的一张五视图总览卡，不上传五张独立人物图。
- 场景默认使用3/4斜角空间母图；剧照式母图必须由用户明确指定。母图、场景状态、各视图和光影状态使用不同正式资产 ID 与精确依赖，空间圣经和锚点/投影表不作为图片资产登记。
- 道具/载具先锁定对象本体与交互锚点；状态、图案文字母版、表面应用和对象装配使用不同正式资产 ID 与精确依赖。文字必须先做可逐字校对母版，载具舱内作为场景空间另行生产并依赖载具外观版本。
- 生物/怪物先锁定单一形态、解剖锚点和独立版本化运动约束集；基础形态、结构变体、生理状态和持物穿戴组合使用不同正式资产 ID，单镜转化过渡交 VFX 与正式镜头 Prompt。
- VFX 先判断是否需要独立图片资产。跨镜复现时使用 `视觉母版 → 状态变体 / 接触参考` 的精确依赖链，并把 VFX 定义、时序和接触数据绑定到登记回执；一次性普通效果不伪造资产，只向分镜与 Prompt 交付单镜执行条款。
- 图片 Prompt 只翻译唯一责任资产 Skill 已确认的设计，使用稳定 `图片PromptID@版本` 并由任务索引追踪；相同输入原样再生成不升级，正文、参考映射、平台设置或上游版本变化时完整重写并递增。候选仍返回责任资产 Skill 验收，只有用户明确指令才提交登记。
- 风格锁定分为项目风格意图、四卡专业基线链、P0正式资产测试、组合快照与批量放行四种独立任务；P0通过不等于登记，四卡未闭合或测试未通过时不放行批量生产，组合快照不是第五张长期基线。
- 通用创作 Skill 使用前先请用户确认；大师 Profile 到对应阶段再询问是否调取。
- 中央源定义/Profile版本与项目创作控制卡版本分开；调用原始资料不升级源版本，项目内容实质变化才建立下一项目版本。
- 摄影 Profile 只在建立/重建全片摄影基线时常规询问一次；场戏、逐镜与 Prompt 阶段继承摄影规则卡，只有用户确认的限时场戏例外可以重新调取。
- 镜头视觉设计是分镜表唯一写入者；摄影指导先建立规则、后审核摄影实现，不直接改写分镜或重定镜头叙事功能。
- 表演指导是角色表演母档和场戏表演卡的唯一写入者；重要角色在剧作/导演场戏工作前建立一项目一份当前有效母档，场戏只做适配，简单路人可写明理由后跳过。
- 声音指导把声音身份卡、独立参考音频和场戏声音卡分开；只有发声角色按需建立独立声音资产，Seedance临时镜头内声音须由用户选择且不会自动登记。
- 分镜组、单镜头和正式 Prompt 分别使用稳定 ID 与独立版本；Prompt 放行不等于生成结果可用。
- 生产对话只回显轻量检查点，不维护项目进度表；用户明确要求同步时，独立记录对话可依据其“镜头可用”结论写进度，不要求上传视频。
